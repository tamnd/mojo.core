# Changelog

Notable changes, newest first. This project follows semantic versioning from 1.0. Before then, anything can move.

## Unreleased

DEFLATE, the reading half. `core.compress.flate` is new and is nine of Go's thirty one symbols, which is the whole of the half that reads. `new_reader` and `new_reader_dict` hand back a `Decompressor`, which is a `core.io.Reader` and a `core.io.Closer`, `CorruptInputError` says how far a stream got before it stopped making sense, `InternalError` is Go's name for the one state the decompressor has no branch for, and `Reader` is Go's interface for what a decompressor reads out of. Twelve more are the writer and its five levels and arrive with the other half of issue 37. Ten are waived with a reason about Go: `ReadError` and `WriteError` with their fields and their methods, which Go's own documentation marks deprecated with the note that they are no longer returned and which nothing in Go's package builds, and `Resetter`, whose one method takes an arbitrary reader and so cannot be satisfied by a `Decompressor[R]` that reads out of its own `R`.

This package is first in the milestone because four others stand on it. `gzip` is a header, a DEFLATE stream and a CRC. `zlib` is a smaller header, the same stream and an Adler-32. A zip entry is the same stream again with a directory around it. A PNG image is its pixels filtered and then run through zlib. A half finished dependency makes four sets of tests meaningless, so this half is finished and tested against streams this repository cannot yet produce before any of the four starts.

Three pieces, one file each. The Huffman table is zlib's shape and Go's port of it: one flat table of five hundred and twelve entries indexed by the next nine bits read backwards, each entry packing the real code length into its low four bits and the decoded symbol into the rest, with codes longer than nine bits going through a link entry into a small overflow table. The property that makes it worth having is that the lookup works on bits that have not been read yet, because DEFLATE writes codes least significant bit first, so the entry an incomplete read lands on still reports a length no larger than the real one and that length says how many more bits to pull. The sliding window is one thirty two kilobyte buffer used as a ring, where a copy whose length is longer than its distance walks forward over the bytes it is writing, which is DEFLATE's only way to spell a repeated run. The block loop is over both.

Go stores what to do next as a `func(*decompressor)` on the struct and calls through it. A function pointer in a struct is not a shape this library uses, so the step is a small integer and the dispatch is a switch, which is the arrangement `core.encoding.json` already uses for its scanner and for the same reason. Go's `stepState` comes across as it is, because it says which half of a Huffman block was interrupted and a number was already right for that.

Reading is the security sensitive half, since the bytes came from somebody else. Nothing here can be made to allocate without bound: the window is allocated once, the two code length arrays are fixed size, and the overflow tables are bounded by the fifteen bit maximum a DEFLATE code may have. Nothing here can be made to hang: every loop consumes a bit or a byte, a stream that stops in the middle of anything raises `ErrUnexpectedEOF` rather than waiting, and a stream that is not DEFLATE raises on the first thing that does not parse. The output length is not bounded and cannot be, because a few hundred bytes naming a gigabyte is what compression is, so `core.io.limit_reader` around the decompressor is the answer here exactly as it is in Go and it stays the caller's choice because only the caller knows what a reasonable size is.

One thing is deliberately different and it is in the signature. Go's `NewReader` takes any `io.Reader` and quietly wraps one that cannot read single bytes in a `bufio.Reader`, and its own documentation then has to warn that the decompressor may read more data than necessary. `new_reader` asks for a reader that has `read_byte` already, so nothing is wrapped behind the caller's back and whatever follows the last block is still in the reader the caller handed over. That is not a detail: `gzip` and `zlib` both have a checksum to read after the last block and can only find it if the decompressor left it alone. A caller holding a plain reader wraps it in `core.bufio.Reader` themselves and can see in their own source that they did.

Go's reader side corpus is here in full and passes, which is its twenty nine stream table run twice, once through a reader that hands over everything it has and once through one that hands over a single byte per call, the truncation tests, the table that used to crash on an out of range literal count, the three Huffman regression tests that each carry a Go issue number, the dictionary decoder script, and both reset paths. The one Go test left out is `TestReaderEarlyEOF`, which needs a writer. What has been added is streams from an encoder that is not this one: Python's zlib at levels zero, one, six and nine, raw DEFLATE, over the poem and over Lorem Ipsum and over a text longer than the window, with the exact call that produced each written above it. That matters more than it looks like it should, because there is no writer in this package yet, and a decompressor tested only against its own writer tests agreement rather than correctness.

## v0.7.0 - 2026-09-10

M6 is complete. This is the milestone where the library learns the formats programs hand each other: JSON, XML, ASN.1 DER, CSV, PEM, fixed width binary, and the four byte codecs that everything else is wrapped in. Twenty two pull requests, six issues, and the parity count moves from 19.4 percent to 23.0 percent, which is 2,021 of Go's symbols across thirty nine packages. `core.encoding`, `core.encoding.json`, `core.encoding.xml`, `core.encoding.asn1`, `core.encoding.binary`, `core.encoding.csv`, `core.encoding.pem`, `core.encoding.base64`, `core.encoding.base32`, `core.encoding.hex` and `core.encoding.ascii85` are all complete against Go apart from what is waived with a reason about Go. Gob is the one package of the tree that is not here, and it is deferred to M13 because it needs the type registry that arrives with it.

The thread that runs through the whole milestone is reflection, and what to put in its place. Four of these packages are built in Go around a walk over a value whose type is not known until the program runs, `json`, `xml`, `asn1` and `binary`, and `core.encoding` itself is nothing but the set of interfaces that walk consults on its way past. There is no such walk here and there is not going to be one. That could have been the end of all four, and instead the same question came up four times and got the same two answers each time. The first answer is that the interface Go's walk consults before it starts guessing becomes the whole path. `json.Marshaler`, `xml.Marshaler`, `xml.Unmarshaler` and the six traits of `core.encoding` are all a type saying what it can do, and a function that takes one as a parameter is asking exactly what Go's type assertion asks, only at compile time and with an answer that cannot come back no. The second answer is that where Go's walk reads a struct tag while the program runs, `tools/codec` reads the same tag once and writes the loop out, so a decoder for a struct is ordinary code that can be read and stepped through rather than a walk nobody can see. Between them they cover everything except the part that was never worth having, which is deciding at run time what an unknown value is, and the deviations page now carries a row for each place a caller can tell.

The lesson worth carrying forward is that a table written by hand tests what the person writing it thought of. Go's own tables came across for every package in this milestone and every one of them passes, and none of them is where the bugs were. The bugs were in JSONTestSuite, three hundred and eighteen files collected by somebody whose entire purpose was to find the shapes parsers quietly disagree about, and in Mozilla's root store, a hundred and twenty one certificates written by a hundred different programs over twenty five years and now required to survive the ASN.1 reader and writer byte for byte. Both are vendored, pinned file by file, and run on every commit. That is why the exit clause for this milestone was written as two corpora rather than as a parity number, and it is the shape the exit clause should take from here on.

JSON, the scanner. `core.encoding.json` is new and is twenty of Go's sixty eight symbols, which is the whole of the part that does not need to know what a document holds. Go has one entry point, `Unmarshal`, which reads a document into whatever value it is handed by inspecting that value's type while the program runs, and there is no such inspection here, so the package is two paths instead. This is the first: `valid` says whether bytes are one JSON value and nothing else, `compact` takes the insignificant whitespace out, `indent` puts it back in a chosen shape, `html_escape` makes a document safe to drop into a script tag, `Number` is a number kept as it was written, `SyntaxError` says where a document stopped being JSON, `new_decoder` reads a stream as a flat sequence of tokens, and `parse` reads a whole document into an arena that can be walked in any order, either of which is enough to work with a document of any shape without a type to read it into. The second path is generated code, one decoder per struct, and it arrives with issue #33.

Underneath all of it is a port of Go's `scanner.go`, one byte at a time with no lookahead and no buffer of its own. Feed it a byte and it answers with an opcode saying what just happened, and that is enough for `valid`, `compact`, `indent` and the token half of `Decoder` to be four short loops over one machine rather than four parsers that have to agree with each other. Go stores the next state as a function pointer, on the reasoning that it beat a switch by ten percent, and here it is a number and a dispatch loop, because a function pointer in a struct is not a shape this library uses and because Go's states tail call each other constantly, which a number and a loop express directly. Nesting is capped at ten thousand levels, which is Go's cap and the one RFC 7159 section 9 says an implementation may set, and it is a named constant here where Go's is unexported, because it is a limit on input a program may be handed from anywhere and the only ways to learn the number in Go are to read the source or to feed in ten thousand brackets and count.

Every message is Go's word for word, offsets included. Go writes the quoting in those messages out by hand rather than borrowing `strconv`, because the borrowed version gets a lone quote of one kind or the other wrong, and that is reproduced here for the same reason. `SyntaxError.of` reads a raise back into Go's type, since there is no error value to type assert against, and `errors.matches(e, ErrJSONSyntax)` answers for the code. Go's `Valid` returns yes or no and throws away the message and the offset the scanner had already worked out, so `valid_or_raise` is here as well and raises them, over the same single pass, which spares a caller who only wanted to check a document from having to unmarshal it into something to find out why it was refused.

One thing is deliberately different. Go's `Compact` reports an offset of zero on every failure, because the loop that feeds the scanner is the one loop in that file that does not count the bytes it has fed, so a caller who catches its `*SyntaxError` is told that the document is bad and not where. This one counts, and the deviations page has the row. `compact` and `indent` both append to a `List[Byte]`, which is the shape the rest of this library uses, and both cut the list back to the length it had when they refuse, so a caller reusing one buffer for many documents never finds half of a bad one in it.

`Number` is the text of a number and not a number. JSON has one number type and it is not a machine type, so `1e400` and a twenty digit integer are both numbers a document may hold and neither survives being read as a `Float64`, and a `Number` keeps the text and lets the caller say which machine type they wanted and find out there whether it fits. It also keeps the round trip: reading `1.0` as a float and writing it back gives `1`, and reading it as a `Number` and writing it back gives `1.0`. `float64` goes through `core.strconv.parse_float`, so the answer is the float nearest the value the text names rather than one accumulated digit by digit.

Go's `TestValid`, both halves of its `TestNumberIsValid` table and the two offsets its `TestIndentErrors` pins are all here and all pass, along with its ten row `TestCompactAndIndent` table checked all four ways Go checks it. The rest of the suite is the edges Go's own tests do not go near: the shapes RFC 8259 names, the shapes it excludes, every way a number can be written that is a number in some other language and is not one here, the four places a document can end in the middle of something, and the depth cap at exactly ten thousand and at one more.

JSONTestSuite runs in full. Nicolas Seriot's corpus from "Parsing JSON is a Minefield" is the closest thing there is to a conformance suite for RFC 8259, and all three hundred and eighteen of its parsing files are vendored under `tests/data/jsontestsuite`, pinned one by one in the lock file, and put through `valid`. The ninety five documents that are JSON are all accepted. The hundred and eighty eight that are not are all refused, and every one of the refusals carries a message and an offset, which is the half of the corpus that finds bugs: a parser that accepts too much passes everything else and fails in here, on a trailing comma, a comment, a single quoted string, a number written the way some other language writes one, or an input that simply stops.

The thirty five cases RFC 8259 leaves to the implementation are answered by name rather than by whatever fell out, thirty one accepted and four refused, which is Go's split case for case. The four refused are the documents that are not UTF-8, and they are one decision rather than four: the scanner reads UTF-8, a byte order mark is neither whitespace nor the start of a value, and a document in UTF-16 is a document in another encoding, so all four stop at the first byte, which is what section 8.1 asks for. Nothing about what a string holds is refused, so the eleven files carrying unpaired surrogates and the nine carrying bytes that are not UTF-8 inside a string are all accepted, because the scanner counts brackets and quotes and reads what is between them only far enough to find the closing quote, which is where Go draws the line too and why `valid` is a question about structure and not about text.

Nothing in this suite opens a file at run time, so the corpus is turned into data by a generator and the test reads the data. Two of the files are three hundred and fifty thousand of the three hundred and fifty four thousand bytes, one being an opening bracket a hundred thousand times over, and the generator finds a repeat rather than being told about one, so what lands in the tree is four kilobytes of corpus and two long lines.

JSON, the token half. `new_decoder` and `Decoder` read a stream one token at a time, which is the part of Go's `Decoder` that does not need a type to read into. A document arrives as the four brackets and the strings, numbers, booleans and nulls between them, and the commas and colons are dropped because they carry nothing a caller does not already have from the brackets and the counting. The decoder holds its own buffer and reads ahead of what was asked for, which is what makes a stream of values on one connection work: the bytes after a value stay in the buffer and the next call starts where the last one stopped. `more` says whether the array or object being read has another element, which is the loop condition for reading an array of unknown length, `input_offset` names a byte of the original stream rather than a byte of a buffer nobody else can see, and `buffered` hands back what was read past the end of a value, for the case Go documents it for, a JSON header followed by bytes that are not JSON.

Go's `Token` is an `any` holding one of six Go types and a caller finds out which one arrived with a type switch. There is no `any` here and no type switch to do on it, so `Token` is a struct with a `kind` on it and a field for each of five kinds behind that, and five accessors that raise naming both what was asked for and what is actually there rather than handing back a value that is not there. Five rather than six because Go's list counts a number twice: a number arrives as a `float64` normally and as a `Number` after `UseNumber`, which is one thing decided by a switch on the decoder rather than by the document, and `1e400` is a number a document may hold and no float can, so a decoder that hands back floats by default is a decoder that loses documents. Every number here is a `Number` and a caller who wants a float asks for one and finds out there whether it fits, which is Go's own answer to that made the only path. `Delim` wraps a byte where Go's wraps a rune, because the four brackets are the whole of what a delimiter can ever be and the wider type allows values a decoder never produces.

Three things are not Go's. `max_depth` caps how deeply brackets may nest on the token path, which Go leaves uncapped there even though its scanner caps it for `Valid` and `Unmarshal`, so a file of nothing but an opening bracket costs Go a stack the size of the file and costs this a refusal in the scanner's own words. `tokens` hands back a `core.iter.Cursor` over the tokens left, the third user of that trait after `csv.Reader.records` and `xml.Decoder.tokens` and there for the same reason, that Go's loop is a `Token` and a comparison against `io.EOF` and a loop that leaves the comparison out ends on the first malformed document while reporting nothing. And every token owns its bytes, so a token kept across a hundred calls is still the token that was read. `buffered` is a copy for that reason too, where Go returns a reader over the decoder's own buffer that the next call moves out from under it, and the deviations page has all four rows.

Go's `TestDecodeInStream` is the table the tests are built on. Its eight streaming rows are here in full, along with the rule its harness applies to every row, that `More` is true before every token except a closing bracket, and the three of its failing rows that do not need `Decode`. Two of those pin an offset that counts from the start of the value rather than the start of the stream, which is a quirk of Go's scanner rather than a decision, and it is kept because a port that reported a different number would be reporting a different thing. The rest of the suite is what Go's table does not reach: where the offsets land as the buffer slides, what a source handing back one byte a call does to the refill loop, the escapes and surrogate pairs a string can hold, bytes that are not UTF-8 inside one, and a document that stops in the middle of a value, which is the one case that tells a stream that finished from one that was cut.

JSON, the whole document. `parse` reads bytes into a `Document` and hands back a `Value` on its root, which is the other half of working with a document of unknown shape and the half a caller wants when they have to see the end of it before deciding about the front. Go's answer is `Unmarshal` into an `any`, which gives back a tree of `map[string]any` and `[]any` that a caller walks with type switches, and neither half of that is available: there is no `any`, and a struct cannot hold itself. So a document is one flat arena. Every value in it is a node in a list, an object or an array holds a range of indices into a second list, and a `Value` is an index into the arena rather than a pointer at a node. Nothing points at anything, so nothing is recursive, and a document is three allocations that grow rather than one allocation per node. `kind` says which of the six a value is, `at` and `len` read an array, `key`, `member`, `has` and `field` read an object, and `as_bool`, `as_number` and `as_string` raise naming both what was asked for and what is actually there.

A handle is checked twice. Mojo's origins tie a `Value` to the document it came from, so a document cannot be moved or parsed into again while a handle on it is alive, which is the half a counter cannot do and a compiler can. The counter is the other half: it sits on the document and on every handle, `reset` and `parse_into` raise it, and a handle from an earlier generation raises `ErrJSONStale` rather than reading whatever now lives at its index. `reset` is why the counter is needed at all, and it is there because an arena can be refilled: a program reading a million small messages through one document allocates for the largest rather than for the total, where Go's tree is garbage and the next `Unmarshal` allocates a new one.

Four things about a document are decided rather than left to fall out. A number keeps the text the document wrote and is converted only when a caller asks for a machine type, so `1e400` and a thirty digit integer are documents this holds and Go's `any` loses. Nesting is capped at the scanner's own ten thousand, and both the builder and the writer use an explicit stack, so a document nested at the cap costs a list rather than ten thousand call frames. Duplicate keys keep both members in the order the document wrote them and `field` returns the last, which is what Go's map ends up with because each assignment overwrites the one before, and the order is still there for a caller who would rather see what was sent. And a string that is not text is refused rather than repaired: an escape naming half of a surrogate pair with no other half, and bytes that are not UTF-8, both raise `ErrJSONText`, where Go turns each of them into U+FFFD and carries on. A Mojo `String` says it is UTF-8, so the substitution would be a silent edit of somebody's data rather than a representation of it. That is the one place this refuses a document `valid` accepts, and it is only about what a string holds: `valid`, `compact`, `indent` and the token decoder all still take those documents.

`Value` writes itself back out, so `String(value)` is the document as compact JSON and a nested handle writes only its own part. Go's way back out is `Marshal` on the `any`, which is the reflection half of the package doing a job that needs no reflection, and a node already knows what it is. Escaping is what RFC 8259 section 7 requires and nothing more, so a document that arrived in UTF-8 leaves in UTF-8 and `html_escape` is still the call for one going into a script tag.

JSONTestSuite runs a second time. All three hundred and eighteen files go through `parse` as well as through `valid`, and the two agree on the ninety five that are JSON and the hundred and eighty eight that are not. They differ on exactly twenty of the thirty five the standard leaves open, the eleven carrying unpaired surrogates and the nine carrying bytes that are not UTF-8 inside a string, which `valid` accepts and `parse` refuses with `ErrJSONText`, and the test names all twenty and asserts the count. Each of the ninety five is also written back out and read again, which has to give the same bytes the second time.

XML, the token half. `core.encoding.xml` is new and is fifty three of Go's eighty two symbols, with two waived and twenty seven still to come. A document is read as a stream of tokens and written as a stream of tokens: `new_decoder` wraps a reader and `token` hands back the next start element, end element, run of text, comment, processing instruction or directive, with the elements matched against each other and the name space prefixes resolved to the URLs they were declared as, and `new_encoder` goes the other way. The twenty seven that are missing are `marshal`, `unmarshal`, `marshal_indent`, `Encoder.encode`, `Encoder.encode_element`, `Decoder.decode`, `Decoder.decode_element`, the four codec traits and the three error types they raise, and every one of them turns a struct into elements by reading its fields, which Go does with reflection and this library does with generated code, so they arrive with the generated codec work in issue #33.

Go has no `any` and no type switch here, so `Token` is a struct with a `kind` on it and the fields of all six token types behind that. Which fields a kind uses is not a guess a reader has to make: each field says, `kind` is what to branch on, and the six accessors raise naming both kinds rather than handing back a token that is not there. Go's tokens point into the decoder's buffer and stop being true as soon as the next one is read, which is what its `CopyToken` exists to escape; every token here owns its bytes, so a token kept across a hundred calls is the token that was read, and `copy_token` is still here because a port will reach for it.

A directive is not parsed. A `<!DOCTYPE ...>` arrives as a `Directive` holding its own text and nothing in it is acted on, which is Go's decision and is the reason the two well known attacks on an XML parser are not possible here rather than defended against: a document cannot declare an entity, so there is nothing for a billion laughs expansion to expand, and it cannot name an external file, so nothing is fetched. Every entity that is expanded comes from `Decoder.entity`, which the caller filled in, and the text it expands to is never scanned again, so a table of any size expands to at most its own size and there is no expansion budget to configure. On top of that `max_depth` caps how deeply elements may nest, which Go caps only inside its reflection half, so a token by token read of a million nested tags is refused here and is a million frames in Go. `raw_token` ignores the cap, because a raw token does not match elements and pushes nothing.

`strict`, `auto_close` and `entity` are Go's three settings for reading the HTML that is out there rather than the XML that is not, and `html_auto_close()` and `html_entity()` are the tables to hand them. They are functions where Go has package variables, on the reasoning that made the base64 encodings functions: a value nobody may change is either a constant or a function, and a table of a hundred entities is too big to be a constant. With them a decoder forgives a missing end tag, an entity that is not one, an attribute with no value and a value with no quotes.

The encoder checks the two things a stream of tokens can get wrong, that every start element is matched by an end element with the same name and that no token carries bytes that would read back as markup, so a comment holding the end marker, a processing instruction holding its own, and a directive whose angle brackets do not balance outside comments and quotes are refused rather than written. Everything is buffered, so `close` is the call to prefer over `flush`: it flushes and then says whether anything was left open, and an encoder that is never closed can produce a truncated document without complaining. One thing changed on purpose. Go decides whether an xml declaration is allowed by asking its buffered writer whether it is holding anything, which is the right question only until the first flush, so a caller who flushes and then writes a declaration gets a second one in the middle of the document; here a flag says whether anything has ever been written, which is the question Go meant to ask.

Go builds messages and attribute values out of arbitrary bytes with `string(b)`, and a Mojo `String` says it is UTF-8, so anything that is not is replaced with U+FFFD before the `String` is made rather than after. A numeric reference naming a surrogate becomes the replacement character for the same reason, which is what Go's `string(rune(n))` does with one.

`tokens()` hands back a `core.iter.Cursor` over the tokens left in a decoder, the second user of that trait after `csv.Reader.records` and there for the same reason: Go's loop is a `Token` and a comparison against `io.EOF`, and leaving the comparison out ends the loop on the first malformed document while reporting nothing.

Go's tables are all here and all pass. `rawTokens` and `cookedTokens` are one document parsed twice, once with the prefixes left alone and once with them resolved, and the difference between them is exactly what `token` does over `raw_token`. `xmlInput` is the documents a parser has to refuse, `nonStrictTokens` the eight bad entities a forgiving parser leaves alone, `nestedDirectives` and `directivesWithComments` the doctypes that are only read correctly if the matching of angle brackets is right, `procInstTests` the eleven ways a declaration can be written, and `encodeTokenTests` the forty rows that pin down which prefix an encoder invents for an attribute in a name space nobody declared. Go's own `testInput` splices a carriage return, a newline and a tab into the middle of a tag with string concatenation because a raw literal cannot hold them legibly, and those three characters are in the fixture here as themselves, since whitespace inside a tag is whitespace whatever it is made of and a parser that only understood spaces would pass every other test.

Two symbols are waived. `NewTokenDecoder` builds a decoder whose source is another `TokenReader`, which needs one value to hold either a byte stream or a token source, and that is an existential; a filter is still writable as a `TokenReader` over the decoder you have. `Decoder.CharsetReader` is a function field stored and called later for a document in some other encoding, and with it gone such a document is refused, which is what Go does when the field is nil.

CSV. `core.encoding.csv` is new, twenty nine of Go's thirty two symbols with three waived. CSV has no specification anybody agreed to before the fact. RFC 4180 was written in 2005 to describe what programs were already doing and says so in its own introduction, and what this implements is that document plus the one departure Go made and this keeps, which is that a record is written ending in a newline rather than a carriage return and a newline unless `use_crlf` is set. A file is records separated by newlines and fields separated by commas, a field holding a comma, a quote or a line ending is written inside quotes, and a quote inside a quoted field is doubled. Everything else in the package is either a setting for a file that does not quite follow that or a number saying where one stopped following it.

The reader forgives what Go's forgives and in the same places. Whitespace is part of a field unless `trim_leading_space` is set, a blank line is skipped but a line holding only spaces is a record with one field in it, and a carriage return before a newline is dropped everywhere including inside a quoted field, so a file written on Windows and the same file written on Linux give the same records. A bare carriage return with nothing after it is data. `comma` is the delimiter and may be any rune that is not a quote, a line ending or the replacement character, so a tab separated file is one assignment. `comment` skips a line beginning with a character, and it has to begin the line, so a hash after a space is a field. `fields_per_record` is a shape check, positive to demand a count, zero to take the count from the first record, negative for no check at all. `lazy_quotes` takes a stray quote literally instead of refusing the file.

A record may span lines, because a quoted field may hold a newline, so a failure carries two line numbers: `start_line` where the record began and `line` where the reader gave up. Go builds three different messages depending on which of those is worth printing and all three are here word for word, reachable through `ParseError.of(e)` along with the column and the code. `field_pos` gives the line and the byte column that each field of the last record started on, which is what lets a program point at the offending character rather than naming the row, and it raises on an index out of range where Go panics. `input_offset` is where the next record starts. There are two additions. `last_record` is there because Go's `Read` hands back the record alongside `ErrFieldCount` and a raise carries one value, so the record that failed the count waits on the reader, and reading carries on after it on both sides. `records()` hands back a `core.iter.Cursor` over the records left, which is the shape design.md section 7 asks for and this is its first real user: Go's loop is a `read` and a comparison against `io.EOF`, and leaving the comparison out ends the loop on the first malformed row while reporting nothing, which is the flaw `bufio.Scanner` has. With a cursor the failure comes out of `has_next` or `next` and cannot be dropped, and the reader is still usable afterwards, so a few records through the cursor and the rest through `read_all` is fine.

The writer quotes a field that needs it, doubles a quote inside a quoted field, and writes `\.` quoted as well, because a bare one ends a PostgreSQL copy. With `use_crlf` set a newline inside a field is written as a carriage return and a newline and a bare carriage return is dropped, which is Go's behaviour and is what makes the output readable by a program that splits on the pair. `write_all` writes every record and flushes. `flush` raises where Go's returns nothing and leaves the failure for a later call, and `error` is still here and still answers for a caller who would rather ask than catch.

A field that is not valid UTF-8 raises `ErrNotText`. Go builds its fields with `string(b)`, which takes any bytes at all, so a Go program reading a file written in Latin-1 gets fields it can count and compare and only notices when it prints them. A Mojo `String` says it is UTF-8, so there is no honest string those bytes could become. The three waived symbols are `TrailingComma` and `ErrTrailingComma`, which Go's own documentation says are no longer used and which nothing in Go's package reads or returns, and `ReuseRecord`, which promises that two returned slices share storage where a record here is an owned `List[String]` handed to the caller.

Neither of Go's two test tables can be harvested, because `tools/testgen` writes a row of scalars or a row of lists of them and both of Go's hold lists of lists, so sixty seven of Go's sixty eight reader rows and twenty seven of its twenty nine writer rows are typed out with Go's names in Go's order. Go's position markers came with them: a section sign for the start of a field, a pilcrow for a record boundary and a summation sign for where a record stops parsing, stripped out before parsing and then checked against `field_pos` and against the two lines and the column on every failure. Two of Go's writer rows and one of its reader rows hold the same four bytes that are not valid UTF-8, and the reader one is checked here as an `ErrNotText` refusal instead.

PEM. `core.encoding.pem` is new and complete, all seven symbols. It is the wrapper every TLS key and certificate arrives in: a `BEGIN` line, optional `Key: value` headers, base64 wrapped at sixty four characters, and an `END` line naming the same type. The format came out of Privacy Enhanced Mail, which nobody deployed, and outlived it because binary does not survive being pasted into a mail message or a configuration file.

`decode` finds the first block in a document and hands back everything after it, so a certificate chain is a loop rather than a split. Almost all of the package is in how much that loop forgives: text before the first block, text between two of them, a run of `BEGIN` lines with nothing to close them, an opening line that is not at the start of a line, a body that is not base64, and a closing line that names a different type. Every one of those is skipped rather than refused, and the search carries on after the closing line that failed, so one damaged block does not hide the ones after it. Go's fix for CVE-2022-24675 is here too: the loop finds the first closing line and then the last opening line before it, so ten million opening lines cost one pass rather than ten million.

`encode` writes `Proc-Type` first, which RFC 1421 section 4.6.1.1 asks for, and sorts the other headers by key, which it does not, so that the same block always encodes to the same bytes. A header key with a colon in it raises `ErrHeaderKeyColon` before a byte is written, so a writer is either left untouched or handed a whole block. `encode_to_memory` raises there too, where Go returns nil and tells callers in its own documentation to use `Encode` if the reason matters.

Go's unexported `lineBreaker` has no counterpart here. The body is already in memory by the time it is encoded, so the base64 is made in one call and cut into lines afterwards, which is the same output for a quarter of the moving parts. The one thing this cannot do is Go's `string(b)` on a type line or a header that is not valid UTF-8, since a Mojo `String` is UTF-8 by construction; such a block is skipped, and the deviations page has the row.

Hex. `core.encoding.hex` is new and complete, all fifteen symbols, and like base64 it is a port rather than the wrapper the plan called for. Mojo's `std.base64` has `b16encode` and `b16decode` and both were tried before this was written: they spell hex in upper case and read only upper case back, where Go writes lower case and reads either, and `b16encode` takes a string rather than bytes, which is backwards for an encoder whose input is binary by definition. A wrapper would have had to case fold in both directions and would still have been wrong about which case came out.

Two characters to the byte, `encoded_len` and `decoded_len`, `append_encode` and `append_decode`, `encode_to_string` and `decode_string`, and a streaming encoder and decoder. Decoding is three range comparisons rather than Go's two hundred and fifty six byte lookup table, because a table that always misses the cache is not a saving at this size. The streaming encoder is the only one in this directory with no `close`, since a byte is two characters and there is never a group left over, which is why Go's `NewEncoder` returns an `io.Writer` and not an `io.WriteCloser`.

`dump` and `dumper` print the three column hex dump that every other tool prints, the offset, then sixteen bytes in two groups of eight, then the printable text between bars. Go's `expectedHexDump` is checked byte for byte at every write stride from one to thirty nine, because a dumper that flushed on the wrong boundary would pass at sixteen and fail at all the others.

A hex string with an odd number of characters raises `ErrLength` and one with a character that is not a hex digit raises `ErrInvalidHexByte`, which `InvalidByteError.of` reads back to give Go's type and Go's `%#U` message, the quoted character on the end and all. A stream that ends in the middle of a pair raises `ErrUnexpectedEOF` instead, because a string was written down wrong and a stream may simply not have finished arriving, which is the line Go draws too. Go's nine `errTests` rows are all here, each with the bytes that arrived before its refusal.

Ascii85. `core.encoding.ascii85` is new and complete, all seven symbols. Four bytes to five characters, which is as dense as the printable half of ASCII goes, and it is what PostScript and PDF embed binary with. The alphabet is every character from `!` to `u` in value order plus one shorthand, `z` for four zero bytes, and that shorthand is why `max_encoded_len` is the only length calculation in this directory that is a bound rather than an answer.

`decode` hands back two counts, bytes written and characters used, and takes a `flush` that says the input is the end of the document so the last short group should be completed. Without it a group that has not all arrived is left where it is for the next call, which is what the streaming decoder does with it. Space and every control character is skipped wherever it falls, which is more than base64 and base32 skip and is affordable because the alphabet starts above the space. The `<~` and `~>` fence ascii85 usually arrives wrapped in is neither written nor read, the same as in Go.

A character outside the alphabet raises `ErrCorruptAscii85` with its offset, which `CorruptInputError.of` reads back, and so does a final group of a single character, which is all overhead and spells no byte at all. This is the one decoder in the directory that loses what decoded before a refusal, because Go's `Decode` reports both of its counts as zero when it refuses and there is nothing left to put on `errors.partial`. The deviations page has the row.

Go's `pairs` comes across through `tools/testgen` for ascii85 and `encDecTests` for hex, so the Wikipedia paragraph from Hamlet and the seven rows of hex are Go's own bytes rather than retyped ones. The tables Go declares inside its test functions, hex's `errTests` and `expectedHexDump` and ascii85's corrupt inputs, are typed out by hand, because nothing can harvest a declaration that lives in a function body.

Base32. `core.encoding.base32` is new and complete, all nineteen symbols, and it is the twin of the base64 package below it: an `Encoding` holding the alphabet, the reverse map and the padding character, `with_padding` returning a new one, the length calculations, the appending forms, and a streaming encoder and decoder. There is no strict mode because Go's base32 has none. Mojo's standard library has nothing at all here, so unlike base64 there was never a wrapper to weigh up, and the package depends on nothing but `core.errors` and `core.io`.

Go's two ready made encodings are package variables and here they are the functions `std_encoding` and `hex_encoding`, for the reason the base64 four are functions. `std_encoding` is RFC 4648 section 6, the twenty six letters and the digits two to seven that a TOTP secret and a SASL identifier are written in. `hex_encoding` is the extended hex alphabet of section 7, whose symbols sort in the same order as the values behind them, which is what DNSSEC needs to name an NSEC3 record. The same five places Go panics raise `ErrBadAlphabet` here, with thirty two bytes wanted rather than sixty four.

Decoding refuses one shape base64 has no equivalent for. A group is eight characters, RFC 4648 lists five legal padding lengths, and a final group of one, three or six symbols carries no whole byte between its bits, so an input that ends that way is a broken document rather than a shorter one. A refusal raises with `ErrCorruptBase32` and the offset on the record, and `CorruptInputError.of` reads it back to give Go's type and Go's message word for word.

The streaming decoder has the other half of that rule. A padded quantum closes a base32 document, so anything that arrives after one is refused at offset zero rather than decoded, and the count that decides it is characters that arrived during the current read rather than characters held in the buffer, which is the difference between refusing a late arrival and refusing bytes the caller is still owed. Go's `TestBufferedDecodingPadding` is five rows of exactly that and all five are here, message for message.

Go's own table of pairs comes across through `tools/testgen`, so the fifteen rows are Go's bytes rather than retyped ones, and the twenty three rows of Go's `TestDecodeCorrupt` are typed out with their offsets, because Go declares that table inside the test function where nothing can harvest it.

Base64. `core.encoding.base64` is new and complete, all twenty two symbols, and it is a port rather than the wrapper the plan called for. Mojo's `std.base64` is `b64encode` and `b64decode` over the standard alphabet with the standard padding, which is the middle of Go's package and none of its edges: no URL safe alphabet, no way to change or remove the padding, no strict mode, no `EncodedLen` or `DecodedLen` for a caller sizing a buffer, no appending form, no streaming, and a failed decode that says it failed without saying where. Writing all of that around it would have meant owning the disagreements between the two forever, so the tables are built here and the package depends on nothing but `core.errors` and `core.io`.

An `Encoding` is a value holding the alphabet, the reverse map, the padding character and the strict flag, and `with_padding` and `strict` return a new one rather than changing the one they were called on. Go's four ready made encodings are package variables and here they are the functions `std_encoding`, `url_encoding`, `raw_std_encoding` and `raw_url_encoding`, for the reason `time.UTC` is a function: there is no package level `var`, and a variable four callers can assign to is a way for one line to change what every other line encodes with.

Go panics in five places and all five raise here with `ErrBadAlphabet`: an alphabet that is not sixty four bytes, one with a carriage return or a line feed in it, one that repeats a symbol, a padding character that is not a single byte or is a newline, and a padding character already in the alphabet. An alphabet arrives from a configuration file as easily as from a literal, so it is not always something the programmer typed, and a package this far down the tier list does not get to end a process over one line of somebody's config.

A decode that meets a byte outside the alphabet raises with `ErrCorruptBase64` and the offset on the record, and `CorruptInputError.of` reads it back to give Go's type and Go's message word for word. What decoded before the failure is already in the caller's buffer and `errors.partial` says how much, which is what makes `append_decode` able to leave the good prefix behind and still refuse the document.

`new_encoder` and `new_decoder` are the streaming pair. The encoder holds up to two bytes back until it has a group of three, so it has to be closed or the last group is never written, which is the mistake everybody makes once and is why it says so in the first line of its documentation. The decoder skips carriage returns and line feeds wherever they appear, which is what lets it read the base64 out of a PEM file or a MIME body, and it never hands over bytes and a failure at once: a group that will not decode raises on the call after the one that delivered everything before it.

Go's own test table comes across through `tools/testgen`, so the eighteen pairs are Go's bytes rather than retyped ones, and each is read through all five encodings twice, once plain and once strict. The twenty four rows of Go's `TestDecodeCorrupt` are typed out with their offsets, because Go declares that table inside the test function where nothing can harvest it.

How a type says it can encode itself. `core.encoding` is new and complete, six traits with one method each: `BinaryMarshaler`, `BinaryUnmarshaler`, `TextMarshaler` and `TextUnmarshaler`, which are the four Go has had since 1.2, and `BinaryAppender` and `TextAppender`, which are the two it added in 1.24. The package depends on nothing at all, so every codec under it and every type above it can name the same six.

Go finds these at run time with a type assertion and there is nothing to assert against here. A codec that wants a type to encode itself takes it as a generic parameter bound by the trait instead, so the check happens when the program is compiled and a type that cannot encode itself is an error at the call rather than a different path taken later. The fallback Go's assertion allows is not expressible and neither is the mistake it hides.

Nothing changed shape to join. The signatures are the ones the library already had: `marshal_binary` hands back a fresh list, `unmarshal_binary` reads a span and writes nothing unless the whole input is accepted, and `append_binary` grows a list the caller owns. `time.Time` now declares all six, `math.big.Int`, `math.big.Float` and `math.big.Rat` the three text ones, and `math.rand.PCG` and `math.rand.ChaCha8` the three binary ones.

One thing did move. `big.Int.append_text`, `big.Float.append_text` and `big.Rat.append_text` returned nothing and now return the number of bytes they appended, which is what every other appending function in the library returns and what `time.Time.append_text` already returned. A caller who ignored the result carries on unchanged and a caller who wants the count no longer has to measure the list before and after.

Binary, the byte orders and the varints. `core.encoding.binary` is new and is twenty seven of Go's thirty three symbols, which is the whole of the part that does not need to know what a value is. Two halves that share nothing but a package name. Fixed width numbers, where the width is known and the only question is which end goes first, and varints, where the width is whatever the number needs. A format usually picks one: TCP headers and DER lengths are fixed width, protocol buffers and Go's own export data are varints.

`ByteOrder` and `AppendByteOrder` are both here with all nine of their methods, and so are `LittleEndian`, `BigEndian` and `NativeEndian`. Go's `ByteOrder` is an interface, so an order is a value a caller passes to every call and every call through it is an indirect one. A trait here is a constraint rather than a value, so an order is an empty struct and a function generic over one is compiled once per order with the shifts inlined, and a caller who genuinely has to choose at run time writes one branch rather than paying for an indirect call at each of them. Go keeps the appending interface separate because adding methods to `ByteOrder` after the fact would have broken every type outside its standard library that implemented it, and the split is kept here for a better reason, which is that a writer that never reads needs three methods rather than nine. `NativeEndian` is the one order that is not a wire format and it is a compile time branch rather than Go's pair of files behind a build tag, so it costs exactly what naming the right order directly would.

None of the nine check the length of what they are handed, which is Go's decision as well. Go documents a panic and gets one from the bounds check on the slice, and Mojo aborts on the same check, so a caller reading a header out of bytes that arrived from somewhere else checks the length once before the four calls that take it apart rather than in each of them.

The varint half is Go's `varint.go` entire: the appending, writing and reading forms of both the unsigned encoding and the zig zag signed one, the two that read a number off a `ByteReader`, and the three width constants. Seven bits of the number to a byte with the top bit saying whether another follows, so every number under a hundred and twenty eight is one byte, which is what makes the encoding worth having. Signed numbers are doubled and then complemented if they were negative, so minus one is one byte rather than the ten bytes of ones sign extension would have written.

One thing is deliberately different. Go's `Uvarint` carries its failures in the count it returns, zero when the input ran out and a negative one when the number was too wide, so a caller who does not look at the count is handed a zero and carries on. Both raise here, and in three codes rather than two: an empty span is `EOF`, a span that ends part way through a number is `ErrUnexpectedEOF`, and a number wider than sixty four bits is `ErrVarintOverflow` with the bytes it read on `errors.partial`, which is the magnitude of Go's negative count. The first two are the split Go's own `ReadUvarint` makes on a stream and its `Uvarint` does not make on a span, and the difference matters to a caller who was handed a whole record rather than a stream.

What is not refused is a number written with more bytes than it needs. The encoding has no minimality rule and every reader in the wild accepts a padded one, so zero written in four bytes reads back as zero, which is Go's `TestNonCanonicalZero` and is a test here that says so on purpose rather than a gap. The ASN.1 work later in this milestone is the opposite case, because DER does have that rule and a certificate that breaks it is refused.

The tests are Go's tables. The eighteen numbers of `tests` go through both signs and all six calls, the powers of two follow them, and `TestConstants`, `TestBufferTooSmall`, `TestOverflow`, `TestBufferTooBigWithOverflow` and `TestNonCanonicalZero` are here case by case, including the check Go added for its issue 41185 that an eleventh byte is refused before its value is looked at. The six symbols still to come are `read`, `write`, `size`, `encode`, `decode` and `append`, and every one of them takes an `any` in Go and walks its type while the program runs, so they land as generated code with issue #33.

The generated JSON codecs share their runtime. Every file `tools/codec` wrote used to open with the same five hundred lines of scanner and writers, because there was no package to import them from, so a project with three struct packages had three copies and a fix to one was a fix to all three by hand. They are `core.encoding.json.codec` now and the package exports them, and a generated file opens with an import naming only the ones it turned out to use. The fixture codec the selftest builds went from 936 lines to 427, and the diff that did it touched every checked in codec, which is the whole cost of the move and is paid once.

Seven names are public where nothing was before. `ValueScanner` reads a document the way generated code needs to read one, which is the caller saying what it expects next and getting either that or a refusal, so `expect`, `accept`, `read_string`, `read_bool`, `read_signed`, `read_unsigned`, `read_float`, `skip_value` and `end`, with `enter` and `leave` counting the depth. `append_string`, `append_bool`, `append_signed`, `append_unsigned` and `append_float` write the five leaf kinds the way Go's encoder writes them, into a `List[Byte]` rather than a builder, because `core.strings` sits above this package and cannot be named from inside it. `missing_key` is the raise for a field whose key the document does not have. None of the seven is a port of anything, since Go's decoder reads a type while the program runs rather than being called by code that already knows one.

A `ValueScanner` is not the state machine `valid` runs on. That one counts brackets and quotes without caring what is between them, this one is told what to expect and reads it, and they are in the same package because they have to agree: a document one refuses the other refuses, at the same offset and in the same words, and a generated decoder's failure comes back through `SyntaxError.of` like every other failure here. Making that true changed one thing about the generated decoders. A string escape naming half of a surrogate pair used to become U+FFFD, which is Go's answer, and it is a refusal with `ErrJSONText` now, which is what `parse` already did, because a Mojo `String` says it is UTF-8 and substituting would be a silent edit of somebody's data rather than a representation of it.

The number grammar is checked before anything is converted, so `01`, `.5`, `1.`, `+1` and `1e` are refused even though `core.strconv` would read three of them, and a fraction where a whole number goes is refused rather than rounded. A generated decoder reads the documents the rest of the package reads and no others.

Twenty two tests are new, for something Go has no tests for because Go has nothing like it. They are about the two claims a generated codec cannot check for itself. That the grammar this walks is the grammar `valid` and `parse` accept, cross checked row by row against `valid`. And that the writers put out what Go's encoder puts out, including the three HTML characters and the two JavaScript line terminators Go escapes beyond what the grammar asks for. Everything the writers write is read back through the scanner in the same test, which is the property that actually matters. `tools/codec` keeps its own test, which generates a codec for a package of fixtures, builds it outside this repository and runs it, and that one is about the code the generator writes rather than about the code it calls.

JSON, a value read later. `RawMessage`, `Decoder.decode` and `Decoder.disallow_unknown_fields` are new, which finishes the decoder side of the package: twenty five of Go's sixty eight symbols now, with one waived. The three of them are one thing, which is the document whose shape is decided by something inside it. A message with a `kind` and a `payload` cannot be read in one pass, because what the payload is depends on the kind and the kind is not known until it has been read, so the payload is kept as its bytes and read a second time by whoever knows what it is.

`decode` is Go's `Decode` with the typing taken off. Only a decoder knows where a value ends in a stream it is still reading, so that is the half it keeps, and what comes back is a `RawMessage` of that value's bytes for the generated code or the document path to read. The typing is the generated `unmarshal_json_<struct>`, and `disallow_unknown_fields` is Go's switch remembered on the decoder and handed to that function as its second argument, so Go's one call is two here and the setting travels between them. Go's `TestDecodeInStream` is now here row for row rather than half of it, including the two failures only `Decode` can see, a missing comma between array elements at offset eleven and a missing colon after a five hundred and thirteen character key at offset five hundred and eighteen.

`RawMessage` is a struct owning a `List[Byte]` where Go's is `type RawMessage []byte`. A method needs a struct to be on and a slice of somebody else's bytes needs an origin to be tied to, and owning the copy also means a raw message outlives the buffer it was read out of rather than pointing into one the next read moves. An empty one writes as `null`, which is Go's rule for a nil one and is what makes the zero value of a field encode to something that reads back. One thing is stricter than Go: `unmarshal_json` scans the bytes before keeping them, where Go copies whatever it is handed. Go's reasoning holds for Go, whose only caller is its own decoder, and this is a call anybody can make with anything, and a raw message that is not one JSON value breaks the document it is written into somewhere far away from where it was made. The constructor that takes bytes still copies without checking, so a decoder that has already walked them does not walk them twice.

It is a field type, so `tools/codec` handles a struct with one: the field is read with `ValueScanner.read_raw` and written with `append_raw`, and `omitempty` on it leaves the key out, which is the difference between a payload that is empty and one that was never sent. Generated decoders take a second argument now, `disallow_unknown`, defaulted off so that every existing call reads the same, and a key no field matches goes to `ValueScanner.unknown_key` rather than straight to `skip_value`. Refused, it raises Go's message word for word with an offset on it naming the value the key introduced, which Go's failure has no room for, and it does not carry `ErrJSONSyntax` because the document is well formed and the disagreement is about what the reader expected. The fixture package the selftest builds and runs has an envelope struct in it now, so all of this is proven end to end outside the repository rather than only in the emitter's output.

`Decoder.UseNumber` is waived rather than owed. It switches between reading a number into an `any` as a `float64` and reading it as a `Number`, which is a choice Go has to offer because its default loses digits, and every number here is already a `Number` on the token path and is kept as its own text in a `Document`, so both positions of the switch are the same position.

ASN.1, the DER reader. `core.encoding.asn1` is new and is forty seven of Go's fifty one symbols, which is the whole of the part that does not need to know what a value is. Go's way in is `Unmarshal`, which reads a structure into whatever value it is handed by walking that value's type while the program runs, and there is no such walk here, so the package is two paths in the same shape `encoding/json` took: this one, and generated code with a reader and a writer per struct, which comes later. What is here is `Parser`, a cursor over bytes that reads one header, or one primitive value, or hands back a second cursor over the contents of a SEQUENCE, and that is the layer Go has no name for because reflection sits directly on top of it.

Nothing in it recurses. A SEQUENCE gives back another `Parser` rather than calling into itself, so a structure nested a million deep costs a million calls that each return instead of a stack a million frames tall. Go caps nesting at ten thousand levels for exactly that reason and there is no cap here, because there is nothing to cap.

Everything refuses rather than repairs, which is what DER is for. Two programs hashing the same object have to get the same bytes, so a length that could have been shorter, a length written with a leading zero byte, an indefinite length, a tag number that fits in five bits and was written in the long form, an integer with a redundant leading byte, a bit string whose padding bits are not zero and a boolean that is neither zero nor all ones are all errors, even where the value they were reaching for is obvious. A reader that accepts any of them is a reader that will one day disagree with the one at the other end about what a certificate says.

`SyntaxError` and `StructuralError` are Go's split and are two codes here. The first says the bytes are not DER, which means the sender is broken. The second says they are DER for something else, which means the sender and the reader disagree about what a field holds. Go separates them because a certificate parser reports the two differently, and `SyntaxError.of` and `StructuralError.of` read the record back the way `json.SyntaxError` already does.

The two time types come with the check Go put behind them. Both UTCTime layouts and the one GeneralizedTime layout are Go's, and after a date parses it is written back out and compared with what came in, so a date that parsed by luck rather than by being well formed is caught. That check exists because a time package that normalises turns the thirteenth month into January of the next year rather than refusing it, which is Go's issue 11134 and is why its table has twenty four refusals in it. A UTCTime says its year in two digits and so cannot mean anything from 2050 on, so 50 through 99 come back as the nineteen hundreds, which is RFC 5280's rule and not an invention.

Each string type checks its own alphabet, including the two characters Go lets into a PrintableString that X.680 does not, the wildcard star and the ampersand, both of which are in working certificates that have not expired yet. T61String is read as Latin-1, which is what Go does and what BoringSSL does and what is not quite right, since T.61 is a defunct encoding whose code page only nearly matches Latin-1. BMPString is UCS-2, so a pair of bytes naming half of a surrogate is not a character at all and the permanent noncharacters go with it.

One thing is deliberately different. Go maps SET onto SEQUENCE while it parses, so a field declared one way is filled from the other and a document with the two the wrong way round is read without complaint. They stay apart here, because the two say different things about whether order is meaningful and a reader that cannot tell them apart cannot check that a SET OF was sorted, which is a rule certificate profiles lean on. A caller who wants Go's behaviour reads the header first and calls whichever of the two it names.

Go's tables are all here and all pass, `boolTestData`, `int64TestData`, `int32TestData`, `bigIntTests`, `bitStringTestData`, `bitStringRightAlignTests`, `objectIdentifierTestData`, `tagAndLengthData`, `utcTestData` and `generalizedTimeTestData`, case for case. Go tests its parsing helpers on contents with the header already taken off, and those helpers are private here, so every row is wrapped in the header it would have arrived with and read back through the public call, which tests one thing more than Go's version does: that the header and the contents agree.

ASN.1, the DER writer. `Builder` is the other half of the layer generated code sits on and it writes what `Parser` reads. Go's encoder builds a tree of encoder nodes, asks each node how long it is and then walks the tree a second time to write it, because it cannot know a length until it has walked the Go type behind it. There is no type to walk here, so this writes forward into one buffer instead. `begin_sequence` puts down the tag and a single byte where the length goes, the caller writes the contents, and `end` fills that byte in, or widens it and shifts the contents along if the length turned out to need more room. `begin` pushes the offset of that byte onto a list and `end` pops it, so nothing recurses and there is no depth to cap, which is the property `Parser` already had and the reason the two match.

Every primitive writer takes the tag it writes as two arguments with defaults on them, so `add_int64(v)` writes an INTEGER and `add_int64(v, ClassContextSpecific, 0)` writes the same contents under a context specific zero, which is what an ASN.1 module means by an implicit tag and is one call rather than a second set of them. Explicit tagging is `begin_explicit(0)`, the value, `end`. `add_string` and `add_time` are the two that take no override, because each picks a tag from the value it is handed and ASN.1 does not allow a CHOICE to be tagged implicitly, since there would be nothing left to say which arm was chosen.

A SET OF is sorted, which is the one DER rule a writer has to do work for. `begin_set_of` marks the value and `end` reads the elements back with a `Parser` to find where each one starts and ends, orders them by their bytes and writes them back in that order. Ordering by bytes is the whole of it because the length octets come before the contents, so a shorter element sorts ahead of a longer one that starts the same way without any padding having to be invented, which is the observation X.690 11.6 leans on and is what Go's own encoder does.

Four things Go writes without looking are refused, and each has a row on the deviations page. A `BitString` whose byte count and bit length disagree has no single encoding, and one whose padding bits are not zero has a second encoding that means the same thing, and both are the property DER exists for and are both already refused on the way in. An object identifier with a negative component is not an object identifier, and Go writes such a component as no bytes at all, so `1.2.-3.4` marshals to something that reads back as `1.2.4`. An `Enumerated` too wide to be read back is refused rather than written, because the reader is a thirty two bit one exactly as Go's is.

Two string types are written here that Go can only read. Go picks a tag from a Go type and both T61String and BMPString are a Go `string`, so its writer has no way of being told which of them was meant, where here the caller names the call and there is nothing to infer. Both matter to certificates issued before UTF8String was in common use, which is to say to anything that has to encode an old chain again. A GeneralizedTime also keeps its fractional second, written the way X.690 11.7 asks with no trailing zeroes, where Go drops it, so a time written here is the time that comes back.

`marshalTests`, `marshalWithParamsTests`, `marshalErrTests` and the rows of `TestMarshalOID` are all here and all pass, expressed as the calls a generated writer would make rather than as the struct Go puts tags on. Beyond them are the cases a table of hex strings cannot reach: a length that outgrows its placeholder at a hundred bytes, at two hundred and at forty thousand, an outer length that has to count what an inner one grew by, a tag written in the two octet and three octet high tag forms and read back, every string type written and read again, a certificate shaped value parsed and written back byte for byte, and a `RawValue` taken out of one document and put into another.

ASN.1, read and written again over Mozilla's root store. The test issue #35 asks for is here: a hundred and twenty one real certificates, the set a browser trusts, vendored from curl's conversion of Mozilla's store, pinned by digest in the lock file and embedded by a generator because nothing in this suite opens a file at run time. Each one is taken apart with `Parser` down to the last integer and put back together with `Builder`, and the result is compared with what came in byte for byte. Nothing is copied through: every integer goes through `BigInt`, every object identifier through `ObjectIdentifier`, every time through `Time`, and every length is one `Builder` worked out after the contents were written. So this is the evidence that the reader and the writer are inverse, over a hundred and twenty nine thousand bytes of documents neither of them was written against.

A table written by hand tests what the person writing it thought of. This bundle was written by a hundred different programs over twenty five years, and it holds the two hundred and forty nulls that are the algorithm parameters a modern encoder would leave out and DER says have to be there, the eight hundred and fifty two relative distinguished names that are SET OF values someone else already sorted, and the two hundred and forty two integers that a signature was computed over and that therefore have to come back with the leading byte they went in with. A second test counts what the walk found by kind and pins the totals, because a walk that refused to descend and copied each certificate over whole would pass the first test and prove nothing.

The other half of the issue is the malformed corpus, and it is every certificate damaged the ways a document is damaged in practice, one at a time, each refused with the message that names the damage rather than a general complaint. Four truncations each, which is what a dropped connection looks like. A byte on the end, which is a framing bug, and which Go reports through a second return value that callers routinely drop. The outer SEQUENCE relabelled a SET, which Go reads without complaint because it maps the two onto each other, and which is refused here since a certificate is signed over its bytes in the order they are in. And three ways of writing the same document twice, which is the thing DER exists to rule out: a leading zero in the length, the indefinite form, and the high tag form for a tag that fits in five bits.

Binary, whole values. `core.encoding.binary` is complete, all thirty three of Go's symbols, with `read`, `write`, `size`, `encode`, `decode` and `append` joining the byte orders and the varints above. These are the calls that move a value, or a run of values, rather than one number of a width the caller named, and the width comes from the type instead. Go works that out by walking the value while the program runs. There is no such walk here, so the type is a parameter and the walk happens while the program is built.

That is a narrower set than reflection would reach and less narrow than it sounds. Go's own six begin with a fast path that touches no reflection at all, `intDataSize` and `encodeFast`, and what that path covers is exactly a bool, a sized integer, a float and a slice of any of them, with reflection as the fallback for a struct or an array. What is here is that fast path with Go's run time type switch done by overload resolution, so the bytes are the same bytes and the shifts are inlined. Structs are the part reflection was doing, and a caller who has one writes the calls a field at a time or generates them, one encoder per struct, which is the division `asn1.Builder` already makes and the one the JSON codec makes.

A type with no fixed size is refused the way Go refuses one: `size` gives back -1, which is exactly what Go's `Size` does, and the other five raise with Go's message. Mojo 1.0 cannot turn a compile time fact into a compile error, so that refusal happens when the call runs. Go's commonest case never gets that far. An `int` is not fixed size because it is thirty two bits on one machine and sixty four on another, and Mojo's `Int` and `UInt` are not `Scalar` at all, so `write(w, order, 3)` does not compile rather than failing when it runs. What is left for the run time refusal is an integer wider than sixty four bits, because a `ByteOrder` has no method that wide and inventing one here would be inventing a wire format rather than porting one. The narrow floats Mojo has and Go does not are allowed, since a float16 is two bytes with an order to put them in like anything else.

`read` reads the whole value before decoding any of it, through `io.read_full`, so a source that hands over bytes a few at a time is fine, a stream that stops part way is `ErrUnexpectedEOF`, and a stream that had nothing at all to give is `EOF`, which is the split Go documents. Nothing is written into the destination unless every byte arrived, and that is worth more over a run of values than over one: a caller who catches the failure and retries is looking at the values they had before rather than at a run that is half new and half old with no way to find the seam. `write` builds one buffer and makes one call on the writer, as Go does, so a value never arrives at the far end of a socket split in two by this library's own doing. `encode` refuses a buffer with no room rather than leaving a prefix in it, and `append` grows the caller's list and hands back the count, the same rule the varint appenders follow.

The tests are Go's own table. Its `binary_test.go` is built on one struct with a field of every fixed size type in it and two golden byte arrays saying what that struct encodes to under each order, and both arrays are here in full and produced a field at a time, which is the calls a generated encoder would make. The two complex fields are not left out. Mojo has no complex scalar, and a complex on the wire is its real part followed by its imaginary one and nothing else, so the sixteen bytes Go's table spends on them are produced by four calls rather than two and the bytes are the ones Go wrote. `TestReadSlice`, `TestWriteSlice`, `TestReadBool`, `TestReadBoolSlice`, `TestSliceRoundTrip`, `TestReadTruncated` and `TestNoFixedSize` are all here as well, along with two things Go's table does not reach: a negative number keeps its two's complement and a NaN keeps its payload, both of which a port that converted where it should have reinterpreted would quietly lose.

ASN.1, one value in and one value out. `core.encoding.asn1` is complete, all fifty one of Go's symbols, with `marshal`, `marshal_with_params`, `unmarshal` and `unmarshal_with_params` joining the parser and the builder above. Go's `Marshal` takes an `any`, asks reflection what type it holds and writes the DER for it, and `Unmarshal` takes a pointer and asks the same question in reverse. Neither question can be asked here, so what stands in for the answer is an overload per type: the nine types Go's own walk bottoms out at, which are a bool, a sixty four bit integer, a `big.Int`, a string, a byte slice, an object identifier, a bit string, a time and a `RawValue`, each have their own pair, chosen while the program is built by the type of the argument rather than while it runs by a type switch.

That is the whole of the difference, because the reflection was never the interesting part of those two functions. The interesting part is the struct tag grammar and what a tag does to the header a value is written under, and that is a string on both sides, so `optional`, `explicit`, `application`, `private`, `set`, `omitempty`, `default:5`, `tag:0`, the four names for a string type and the two for a time type all mean here what they mean there. Go parses the number after `default:` and `tag:` with `strconv` and drops the part on an error rather than reporting it, so a tag string with a typo in it is a tag string with one fewer part, and that is reproduced rather than tidied up, because a port that raised where Go shrugged would refuse tags that work in the program being ported.

An implicit tag replaces the header a value would have had and an explicit one wraps it, which is one word of difference in the tag string and two bytes of difference on the wire, and the writer and the reader agree about which is which. `unmarshal` hands back what is left of the input, the way Go's `rest` does, so a caller reading a run of values off one buffer keeps going without counting the bytes themselves. A field that is optional and not there leaves the destination at the zero value, or at the `default:` if the tag string named one, where Go leaves the struct field alone because it has a whole struct in hand and this has one value.

What is not here is the struct walk. A SEQUENCE is a list of fields with a tag string on each, and walking one is what generated code does, a field at a time, against `Builder` and `Parser` directly, which is the same division `encoding/json` and `encoding/binary` already make. Two of Go's types also have no overload: `Enumerated` is a name for `Int` here and `Flag` is a name for `Bool`, so a call passing one would be a call passing the other and the tag written would be a coin toss. An ENUMERATED goes out through `Builder.add_enumerated` and comes back through `Parser.read_enumerated` instead, which is the same one call with the ambiguity spelled out of it, and the deviations page has that row and the other three.

Every row of Go's `marshalTests` that is a single value rather than a struct is a test here, unchanged, which is the integers either side of where the width goes up, the times including the one in a zone eight hours behind UTC that keeps its offset, the bit strings, the object identifiers including the one whose first number is 2, the strings at a hundred and twenty seven bytes and at a hundred and twenty eight where the length outgrows the byte it was written in, and the four string types a tag string can name. What the struct rows carried that a single value carries too is the tag string, since `MarshalWithParams` applies one to the top level value, so `implicit,tag:5` on a Go field is `tag:5` on an integer here and the header is the same header. The rest of the suite is the round trip and the cases only bytes reach: an optional field that is not there, a default that arrives when nothing does, an explicit tag with nothing inside it, a tag that does not match, and a value that stops in the middle.

JSON, the writer half. `core.encoding.json` gains `marshal`, `marshal_indent`, `unmarshal`, `new_encoder` and `Encoder` with `encode`, `set_indent` and `set_escape_html`, along with the two traits they are written against, `Marshaler` and `Unmarshaler`. Go's `Marshal` takes an `any` and walks it with reflection, and along the way it asks every value it meets whether it implements `Marshaler`, because a type that knows its own JSON should win over a walk that is guessing. The walk here is generated code, one encoder per struct written by `tools/codec`, and there is nothing to ask while the program runs, so what is left is the interface Go asks for. A type that can write itself out implements `Marshaler`, a type that can read itself back implements `Unmarshaler`, and the five calls take one. `RawMessage` already had both methods and now declares both traits, which makes it the first value in the package that goes through them.

That is a smaller door onto the same room. Go's own `Marshal` on a value implementing `Marshaler` does exactly what `marshal` does here, which is call the method, compact what came back and hand the bytes over, and the compacting is worth keeping for both of Go's reasons: a type that lays its output out prettily still produces one line, and a type that hands back bytes that are not JSON is caught at the call that made them rather than at the far end of a wire. What Go has in addition is the fallback for a type that implements nothing, and the fallback here is `marshal_json(value)`, the free function the generator wrote, which is a direct call rather than a walk.

`Encoder` is the streaming form and it is Go's, down to the newline after every value. Go gives two reasons for that newline and both still hold: a stream being read by a person while something is going wrong is readable as lines, and a number written with nothing after it gives a reader no way to know the digits have stopped. Nothing is buffered, so a sink that is a socket sees one value per call rather than a value split across several. The newline goes on before the laying out rather than after it, which is Go's order and matters, because `indent` copies trailing whitespace and the other order would give a second newline to a value that already ended in one and a blank line between every pair in a stream. `encode_bytes` is the one addition, since generated code hands back bytes rather than a value implementing anything, so this is where those bytes go, compacted and checked the same way `encode` treats what a `marshal_json` returned, which is what keeps a generated encoder and a hand written one putting the same stream on the wire.

`set_escape_html` means here what it means on Go's `Marshaler` path. It stops the three HTML characters being spelled out on the way past and it does not take away escaping the value already carried, because both sides compact what the method handed back rather than rewriting it. The difference is that every value here takes that path, so a generated encoder, whose `append_string` escapes always, keeps its escapes whatever the switch says, and the deviations page has the row. `marshal` escapes and has no switch to turn that off, which is Go's rule for `Marshal` as well. The two line separators follow the switch rather than ignoring it, which is what Go's compacting pass does and is not what Go's reflection path does, and the compacting one is right here for the same reason it is right in Go: a value that writes its own JSON takes that path there too.

The tests are Go's own stream tables. `streamTest` is eight values, one of each JSON kind, and `streamEncoded` and `streamEncodedIndent` are what an encoder writes for them plain and laid out, and both tables are here in full and run at every length from nothing to all of it, which is Go's check that a value carries no state into the next one. The `MarshalJSON` rows of `TestEncoderSetEscapeHTML` come after them, since that is the path every value takes here, and Go's `strMarshaler` is the type they are built on for the reason that makes it worth porting: a value that writes its own JSON is the only value whose bytes reach the encoder without having been through the escaping already. The rest is one behaviour at a time, what `marshal` does to whitespace and to bytes that are not JSON, where the newline lands, and what a value that refuses to be written does to the stream it was going into, which is nothing, so the next value that is fine still lands at the start of a line. The seven error types Go raises from these calls are the rest of issue #209 and are still owed.

JSON, the error types. `core.encoding.json` gains `UnmarshalTypeError` and `UnsupportedValueError`, and with them every one of Go's sixty eight symbols in the package is either written here or waived with a reason about Go. `UnmarshalTypeError` is what a decoder raises when the document is well formed and says one thing and the field wants another, and `UnsupportedValueError` is the same disagreement going the other way, a float that is infinite or is not a number and so has no spelling in JSON. Both are read back off a raise by their own `of`, the way `SyntaxError.of` reads one, since there is no error value to type assert against, and `errors.matches(e, ErrJSONType)` and `ErrJSONUnsupported` answer for the codes. A document that is simply not JSON is unaffected: `tru` is a broken literal rather than a bool in the wrong place, so it comes back as the syntax error it always was, and only a value the scanner can name in full becomes a disagreement about types.

The other five of Go's eight are waived, and the line between them is reflection. All eight carry a `reflect.Type`, because a walk over a value of unknown type has nothing else to say what it met with, and the two that are here are the two that do not need one. `UnmarshalTypeError` is handed the name by the call that failed: `read_signed(64)` is a decoder saying it wants an `Int64`, so `Int64` is what goes on the record, written by the code doing the reading rather than derived from a value while the program runs. `UnsupportedValueError` names a value rather than a type. Of the five waived, `InvalidUTF8Error` and `UnmarshalFieldError` are deprecated in Go's own documentation and nothing in Go returns either. `InvalidUnmarshalError` and `UnsupportedTypeError` are what Go's walk gives back on being handed a nil, a value that is not a pointer, a channel or a function, and all four of those are compile errors here rather than values that come back. `MarshalerError` is a wrapper whose only content is a type name Mojo cannot produce, which is the same absence that leaves `core.fmt` without `%T`, so what a `marshal_json` raises comes back out of `marshal` unchanged instead, which is what its `Unwrap` was for. `tools/parity/waivers.toml` has a line for each of the twenty symbols those five are made of.

A generated decoder now says whose field it is about to read. `tools/codec` writes one `sc.at_field("Item", key)` into every decode loop, which costs a line per struct and is what puts the struct and the key on a refusal raised several calls below it, so a document that disagrees with one field of one struct says which one: `json: cannot unmarshal string into struct field Item.id of type Int64`. The scanner keeps the two names on itself, which is where Go keeps them too, as its decoder's `errorContext`. A nested struct overwrites both and does not put them back, which is right rather than sloppy: the innermost call is the one that failed, and the loop above it sets them again before its next read.

Three things about a type disagreement read differently from Go's. The message says `into a value of type Int64` where Go says `into Go value of type int64`, and it is the one message in this package that is not Go's word for word, because the type named is a Mojo type and calling it a Go value would be telling somebody their `Int64` is something it is not. The offset is the byte the value begins at, always, where Go has one rule for a literal and another for a composite, so the two agree on `{"X": [1,2,3]}` and are one apart on `{"X": 23}`, and one rule means the number is one a caller can slice the document with. And the struct and the field are the innermost struct and its own field rather than Go's path from the root. A `null` where a value belongs is on the record as well, which Go leaves at the zero value and this cannot, for the reason `missing_key` gives. The deviations page has the rows.

Skipping a value keeps its nesting in a list rather than in the call stack. That is the change `Value.write_to` already carries, made for the same reason: the cap is ten thousand levels, a thread here gets eight megabytes of stack, and a frame holding the locals of a call that reads a string or a number does not fit ten thousand times over. A document of nothing but brackets has to come back as the refusal the depth check makes and not as a dead process, and that is a promise about every input rather than about the ones a compiler happens to leave room for.

The tests are Go's own rows. The `UnmarshalTypeError` rows of `TestUnmarshal` and all three float rows of `TestUnsupportedValues` are here, put through `ValueScanner` rather than through a type, since that is the call a generated decoder makes and the place the disagreement is found. The driver in `tools/codec` does the same thing end to end, with a struct, a document and the message that comes out of it, which is the only evidence that the generated `at_field` line is in the right place.

XML, the value half. `core.encoding.xml` gains `Marshaler`, `Unmarshaler`, `MarshalerAttr`, `UnmarshalerAttr`, `marshal`, `marshal_indent`, `unmarshal`, `Encoder.encode`, `Encoder.encode_element`, `Decoder.decode`, `Decoder.decode_element` and `UnmarshalError`, which is the whole of the half that was outstanding, so the package is now all eighty two of Go's symbols with twelve of them waived for a reason about Go. The token half has been here since the package landed and is unchanged.

Go's other half is a walk over a value with reflection, reading struct tags as it goes to decide what becomes an element, what becomes an attribute and what is left out, and along the way it asks every value it meets whether it implements `Marshaler`, because a type that knows its own XML should win over a walk that is guessing. There is no walk here. The interface Go asks for is the whole path instead: a type says how it writes itself and how it reads itself back, and the seven calls take one. That is a smaller door onto the same room, since Go's own `Marshal` on a `Marshaler` calls the method and writes what it wrote, and the difference is that a type which cannot write itself is a compile error at the call here rather than a `Marshal` that fails on some inputs and not others.

The one thing lost with the walk is the name Go gives an element by default, which it reads off the Go type, so a `Person` with no tag on it becomes `<Person>`. There is no type name to read here and nothing to derive one from, so `marshal` hands `marshal_xml` a start element with an empty name and the value names itself, and `encode_element` is the call for a caller who does have a name in hand. The deviations page has the row.

A value writing itself cannot damage the document around it. A marker goes on the encoder's stack of open tags before the call, which is Go's own arrangement and is worth having for both of the things it catches: an element the value opened and did not close is refused when the call returns, and an end tag that would close the caller's element is refused at the tag itself, by the check `encode_token` was already making. Between them a `marshal_xml` writes one element and nothing else, or it writes nothing at all.

Of Go's three error types beyond `SyntaxError`, one survives the move away from reflection and two do not. `UnmarshalError` survives because it holds a sentence rather than a `reflect.Type`, and Go's walk raises it in exactly two places, an element whose local name is not the one the destination expects and one whose name space is not, which are now checks the `unmarshal_xml` an implementation writes makes for itself. `unmarshal_error` builds the raise and is the one error builder in this library that is public, because it is the one whose callers are outside the package. `TagPathError` is waived because it reports two struct tags in one struct disagreeing about a path, which Go can only find while the program runs and which nothing reads tags at run time to find here. `UnsupportedTypeError` is waived for the reason its namesake in `encoding/json` is, that a type which cannot write itself does not implement `Marshaler` and the call site says it needs one.

Go's own tests for this half are hundreds of rows over structs with tags on them, and almost every row is a statement about what reflection makes of a tag rather than about XML, so the tests here are the part Go's `Marshaler` path does: a value writes itself out as one element and reads itself back as the same value, a caller can name the element instead of letting the value name it, a value that leaves an element open is refused and so is one that closes an element it did not open, everything in front of the first element is skipped the way Go's `Decode` skips it, a document with no element in it raises the end of the input, and the wrong element reads back as an `UnmarshalError` rather than as a syntax error.

## v0.6.0 - 2026-09-06

M5 is complete. This is the milestone where the library stops being arithmetic and text and starts touching the machine it runs on: the generated system call layer, files and directories, the environment, processes and signals, paths, instants and the time zone database. Twenty six pull requests, twenty four issues, and the parity count moves from 13.7 percent to 19.4 percent, which is 1,709 of Go's symbols across twenty eight packages. `core.os`, `core.path`, `core.path.filepath`, `core.io.fs` and `core.time` are all complete against Go apart from what is waived with a reason, and `core.os.exec` and `core.os.signal` are new.

The thread that runs through the whole milestone is that a name is not a capability. A path is a request that somebody else can answer differently between the moment it is checked and the moment it is used, so everything here that has to be safe works on descriptors instead. `remove_all` opens each directory and unlinks out of the descriptor it opened rather than walking back down the path for every entry. `Root` resolves a name one element at a time through `openat` with `O_NOFOLLOW`, follows any symbolic link itself rather than handing the joined string back to the kernel, and pops `..` off its own stack of descriptors. `dir_fs` is a name rule and says so, and `open_root` is the one that is a sandbox. The same idea decides the shapes further up: `core.os.signal` hands back a descriptor rather than a channel, because a descriptor is what the event loop in M10 will wait on, and a signal will then be waited for beside a socket without either being a special case.

The lesson worth carrying forward is about hangs. Everything in this milestone can block: a read that never returns, a child that never exits, a pipe nobody drains. A test that hangs is the one failure that reports nothing at all, and one of them did exactly that in CI for four hours before being cancelled with a single line about a limit in the log. Two things came out of fixing it. The suite runner takes a `--deadline` and samples the stopped process before killing it, so a hang names the thread it is stuck in, and the thread sanitiser job is now eight shards rather than one build, which is both faster and cheaper because instrumenting the whole library at once costs far more than instrumenting an eighth of it eight times. The test itself is skipped under the sanitiser with the reason written where it is skipped: the sanitiser wraps `read`, a signal arriving inside one of its wrappers has its handler deferred until the wrapper returns, and `SA_RESTART` means that wrapper never returns.

Waiting. `core.syscall` gains `nanosleep` and `core.time` gains `sleep`, which is Go's `time.Sleep` and the last symbol in that package that is not a timer. A signal that arrives during a wait ends it early and the kernel says so with `EINTR`, so `sleep` is a loop: it reads `CLOCK_MONOTONIC` before the first wait and again after every interruption, and waits out whatever is left. It deliberately does not use the remaining time `nanosleep` will write back, because that makes the total wait the sum of a chain of subtractions each made at a moment nobody measured, and reading the clock gives the elapsed time directly and is right whether the sleep was interrupted once or a thousand times. A zero or negative duration returns without reaching the kernel at all, which is what Go does with the same argument, and the wait does not move when the wall clock is set.

That leaves thirteen symbols in `core.time`, all of them timers, and all thirteen are waived with a reason naming M9. `Timer.C` and `Ticker.C` are channels, `After` and `Tick` are functions that return one, `NewTimer` and `NewTicker` exist to build a struct with one in it, and `AfterFunc` runs its function on a goroutine. Channels and goroutines are what M9 brings, so the thirteen are one wait rather than thirteen pieces of work, and a timer built before then would either have to invent a way of delivering that nobody coming from Go would recognise or block the calling thread, which is `sleep` under another name.

A directory a program cannot escape from. `core.syscall` gains `fstatat`, `fchownat`, `mkdirat`, `renameat`, `linkat`, `symlinkat`, `readlinkat` and `fchmodat`, the eight calls that take a directory descriptor and a name beside it. `core.os` gains `Root`, `open_root`, `open_in_root` and `RootFS`, and with them `copy_fs`, `is_timeout`, `File.chown`, `File.read_from` and `File.write_to`, which is every symbol Go's `os` has apart from two that are waived.

A `Root` holds one open directory and resolves every name it is handed one element at a time, opening each element with `openat` and `O_NOFOLLOW` and keeping the descriptors it opened on a stack. `..` pops that stack, so it is a step this library takes rather than a string the kernel is left to interpret, and popping past the root is refused rather than performed. A symbolic link comes back from the open as `ELOOP`, and the walk reads it with `readlinkat` and puts its elements in place of the one it was resolving, so a link is followed by the same code that checks everything else, an absolute target is refused, and forty of them is the limit. The name is never put back together as a string and handed to the kernel.

What that buys is the property Go's `Root` has. A name that arrived from outside the program cannot reach a file outside the root, however many links and `..` elements are in it and whatever anybody else does to the directory while the walk is running. What it does not close is the last step: the final element is resolved and then operated on, and between the two somebody can replace it. The operation still happens inside a directory this walk opened and verified, so it cannot land outside the root, but it can land on a different file with the same name. `core/os/root.mojo` says that in its own docstring rather than leaving a reader to work it out.

`Root.fs()` is a root as a `core.io.fs.FS`, over a duplicated descriptor rather than a shared one. Go's `Root.FS` holds the root itself, so closing the root breaks the file system that came out of it, and a program that wants both has to keep the root alive by hand. The `dup` costs one call, made once per file system rather than once per name, and the two values then close independently.

`copy_fs` goes the other way and writes a whole `core.io.fs.FS` out onto the disk. Every file is created with `O_EXCL`, so a name that is already there stops the copy rather than being replaced, and anything that is not a directory or a regular file is refused, a symbolic link included. There is no `read_link` that every `FS` answers, so the target cannot be asked for, and writing the link out as an ordinary file holding the target's contents would put a second copy of the data somewhere the caller did not ask for one. Go refuses it for the same reason.

`File.read_from` and `File.write_to` are the two `core.io` fast paths, and they are honest fallbacks rather than fast ones. Both are a loop through a 32 KiB buffer, which is what Go falls back to when neither `sendfile` nor `copy_file_range` applies, and neither of those is bound in `core.syscall` yet. The bytes move and the count is right, so `core.io.copy` between two files takes the path and is correct today and not yet quicker. Issue #188 is where the kernel side goes, and the two method bodies are the only thing that changes when it lands.

`is_timeout` is the fourth predicate and the odd one, because it asks the errno and nothing else. The other three have a sentinel behind them and this one does not: Go's `IsTimeout` looks for a `Timeout() bool` method rather than for an error value, and there is no `ErrTimeout` in `io/fs` to match against, so this is `PathError.timeout` asked of any error including one that never became a `PathError`. `File.SyscallConn` and `ProcAttr.Sys` are waived, both of them Go runtime mechanisms with nothing underneath them here. The first reaches a descriptor the Go runtime owns and can move in and out of the poller, and `File.fd` is the whole of the answer when nothing but the file owns it. The second is a struct declared once per platform, and `core.syscall` deliberately declares none.

Starting another program, and hearing about a signal. `core.syscall` gains `spawn`, `waitpid`, `kill`, `getpgid`, `setpgid`, the eight functions that take a wait status apart, and the five signal calls. `core.os` gains `start_process`, `ProcAttr`, `Process`, `ProcessState`, `Signal`, `find_process`, `INTERRUPT` and `KILL`. `core.os.exec` and `core.os.signal` are new packages, and `core.errors` gains `ErrProcessDone`, `ErrNotFound`, `ErrDot` and `ErrExit`.

The fork and the exec are one C function rather than two halves of a Mojo one. Between a fork and an exec a process has one thread where it had several, and the list of calls that are safe there is short and fixed, and nothing in Mojo promises to stay on it. So the child between them lives in `core/syscall/shim/spawn.c` and decides nothing: which descriptors it gets, what its environment is, which directory it starts in and whether it leads a process group are all worked out on this side and handed over as C arrays. The shim's own comment is the thing to read before changing any of it.

Reading a wait status has one trick in it and it is worth naming, because getting it wrong is silent. C writes `WIFSIGNALED` as `((signed char)(((status) & 0x7f) + 1) >> 1) > 0`, and the cast to a signed char is the whole of what makes it work: the low byte `0x7f` means the process stopped rather than died, and `0x7f` plus one is `0x80`, which is minus 128 in a signed byte and so is not above zero. The same expression written without the cast reports a stopped process as one killed by signal 127. `signaled` compares the two values instead. `core_dumped` has the matching guard, since a continued status has every bit set and the dump bit means nothing in it, which is what Go's `WaitStatus.CoreDump` does too.

`core.os.exec` is the layer a program actually wants. `command` finds the program on `PATH`, puts its name at the front of the argument vector, opens `/dev/null` for the streams nobody chose, makes the pipes and closes the right ends of them at the right moments, and turns a non zero exit into an error rather than a number the caller has to remember to look at. `start`, `wait`, `run`, `output` and `combined_output` are the five ways to set a command going and `stdin_pipe`, `stdout_pipe` and `stderr_pipe` hand back a descriptor joined to one of its streams.

The streams are descriptors rather than readers and writers, and that is the one place this is not Go's shape. Go copies a stream that is not already a file on a goroutine of its own, which is how `Stdin` can be any `io.Reader` and how `Output` can capture two pipes at once without either of them filling and stopping the child. There are no goroutines, and one thread cannot drain two pipes at once: whichever one it is not reading fills up, the child blocks writing to it, and neither side moves again. So `combined_output` gives the child one pipe for both streams and drains that, and `output` gives it a pipe for standard output and a temporary file for standard error, because a file never blocks the program writing to it. That is the only arrangement of those two calls that cannot deadlock, and two tests push a megabyte through one and half a megabyte through the other so that changing it hangs rather than passes.

The captured bytes live on the `Cmd`. Go returns them beside the error, so a command that failed still hands back what it printed, and a raise carries no second value. `captured_output` and `captured_stderr` are filled in before either capturing call raises, so a caller that catches an `ExitError` reads them off the `Cmd` it is still holding.

`ExecError` is a name that could not be turned into a program and `ExitError` is a program that ran and did not exit with zero, and the distinction is the one callers most often want, because a command that returns 1 has usually answered the question rather than failed at it. Both are read back from a raise with `of`, the same shape `PathError` and `LinkError` already have. Go calls the first one `exec.Error` and the bare name cannot be used here, because a struct called `Error` inside the package would shadow the built in `Error` that every raise in it is made of.

`look_path` refuses a program found through an empty `PATH` entry. An empty entry means the working directory, which is how a directory somebody else can write ends up being searched before `/usr/bin`, and Go has refused to run what it finds there since 1.19 rather than quietly doing what an attacker arranged. The raise carries `ErrDot` and has the path that was found on the record, so a caller who really did mean it can read it back and run it deliberately.

`core.os.signal` turns a signal into a byte on a pipe. Go's `Notify` takes a channel and there are none here yet, and a channel that only a signal handler could write to would have to be written in C anyway, so `notify` gives back a descriptor and the signal arrives on it as one byte holding its number. That is not a worse shape, it is an earlier one: a descriptor is what the event loop in M10 waits on, so a program will be able to wait for a signal beside a socket and a timer without any of the three being a special case, and the channel version can be built over this the day channels exist. Go's runtime does the same thing internally, with a self pipe underneath the channel.

The pipe is one descriptor for every signal, made once and never closed. A handler writing into a descriptor that something else has since been given would be much worse than a descriptor that stays open, so `stop` and `reset` put the signal back and leave the pipe where it is. Nothing is queued and nothing is counted, which is the promise Go's buffered channel makes and the one the operating system makes about signals in the first place. `SIGKILL` and `SIGSTOP` cannot be caught by any program, so arming either fails rather than quietly doing nothing.

`os.pipe` now sets close on exec on both ends, which Go's `os.Pipe` does and its `syscall.Pipe` does not. It did not matter until this release and it matters now: a child that inherited the write end of its own input would hold the pipe open against itself, never read the end of it and never exit, and the parent waiting for it would wait forever. The descriptors that cross into a new program are the ones named in the table handed to `start_process`, and nothing else.

Four things a Go programmer will look for and not find. `exec.CommandContext`, `Cmd.Cancel` and `Cmd.WaitDelay` are all about stopping a command from another goroutine while this one sits inside `Wait`, and there is no other goroutine for them to be stopped from, so a caller who wants to give up on a command calls `start`, does whatever waiting it wants to do, and calls `kill`. `signal.NotifyContext` is deferred with `core.context`. `signal.Notify` with an empty signal list means every signal there is, and there is no such spelling here, because a loop over every number would take over `SIGSEGV` and `SIGBUS` as well and a program that catches those and carries on is a program running on a corrupt stack.

The file system as a value. `core.io.fs` gains the `FS` trait and everything written against it: `File` and `ReadDirFile`, the five optional traits, `SubFS`, `read_dir`, `stat`, `read_file`, `read_link`, `lstat`, `glob`, `walk_dir`, `sub` and `Subtree`, plus `format_file_info`. `core.os` gains `dir_fs`, which is a directory on this host as one of them, and `core.os.File` now implements `core.io.fs.ReadDirFile`.

The point of the trait is that one method makes a file system. Anything with an `open` that takes a slash separated name and gives back something readable is an `FS`, so a directory on disk is one, an archive is one and a list of names in a test is one, and every function above works on all three. What was already here was the vocabulary those implementations speak in, the names, the modes, the infos and the entries, and this is the thing that speaks it.

Go's optional interfaces are capability bits here. A file system that can answer `read_dir` faster than opening the name would is told apart in Go by a type assertion, and there is nothing to assert against in this language. So the six optional methods are on the trait with a default body that raises, a file system that implements one sets a bit in `capabilities`, and the free functions read the bit and either call the method or fall back to opening a name. That is the same two branches Go's assertion has, decided at run time from a value rather than from a type, and it is the mechanism `core.io` already uses for `write_to` and `read_from`. The bits are allocated once across the whole library, so a type that is both a `Reader` and an `FS` answers for both in one word.

The fallback is not a consolation prize. A file system that implements nothing but `open` gets a `read_dir` that opens the name, asks the open file for its entries and closes it, a `stat` that opens and asks, a `read_file` that opens and reads to the end, and a `glob` and a `walk_dir` built out of those. A two line file system works with everything in the package, which is the whole reason to have a trait rather than a struct.

`sub` returns a `Subtree` rather than the interface Go returns, and always builds one. Go's `Sub` hands back the argument itself when the root is `"."` and calls the file system's own `Sub` when it has one, and neither is possible here because both would change the return type rather than the code that runs. A `Subtree` rooted at `"."` costs one join per name and behaves as the file system it wraps. A caller holding a file system with its own `sub` calls that method by name, and `SubFS` is the trait that says so.

A subtree cannot be talked out of its own tree. Every name is checked by `valid_path` before the root is joined onto it, and `valid_path` refuses `..`, so there is no name a caller can write that reaches the parent. A failure from underneath comes back with the root taken off the path, which is Go's rule as well: a caller of a subtree never wrote the root and has no business seeing it in a message.

`dir_fs` is the bridge to a real disk and it is a name rule rather than a sandbox. `dir_fs("/prefix").open("file")` is `open("/prefix/file")` and nothing more, so a symbolic link inside the tree pointing outside it is followed, exactly as Go says of its own. The call that would hold against a hostile tree is `open_root`, which is not bound yet. What `dir_fs` does give is that no name a caller writes escapes lexically, that a failure names what the caller asked for rather than where the root is, and that `walk_dir`, `glob` and `sub` all work over a directory on this host.

`core.path` moved to tier 2 to make this possible. Go's `path` imports nothing but `internal/bytealg` and `unicode/utf8`, which is not an accident: `io/fs` imports `path`, so a package underneath the file system cannot pull the string packages down with it. This library had `core.path` on `core.bytes` and `core.strings` for one byte scan apiece, and those two loops are now in `core/path/scan.mojo` where they say why they are there. `core.io.fs` names `core.path` from that point on, which took a second copy of the base name rule out of `core/io/fs/info.mojo`.

Paths that ask a disk. `core.path.filepath` gains `abs`, `eval_symlinks`, `glob`, `walk`, `walk_dir` and `WalkFunc`, which are the eight symbols the package had been waiting for `core.os` to exist for, and `core.io.fs` gains `WalkDirFunc`, `SkipDir` and `SkipAll` with `skip_dir` and `skip_all` to build the two raises.

The callback type is in `core.io.fs` rather than beside the walk that uses it, which is where Go puts it and for Go's reason. There will be a second walk, over the `FS` trait rather than over a real disk, and the two are different code over different things. A callback written for one has to be the same callback the other takes or every helper anybody writes has to be written twice, so the type sits under both of them.

Raising is how the callback answers. Go's callback returns an error and the walk reads it, and here it raises and the walk catches. `SkipDir` and `SkipAll` are the two raises that mean something other than failure and both walks turn either one back into an ordinary return, so a caller never sees one come out. Anything else the callback raises stops the walk and comes out unchanged, which is Go's rule too: the callback is the only thing that decides whether a failure is fatal. Go's one surprising rule is kept, that `SkipDir` from a callback which was handed a file skips the rest of the directory that file is in rather than nothing at all, and there is a test named after it so nobody quietly changes it.

A failure reaching a name goes to the callback rather than out of the walk, because a walk over somebody's home directory hits a directory it may not read and only the caller knows whether that ends the walk or is a line in a report. Go passes a nil `DirEntry` in the one case where nothing at all was learned, which is a root that could not be stat'ed, and a caller who forgets to check the error dereferences nil. Here the entry in that case carries the base name of the root and no type, so the same mistake reads a name that is true instead of ending the process.

Neither walk follows a symbolic link. A link is reported as a link and left there, which is what keeps a tree with a link back to its own parent from being a walk that never ends, and it means a walk of a directory somebody else can write to cannot be made to visit a file outside it. `eval_symlinks` is the one function in the package that does follow links, and it gives up after 255 of them. Go reports a component that is not a directory as a bare errno with no path on it and too many links as a plain message with no code at all, so neither can be told apart from anything else by a caller. Both are a `PathError` here, carrying the operation, the path and the number.

`glob` fails for exactly one reason, which is a pattern that is not one. No match is an empty list, a directory that cannot be read is skipped and a missing directory is skipped, and only a malformed pattern raises, with `ErrBadPattern`. That is Go's behaviour and a caller who needs to know a directory was unreadable walks it instead of globbing it. Worth knowing before using a glob to build a list somebody is going to delete: Go's matcher has no special case for a leading dot, so `*` finds the names a shell hides.

Temporary names, and the times on a file. `core.os` gains `create_temp`, `mkdir_temp` and `chtimes`, `core.syscall` gains `utimensat` and the two `UTIME_` constants, and `core.os` now depends on `core.math.rand` and on `core.time`.

`create_temp` and `mkdir_temp` are the same idea twice. The caller gives a directory and a pattern, the last `*` in the pattern is replaced with a random number, and the file or directory is created with `O_EXCL`, so the creation itself is what decides whether the name was free. Nothing checks a name and then creates it, because a check followed by a create is a race with every other program on the machine, and on a directory everybody can write to that race is the one an attacker wins. A name that was taken is not a failure: the call tries again with a new number, up to ten thousand times, which is Go's bound and is there so that a directory that cannot be written to for some other reason fails in a moment rather than spinning.

The file comes back open for reading and writing with mode 0600 and the directory is made 0700, which is the other half of the argument. An unguessable name is worth nothing if the thing it names is readable by everybody, and tight permissions are worth nothing if the name was predictable, so both are needed and both are here. Neither call removes what it made, since only the caller knows when it is finished with it.

A pattern is a name and not a path, so a pattern holding a path separator is refused with `ErrInvalid` and nothing is created. Letting one through would put the file somewhere the caller did not name, and a caller that wants a subdirectory passes it as the directory. The random part comes from `core.math.rand`, which is seeded from the operating system and keeps a generator per thread, and that is the same source Go uses here.

`chtimes` sets the access and the modification time on a path and is the call that finally makes `core.os` depend on `core.time`, which its `PACKAGE.toml` had been saying it would since the package was started. A zero `Time` for either one leaves that timestamp alone, which the platform spells as `UTIME_OMIT` in the nanosecond field of a `struct timespec`.

Where this differs from Go is the range. Go puts the time through `Time.UnixNano`, which stops working outside 1678 to 2262 because that is as far as a signed count of nanoseconds reaches, and a date beyond it is quietly set to a wrong one. Here the seconds and the nanoseconds go down as the two numbers they already are, so a file can be given any date a `Time` can hold. The precision is still the file system's: one that keeps whole seconds rounds the nanoseconds away and reading the time back gives what was stored.

`UTIME_NOW` and `UTIME_OMIT` are recorded from the host's own headers like everything else in `core.syscall`, and they are a good argument for why that machinery exists: macOS spells them -1 and -2 and Linux spells them 1073741823 and 1073741822, so either one typed by hand from one platform's manual page is a silently wrong number on the other.

What the process can say about itself. `core.os` gains `getpid`, `getppid`, `getuid`, `geteuid`, `getgid`, `getegid`, `getgroups`, `getpagesize`, `hostname`, `executable`, `args`, `pipe` and `exit`, and `core.syscall` gains the bindings underneath all of them.

The eight ids cannot fail and none of them raises. That is worth stating rather than leaving a reader to notice, because a call that cannot fail and raises anyway makes every caller write a `try` that can never be taken, and a reader who sees one starts wondering what the failure would mean. `getgroups` is the exception among the group calls and does raise, since it asks twice: once with a size of zero, which POSIX defines as a request for the count, and once for that many, because the limit is 16 on macOS and 65,536 on Linux and a buffer sized for either is the wrong size on the other.

`executable` is the one that is a different question on each platform. Linux reads the link at `/proc/self/exe`, so a container with no `/proc` mounted fails here, and macOS asks `_NSGetExecutablePath` and joins the answer to the working directory when it comes back relative, which is what Go does. The path is absolute and it is not promised to still name the running program, since a file can be renamed or removed while it runs, and Go makes the same non promise about the same call.

`args` is a function where Go has a package level variable, the same choice `stdin` and the other two descriptors already made. The practical difference is that Go's can be assigned to, which some programs do to hide a flag from a library they call, and this cannot, so a caller that wants a modified list makes one.

`pipe` gives back both ends as files that close themselves, and the ends are used where they sit rather than moved into two names. A `File` cannot be copied and Mojo cannot move a value out of a tuple, so reading, writing, closing and handing an end to anything that takes a `Reader` or a `Writer` all work, and giving one end away to something that wants to own it does not. The signature is already the one that will work the day the language allows it.

`exit` ends the process without running a single destructor. It is C's `_exit` rather than its `exit`, so no `atexit` handler runs either, which is what Go does and is the right end of the choice: a program ending itself deliberately should not be running teardown that some other piece of code arranged for a different reason. A program that has written something closes it and returns from `main`.

The environment, and the four directories the environment names. `core.os` gains `getenv`, `lookup_env`, `setenv`, `unsetenv`, `clearenv`, `environ`, `expand` and `expand_env`, and `temp_dir`, `user_home_dir`, `user_cache_dir` and `user_config_dir`.

Nothing about the environment is cached here, which is the one place this differs from Go on purpose. Go copies the environment into a slice at start up and answers every read from that copy, so `os.Setenv` and a `setenv` from a C library linked into the same program disagree from the moment either of them runs, and they never agree again. Reading through to libc every time costs a call and a copy per lookup and is always right, and a library that cannot see the other half of its own process is worse than a slow one. None of it is safe against another thread changing the environment at the same time, and that is not fixable at this layer, because the array libc keeps can be replaced from C and there is no lock either side of that boundary to take.

`environ` needed a second C file. The environment is a C variable rather than a C function, and Mojo can name a function and cannot name a variable, so `core/syscall/shim/environ.c` exists to hand the address of the array back as the return value of a call. macOS makes that worse rather than better: it exports the symbol only to the main executable and a library has to ask `_NSGetEnviron` for it, so the shim is also the one place that difference is written down. Nothing is copied in the C, and the walk to the terminating null and the copy out of each entry are both on the Mojo side.

`clearenv` is written over `environ` and `unsetenv` rather than over C's `clearenv`, because macOS does not have that function. The names are collected before the first removal, since removing from an array while walking it is how entries get skipped. One consequence is worth stating: an entry with no `=` in it, which a parent using `execve` can put there, has no name to unset and stays.

`expand` takes its mapping as a compile time parameter rather than as an argument, because a function is not a value in Mojo. It is spelled `expand[mapping](s)` and the parameter type is `capturing [_]`, so a nested function that closes over something works and a plain top level `def` does not. Go's awkward cases are all here and all tested: a `$` at the end of the string stays, `${` with no closing brace eats the brace and keeps the rest, `${}` disappears, and `$1x` is the name `1` followed by an `x` because the shell's one byte names are one byte long.

Three of the four directories fail rather than guess. `temp_dir` is the exception and falls back to `/tmp`, which is in the standard and is on every host in the matrix. The other three want `HOME`, or the matching XDG variable on everything except macOS, and a program with none of them set gets an error instead of a path, because a program that writes its state into a directory nobody asked for is a program whose state is somewhere its user will not think to look, and on a machine with no `HOME` at all the guess would be the root directory. A relative path in an XDG variable is refused for the same kind of reason. macOS uses `Library/Caches` and `Library/Application Support` and ignores the XDG variables entirely, which is Go's behaviour and is what makes a file written by a Mojo program land where a macOS user would look for it.

The calls that take a path. `mkdir`, `remove`, `rename`, `link`, `symlink`, `readlink`, `chmod`, `chown`, `lchown`, `truncate`, `chdir` and `getwd` are one call apiece, and what each of them adds over `core.syscall` is the same three things: a name with a zero byte in it is refused before the kernel can act on the part in front of it, an interrupted call is made again, and a failure comes back as a `PathError` or a `LinkError` carrying the operation, the path or paths and the number the platform left behind.

`remove` is the one worth reading twice. The platform has two calls, `unlink` and `rmdir`, and the caller has one name, so this tries both rather than asking `stat` which to make. That is Go's arrangement and it is not just cheaper: a `stat` followed by the matching call can be handed a directory and pass it to `rmdir` because the name came to mean something else in between. Which of the two failures gets reported is Go's rule as well, since `rmdir` on a plain file says `ENOTDIR`, which describes the call rather than the file.

`mkdir_all` and `remove_all` are the two that walk a path, and they are in `core/os/path.mojo` because that is where Go keeps them. `mkdir_all` treats a directory that is already there as success at every level, which is the reason it exists, and it leaves the permissions of a level that was already there alone, so it is not a way to fix the mode on a tree. A plain file in the way is `ENOTDIR` naming the whole path.

`remove_all` walks by descriptor rather than by name. Each level opens the directory it is about to empty and removes the entries relative to that descriptor with `unlinkat`, so a name read a moment ago is removed inside the directory it was read from and nowhere else. Building a path out of the name and calling `remove` on it would resolve the whole path again, and something that moved a directory in between could send the removal somewhere the caller never named. Go changed to this shape for that reason and this follows it. Symbolic links are removed rather than followed, and there is a test that puts a link to a directory full of files inside the tree and checks that the files are still there afterwards.

`read_file` and `write_file` are a whole file in one call in each direction. `read_file` sizes its buffer from `stat` and does not trust the size as the answer, because a file under `/proc` reports zero and has contents and an ordinary file can grow between the `stat` and the last read. The end of the file is not an error here, which is the difference from `File.read`: reaching it is the successful outcome, so an empty file gives back an empty list. `write_file` creates or truncates, writes everything and closes, and the close is part of the call, because a write that reached a buffer and not the disk is a failure the caller has to hear about.

Five calls joined `core.syscall` to support all of that. `truncate`, `chown`, `lchown` and `fchown` are the four with nothing to say beyond what they do. `openat` is the fifth and it went through the variadic shim for the same reason `open` did, so `core/syscall/shim/varargs.c` now has three functions in it rather than two.

The error record holds one record per thread, which shaped several of these. Every place that has to make a second call while a failure is in hand takes the errno as a value first, and no failing path closes a file or a directory inside an `except` block, because a close that failed there would put its own record where the fields of the error being reported are.

`DirEntry` and reading a directory. `core.io.fs` gains `DirEntry`, `file_info_to_dir_entry` and `format_dir_entry`, and `core.os` gains `read_dir` along with `File.read_dir`, `File.readdir` and `File.readdirnames`. A directory read is two questions with very different prices: what is in here is one call and gives a name and usually a kind, and what each of those things is costs a call apiece. `DirEntry` answers the first and leaves the second to whoever asks for it, which is why a listing of a large tree does not pay for a `stat` per file it is going to ignore.

Go's `fs.DirEntry` is an interface and this is a struct, the same choice `FileInfo` made and for the same reason: there are no trait objects here and a listing has to be able to hold entries read out of a host directory and entries built out of records in one list. `file_info_to_dir_entry` builds the second kind, which is what a file system with no host underneath it produces.

`info` asks the host again rather than answering from a copy taken when the directory was read, which is Go's behaviour and matters more than it looks. Between the read and the question an entry can be renamed or removed, and an `info` that answered from a snapshot would describe a file that is no longer there while looking exactly like one that is. That is also why `info` can fail at all, and it fails with `ErrNotExist` wrapped in a `PathError` naming the `lstat`.

Several file systems do not carry the kind of a file in the directory and answer `DT_UNKNOWN` for every entry. Where that happens the entry does the one `lstat` at read time and keeps the answer, which is what Go's `newUnixDirent` does, and it is what lets `type` and `is_dir` be questions that cannot fail. On the file systems that do report a kind, and both platforms in the matrix do for the ordinary ones, listing a directory of a thousand files is still one read and no stats.

`read_dir` sorts by name and drops `.` and `..`. The order a file system hands entries back in is its own business and changes between two runs of the same program on the same machine, so a listing that was not sorted would give a program output that moves for no reason a reader can see. `File.read_dir` is the same read taken a piece at a time and is not sorted, because sorting a piece of a listing would be sorting the wrong set; a count of zero or less reads everything left and returns an empty list at the end, and a positive count reads at most that many and raises `EOF` when there is nothing left, which is the pair of behaviours Go's `Readdir` has.

`fdopendir` joined `core.syscall` for this. `File.read_dir` opens the directory handle on a `dup` of its own descriptor, because `closedir` closes the descriptor it was given and a file that lost its own descriptor to a directory read would be a file that stopped working after the listing. The price is one extra descriptor held for as long as the handle is, which is the cost of reading a directory through libc rather than by hand, and `close` and the destructor both give it back.

`File`, the open flags and the standard streams, which is the first type in this library that owns a resource the kernel hands out. `open`, `create`, `open_file` and `new_file` are the four ways to get one, `read`, `write`, `read_at`, `write_at`, `seek`, `stat`, `sync`, `truncate`, `chmod`, `chdir`, `close`, `fd` and `name` are what it does, and `stdin`, `stdout` and `stderr` are the three descriptors the process started with.

A `File` closes itself when it is destroyed, which Go leaves to a finalizer and a finalizer runs at whatever later moment the collector reaches the value, or never. Here it happens at the value's last use, which is a point you can read off the source. The half of that which is not an improvement is that a destructor cannot raise, so a written file still has to be closed by hand: `close` is the only call that can tell you the last write did not reach the disk, and a destructor that swallowed that failure would be the worst of both.

It conforms to seven of the `core.io` traits, `Reader`, `Writer`, `Seeker`, `Closer`, `ReaderAt`, `WriterAt` and `StringWriter`, so `read_all`, `read_full` and `copy` and everything else written against those traits works over a real file with no adapter in between. `capabilities` reports nothing for now, because a fast `write_to` wants `sendfile` on Linux and `copy_file_range` where it exists, and claiming the bit before the code is there would make every caller take a slower path believing it was the fast one.

Three calls joined `core.syscall` to support it. `pread` and `pwrite` are what `read_at` and `write_at` are, a read or a write at a stated offset that leaves the descriptor's own offset where it was, and `fchdir` is what `File.chdir` is. `write_at` refuses a file opened for appending rather than calling `pwrite` on one, because Linux ignores the offset there and writes at the end while macOS honours it, and a call whose meaning depends on which host is underneath it is worse than a call that says no. That is why `new_file` asks `fcntl` for the descriptor's flags: the append bit has to be known when the file is adopted, and there is no asking later.

The two refusals that never reach the kernel, a call on a closed file and a path with a zero byte in it, carry the code, the op and the path but no `errno` field. `PathError.err` is the number the platform left behind, and there is no honest number when nothing was called, so `PathError.of` on one of those comes back empty while `matches(e, ErrClosed)` and `errors.field(e, "path")` answer as they do for everything else.

`stdin`, `stdout` and `stderr` are functions rather than variables, because nothing in this library lives at module scope, and the files they give back do not own their descriptors. A value that owned descriptor 1 would take the process's output away with it at the end of the statement that made it, which is a bug that would look like the program going quiet for no reason. Go's `os.SEEK_SET`, `SEEK_CUR` and `SEEK_END` are waived rather than carried, on Go's own advice to use `io.SeekStart` and its two siblings, which are `core.io`'s three.

`FileMode`, `FileInfo` and the path errors, which is `core.io.fs` growing the three types the rest of the file system work is written in terms of, and `core.os` starting with the three calls that produce them. `stat`, `lstat` and `same_file` are here, along with `is_exist`, `is_not_exist`, `is_permission`, `LinkError`, `SyscallError` and `new_syscall_error`. `File`, the environment and the eight `filepath` functions that read a disk come next and all of them need these first.

`FileMode` is one value holding what kind of file this is and who may do what to it, with the type in the top thirteen bits and the ordinary `rwxrwxrwx` permissions in the bottom nine. The fifteen constants are Go's, spelled in capitals as every constant in this library is, and `string` writes the `drwxr-xr-x` form that `ls` writes. The bits mean the same thing on every platform, which is the whole point of the type, so a mode read on one host and written on another describes the same file.

That independence is why the translation out of a `struct stat` is a switch on `S_IFMT` rather than a mask. `S_IFDIR` happens to be `0o040000` on both platforms this library builds for, and reading `st_mode` as though its type bits were already `FileMode` bits would be writing that coincidence down as a fact. The setuid, setgid and sticky bits are the visible half of the same point: the platform keeps them just above the permissions and a `FileMode` keeps them at the top, so a translation that let them through unchanged would leave them inside `perm`.

`FileInfo` is the six methods Go's interface has, and `sys` is the one that differs. Go returns `any` and every caller on a Unix system immediately asserts it to `*syscall.Stat_t`; here it returns `Optional[Stat]`, and empty is exactly the case Go's assertion fails on, which is a file system with no host underneath it such as a zip archive. The cost is a dependency Go's `io/fs` does not have, since a typed field has to name its type where an `any` names nothing, and that is written down in the package manifest and in the deviations page.

`PathError` sits in `core.io.fs` because Go declares it there, `LinkError` and `SyscallError` sit in `core.os` for the same reason, and all three are read off a raised error with `of` rather than built by hand. Their `err` is an `Errno` rather than Go's `error`, because every failure that reaches one of them in this library came back from a system call. The five sentinels come out of the generated table in `core.errors`, which is where Go's `internal/oserror` ends up.

One function knows which errno means which sentinel, and it is the four groups Go writes down in `syscall.Errno.Is`. `EEXIST` and `ENOTEMPTY` both mean something was already there, `EACCES` and `EPERM` both mean the caller is not allowed, and `ENOSYS`, `ENOTSUP` and `EOPNOTSUPP` all mean the operation is not supported. The three predicates read the sentinel when there is one and the number when there is not, so an error caught straight out of `core.syscall` answers them as readily as one that came back out of `core.os`, which is how Go behaves for a bare `syscall.Errno`.

The tests ask the mapping about failures the kernel produced rather than about errors built in the test file, because a predicate that is only ever asked about an error the same file constructed proves that the builder and the reader agree and nothing else. A second `mkdir` of a directory that is there, an `rmdir` of one that is not empty, an `unlink` of nothing, a `chdir` into nowhere and a `stat` inside a directory with no execute bit are the five, and `ENOTEMPTY` is the row that makes the point, since it is 66 on macOS and 39 on Linux and nothing about it looks like `EEXIST`.

The parity tool now follows a re-exported type to its members. `os.FileMode` is Go's `fs.FileMode` under a second name and `os.FileMode.IsDir` is a symbol Go's manifest owes `os`, so counting the type and not its methods reported a package as missing five methods it exports. The members are read where the type is declared, which is why the tool now resolves the module on the left of an import rather than only reading the names on the right.

`core.path.filepath`, the lexical half, which is nineteen of its twenty seven symbols. `clean`, `split`, `join`, `base`, `dir`, `ext`, `is_abs` and `is_match` are the questions `core.path` already answers, asked about a host path instead of about a slash separated one, and every one of them delegates to `core.path` because on the two platforms this library targets the separator is a slash and the algorithm is the same algorithm. `SEPARATOR` and `LIST_SEPARATOR` are the two constants, `ErrBadPattern` is the same sentinel both packages share, and `from_slash`, `to_slash`, `split_list` and `volume_name` are the four that exist so that a program can say which kind of path it means on a host where the two differ.

The three with no counterpart in `core.path` are the interesting ones. `rel` works out the route from one path to another, so that joining the answer onto the first names what the second named, and raises `ErrRelPath` when reading the two strings cannot say, which is when one starts at the root and the other does not or when the base climbs out through a `..` whose name only the working directory knows. `is_local` says whether a path stays inside the directory it is relative to. `localize` turns a slash separated name into a host path and refuses the ones that would escape.

`localize` is the one to reach for when a name arrived from somewhere else, an entry in an archive or a field in a request. `from_slash` converts and asks nothing, which is fine for a name the program wrote itself and is exactly the wrong tool for one it was handed. `localize` accepts only a name `core.io.fs.valid_path` accepts, so relative, already clean, not empty and valid UTF-8, and refuses any name with a NUL in it, because a NUL ends a file name in every system call underneath and a name that was cut short would open a file nobody asked for. What comes back always answers true to `is_local`, and there is a test that says so over every name the function accepts.

The eight that read a disk are not here. `abs`, `eval_symlinks`, `glob`, `walk`, `walk_dir`, `WalkFunc`, `SkipDir` and `SkipAll` all need `core.os`, and they arrive with it. `HasPrefix` is waived rather than written, because Go's own documentation says not to use it: it ignores path boundaries, so it answers yes when asked whether `/usr` is inside `/us`, and `rel` followed by `is_local` is the pair that answers that question correctly.

`core.io.fs` starts with `valid_path`, which is Go's `fs.ValidPath` and is where the rule about names in that package is written down. A name is slash separated, relative and already clean, whatever the host underneath spells its own paths like, and a name that would need cleaning is refused rather than cleaned, because the caller who assembled it is the one who knows what it was supposed to mean. It is a lexical rule that needs nothing from the `fs.FS` trait, which is still to come, and putting it where Go puts it is what keeps `localize` from carrying a second copy.

Go's own tables drive all of it. `tools/testgen` now harvests fourteen tables out of `path/filepath` and one out of `io/fs`, so a row in these tests is a row in Go's, and the `nonwin` tables Go keeps beside the shared ones are read here because this is one of the hosts they are for. Two tables are hand ported and both say why in the file: Go's `localizetests` has a row that is bytes rather than text, and a Mojo string literal is text.

Two fixes to the extractor came out of that. It now filters Go test files through the build constraints before reading them, so a `_windows_test.go` file that imports an internal package is not read on a host it was never meant for, and it keeps every alias a package was imported under rather than the last one, so a package that one test file dot imports and another imports plainly resolves in both.

`core.time.tzdata`, the IANA zone database compiled into the program. `core.time.load_location` reads the host's own copy, which is the right answer almost everywhere and no answer at all in the two places it is not, a container built from scratch and Windows. This package is the database as data, all 598 zones, so `load_location("Asia/Kathmandu")` works with no file system underneath it.

It is named rather than installed, which is the one deliberate difference from Go. Go's `time/tzdata` exports nothing whatsoever: importing it runs an `init` that assigns a package level function variable, and from that moment `LoadLocation` quietly has a second place to look, which is a thing that happened to your program because of a line in somebody else's file. There is no `init` here and no variable to assign, so the embedded copy is a function the caller names, and a program that wants Go's arrangement writes the two line fallback itself and can see that it did.

The bytes are Go's own `lib/time/zoneinfo.zip`, pinned by digest in `tests/data/LOCK.toml` and turned into one generated source file by `tools/gen/tzdata.py`. Pinning Go's copy rather than a tzdata release is the same choice the four TZif fixtures made: a disagreement between this library and Go about what a zone did in 1943 is then a disagreement about the code and not about which release of the database each side happened to compile.

Nothing is compressed. The archive holds 345,647 bytes across its 598 entries, of which 231,108 are distinct, because an alias in it is a whole copy and `Etc/GMT` and its nine other spellings are ten identical files. Storing each distinct file once and pointing the aliases at it takes a third off before anything clever happens, and what is left is small enough that a deflate decoder would be a dependency bought for nothing, which matters because there is no deflate decoder in this library yet. The cost is about 460 KB of the binary and nothing else at run time.

The lookup does not parse anything. Beside the blob is a second string of fixed width records sorted by name, each one a padded name, six hex digits saying where the zone file starts and four saying how long it is, so finding a zone is a binary search over a string and decoding one is a walk over the hex of that one file. No allocation happens for a zone that was not asked for, and nothing at all is decoded until a name is looked up.

Every expected abbreviation and offset in the tests came from running Go with `ZONEINFO` pointed at the very archive the package was generated from, so a row that passes is a row where the two libraries read the same bytes the same way. Kathmandu at three quarters of an hour, Lord Howe at a half hour saving, Dublin with its daylight flag running backwards, Troll keeping its saving time in the southern winter, and both sides of the day Samoa skipped when it crossed the date line. On top of the rows, every one of the 598 names is loaded and its index record checked, because an offset that is wrong by a byte points at something that is not a zone file and the reader refuses it rather than answering plausibly.

The marshalling methods in `core.time`, so an instant can leave the program and come back. `marshal_binary` and `unmarshal_binary` are Go's binary form byte for byte, `marshal_text` and `unmarshal_text` are RFC 3339, `marshal_json` and `unmarshal_json` are the same in quotes, `gob_encode` and `gob_decode` are the binary pair under the names Go's `encoding/gob` looks for, and `append_binary` and `append_text` put the result on the end of a list the caller already has.

Bytes cross between the two languages, which is the point of writing the binary form out exactly. Fifteen bytes: a version, the seconds since the year 1 as eight bytes most significant first, the nanoseconds as four, and the zone offset in whole minutes as two, with an offset of -1 minute standing in for UTC because no real zone is one minute west. A sixteenth byte appears when the offset is not a whole number of minutes, which is not exotic at all: every zone file starts with a local mean time entry, and Berlin's is 53 minutes and 28 seconds east.

What comes back out of the binary form is an instant and an offset, never a zone name, because the name was never written down. The offset that marks UTC gives UTC, an offset that matches what the host's own zone was using at that instant gives the host's zone with its name, and anything else gives a nameless fixed zone. That is Go's rule and it is why a round trip keeps a name only by luck. The tests check the Unix second, the nanosecond and the offset for that reason, since those three are the same on every machine in the matrix.

The text form can fail and it is worth knowing which two instants it fails on. RFC 3339 wants a year of exactly four digits, so anything outside 0 to 9999 has no spelling in it, and it wants a zone offset whose hour is under 24, which a fixed zone built with a whole day in it does not have. Both raise `ErrMarshalTime` with Go's message and with the name of the method that refused in front of it, so `Time.marshal_text: year outside of range [0,9999]` says which of the three it came out of. The binary form has its own limit, an offset that does not fit two bytes of minutes, and that is `ErrMarshalTime` too.

Reading is where this differs from Go, in a way that favours the caller. Nothing is written to the value unless the whole input is accepted, so an instant handed to a failing `unmarshal_json` is the instant it was. Go assigns before it checks, so a value it refused is a value it cleared to the year 1, and a decoder that carries on past a bad field silently moves the instant. The row is in `docs/deviations.md`.

A JSON null leaves the value alone rather than zeroing it, which is what the rest of Go's JSON decoding does with one. A value that is not a quoted string raises `ErrUnmarshalTime` before the timestamp is looked at, and a quoted string that is not RFC 3339 raises `ErrParseTime`, because a caller wants to know which of the two went wrong.

`go_string`, `is_dst` and `local` came with them. `go_string` writes the `date` call that would build the value again, in this library's spelling rather than Go's, and the location is the part neither language solves: Go writes `time.Location("Europe/Berlin")`, which does not compile, and this writes `location("Europe/Berlin")`, which does not either. `is_dst` reads the flag the zone file carries rather than guessing from the offset, so a fixed zone named `CEST` is not one. `local` is `in_location(local())`.

`parse`, `parse_in_location` and `parse_duration` in `core.time`, which read the layout language in the other direction. The same string that describes how to write an instant describes how to read one, so `parse(DATE_TIME, "2024-03-09 14:05:06")` gives back the instant `format(DATE_TIME)` would have written, and every one of the nineteen named layouts now goes both ways.

Reading is looser than writing in the two places where being strict would refuse strings that are plainly correct. A layout that never asked for a fraction reads one anyway if the value has one, because a timestamp written elsewhere usually does and the seconds are still the seconds either way, and a comma counts as a decimal point because ISO 8601 says it may. A single space in the layout matches a run of spaces of any length in the value, which is what lets `Jan _2` read both the ninth of the month and the nineteenth. Neither of these is something `format` would ever write, and both are Go's.

The one place the two forms of a fraction differ is here rather than in the writer. `.999` is optional when reading and `.000` is not, so a layout ending in `.000` refuses a value with no fraction and `RFC3339_NANO` reads what `RFC3339` wrote. Naming a width never makes reading stricter either: `.999` takes nine digits if nine are there.

A zone arrives in one of three ways and they are not interchangeable. A numeric offset in any of the ten spellings gives a zone with that offset, and if the location being read against was using that offset at that instant then the answer keeps the location, name and all, which is what makes a round trip land where it started. An abbreviation is matched against the location's own table of names first, and if it is not there it is accepted on shape alone: three capitals, or four or five ending in a `T`, with `GMT` allowed a signed hour after it. That last rule is the trap worth knowing about. `MST` reading `+07` keeps `+07` as the zone's name and gives it an offset of zero, because the piece the layout asked for was an abbreviation and a thing that looks like an offset is not one. Go does the same and it is why `-0700` is the spelling to reach for.

`parse` compares a zone against the host's local zone and `parse_in_location` compares it against a location the caller names, which is the whole of the difference between them. The local zone is only loaded when a value actually has a zone in it that needs matching, so a layout with no zone never reads `/etc/localtime`. That matters more here than in Go because `local()` has no cache to hide behind.

A failure is a raise with `ErrParseTime` on the record and Go's `*ParseError` beside it. `ParseError.of(e)` gives back the layout, the value, the piece of the layout that did not match, the characters of the value that did not match it, and the reason if the failure was a range rather than a piece. The message is Go's, character for character, including the quoting, so `parsing time "2024-03-09x": extra text: "x"` reads the same on both sides.

`parse_duration` is the other half and is the one most programs reach for first, since a length of time is what arrives from a configuration file or a command line. `2h45m`, `300ms`, `1.5h`, `-5s` and a bare `0`, with `ns`, `us`, the micro sign, the Greek mu, `ms`, `s`, `m` and `h` as the units. It raises `ErrParseDuration` with the string it was given on the record, and the three messages are Go's: a missing unit, an unknown unit, and everything else as an invalid duration.

Every expected value in the tests came from running Go over the same pair of strings, and almost every one goes through `parse_in_location` against UTC rather than through `parse`, because what `parse` answers for a value carrying `+0000` depends on where the machine running the test thinks it is. The rows that use `parse` are the ones with no zone in them at all.

`format` in `core.time`, which writes an instant out by an example of the answer. A layout is not a pattern of letters standing for fields. It is the reference instant `01/02 03:04:05PM '06 -0700` written the way the result should be written, and the reason it is that instant and not another is that its parts in order are the numbers one to seven. So `t.format("2006-01-02")` gives a date with dashes in it, `t.format("January 2, 2006")` gives one with a comma in it, and anything in the layout that is not a piece of the reference instant is copied through as it stands.

The nineteen named layouts come with it: `LAYOUT`, `ANSIC`, `UNIX_DATE`, `RUBY_DATE`, `RFC822`, `RFC822Z`, `RFC850`, `RFC1123`, `RFC1123Z`, `RFC3339`, `RFC3339_NANO`, `KITCHEN`, `STAMP` with its three widths, `DATE_TIME`, `DATE_ONLY` and `TIME_ONLY`. Twelve of them are renamed by hand because a constant is spelled in capitals here, and the seven whose Go name is already capitals throughout keep the name they had.

Every piece of the reference instant is there. Both years, four months, two weekdays, three ways of writing the day of the month and two of writing the day of the year, both clocks with `PM` and `pm` beside them, the zone abbreviation, the ten spellings of a numeric offset, and the fraction of a second in the form that keeps its trailing zeros and the form that drops them. The five offset spellings written with a `Z` give a bare `Z` at an offset of zero and digits everywhere else, which is what ISO 8601 asks for and is the only thing that separates them from the five written with a sign. A zone with no name prints its offset where the abbreviation was asked for, since something has to go there.

`append_format` puts the result on the end of a list of bytes and says how many it wrote, rather than handing back a grown list the way Go's `AppendFormat` hands back a grown slice. That is what `strconv.append_int` and the rest of the `append_` family here do, and the reason is that the list is already the caller's and a second name for it is the thing that goes stale.

Printing a `Time` goes through the layout language now. The notation an instant prints in was written by hand before there was a layout language and its own docstring said it would move when there was one, so it moved, and every test in the suite that ever printed an instant is a test of the formatter as well. The monotonic suffix is still written by hand, because there is no piece of the reference instant that could stand for a reading no calendar has a place for.

Go keeps a second and faster path for RFC 3339 alone, on the grounds that it is over half of all the layouts anybody writes. There is one path here and the output is the same either way. Reading a layout back is `parse` and is below, and so are `go_string` and the marshalling methods.

Every expected string in the new tests came from running Go over the same four instants. The layouts that are not layouts at all are as much of the point as the ones that are: `Janet` is not a month, because a lower case letter after `Jan` means the layout was in the middle of a word, `the 2nd` has the day of the month in it, because a bare `2` is the day wherever it appears, and `.001` is not three digits of a fraction, because a fraction is a run of zeros or a run of nines and that run ends at the `1`. Go answers the same way on all three and for the same reasons.

`load_location` and `local` in `core.time`, which is the part that goes and finds a zone file rather than being handed one. `load_location("Europe/Berlin")` walks the directories a system might keep its zone database in and reads the first file it finds by that name, and `local()` is the same walk for whatever the host itself is set to. Between them and the reader that was already here, a program can now name a zone the way a person would.

Where it looks is `ZONEINFO` if that is set to something, then `/usr/share/zoneinfo/`, `/usr/share/lib/zoneinfo/`, `/usr/lib/locale/TZ/` and `/etc/zoneinfo`, which is Go's list in Go's order. A directory that does not have the name is not a failure and the search moves on, so a machine with one of those answers the same as a machine with three. `local()` reads `TZ` first and follows Go exactly: no `TZ` means `/etc/localtime`, an empty one means UTC, an absolute path is read as a file, and anything else is a name looked up in the platform directories but not in `ZONEINFO`. It is also the one question in the package that always has an answer, since a program asking what time it is locally on a machine with no zone database wants a time rather than a failure, and Go gives it UTC.

A name is checked for its shape before anything is read. No IANA zone name has two dots in a row and none begins with a slash or a backslash, so a name that does is a path somebody assembled rather than a zone, and looking it up would turn `load_location` into a way of reading a file nobody meant to name. Those three tests are Go's, they happen before the first directory is consulted, and the name that was refused is on the error under `name` so a caller logging it does not have to take it back out of the sentence.

Nothing about this is cached, which is worth knowing before calling it in a loop. Go's `LoadLocation` reads the file every call too, so a named zone costs the same on both sides, but Go's `Local` is built once behind a `sync.Once` and this one is not. The reason is the reason there is no `time.UTC` here either: a `Location` holds a counted handle to a table with a destructor, and nothing with a destructor lives at module scope. Load it once and pass the copy about.

The failure the search reports is the first real one and not the last. A directory that does not have the name is stepped over, and anything else a source says is kept and raised at the end if nothing ever answered, which means a host with no zone database anywhere reports the reason rather than the fourth `ENOENT` in a row. Keeping it means capturing it: a record lives on the thread only until the next raise, and the next raise is the next source in the same loop, so holding the `Error` would have kept the sentence and handed back somebody else's number.

The tests build their own zone database rather than trusting the host's. Each one writes Go's vendored slim files into a scratch directory, points `ZONEINFO` at it and puts both variables back afterwards, so the search is what is under test and a container with no `/usr/share/zoneinfo` gives the same answers as a laptop with the whole thing. One of them writes Nuuk's file under Berlin's name, which is a strange thing to do until you want to prove that `ZONEINFO` is read before the platform directories on a machine that has both.

`getenv`, `setenv` and `unsetenv` in `core.syscall`, which is what the above needed. `getenv` gives back an `Optional`, because `TZ` unset and `TZ` empty mean different things and Go needs two functions to say so.

`Location` in `core.time`, which is the half of the package that knows an offset is not a constant. A location is a list of zones, a list of the instants the zone changes, and a POSIX TZ string for the time after the last of those instants, and `lookup` answers what was in force at a given second along with the window that answer is good for. `fixed_zone` builds one that never changes, `load_location_from_tz_data` builds one from the bytes of a compiled zone file, and an empty `Location` is UTC rather than an error, because it is the default value of a public type here and has to mean something.

A `Location` is a handle and not a table, which is the one thing to know before using it. Go hands out a `*Location` into a structure that is built once and never freed, so a `Time` holding one copies for nothing and the garbage collector is what makes that safe. Here the handle is an `ArcPointer` to an immutable table, so a copy is an atomic increment rather than two lists, and the table goes when the last thing holding it goes. That is not free and it is a great deal cheaper than copying, which is what lets a `Time` carry a location and still be an ordinary value.

A `Time` carries its location and every field is read against it. `in_location` moves an instant to another zone without changing which instant it is, `utc` moves it back, `zone` and `zone_bounds` say which zone was in force and for how long, and `date` takes a location as its last argument and does the two step correction Go does for the wall clock readings daylight saving skips or repeats. Printing a `Time` now names the real zone and offset instead of always saying `+0000 UTC`.

All of it is checked against Go instant by instant. A differ area runs two hundred thousand random instants between 1880 and 2120 through both libraries, loading the same four vendored files through the same entry point on each side, and compares the calendar fields, the weekday, the day of the year, the zone name and offset, both bounds, the printed form and the round trip back through `date`. It found the one bug worth naming here: reading a signed offset out of a zone file by narrowing the bytes and widening them back does not sign extend, so every zone west of Greenwich was hours out and nothing said so. The reader subtracts the range by hand instead, and `docs/design.md` has the rest of it with a probe pinning it.

The reader takes both file shapes. tzdata has written slim files since release 2020b, where the explicit transitions stop at the last one nobody could predict and a TZ string on the final line covers everything after, and fat files listing every transition out to 2037 are still in the wild. Version 2 and 3 files carry the whole body twice, once in four byte times and once in eight, and only the second copy is read. Leap seconds and the isstd and isutc arrays are parsed past and discarded, which is what Go does with them.

Every way of being malformed raises the same error and none of them reads past the end. Go's issue 29437 was a file whose header claimed zero zones, which loaded and then crashed the first time anybody asked it a question, and the reason to name it here is that the fix is a policy rather than a bounds check: the reader records that it ran out rather than raising as it goes, and the one error at the end says the data is malformed without saying which of the eleven fields it stopped on. A caller cannot do anything different with that information, and a file is either a zone file or it is not.

Go's four slim test files are vendored under `tests/data/go-time`, pinned by digest in `tests/data/LOCK.toml`, and embedded by a generator, because nothing in this suite opens a file at runtime. Berlin is the ordinary case, Nuuk changes at an hour the TZ string can only write with a negative offset, Gaza has explicit transitions well past where most files stop, and Dublin is the one location in tzdata whose daylight flag runs backwards, with Irish Standard Time in summer as the standard clock and GMT in winter as the saving one. That last file is why the flag is read out of the file rather than worked out from which offset is larger.

Go's own test asks a `Date` in the loaded location for its zone, which needs the join that is not here yet, so each row asks the location directly at the instant Go's `Date` call works out to, computed by running Go against these same four files. The difference is written down in the test module, since it means these rows check that the file was read correctly and not that a wall clock converts to the right instant.

`core.syscall`, the first package of M5 and the layer everything above it fails through. Constants, type sizes and structure offsets for macOS arm64, Linux x86-64 and Linux arm64, generated from each platform's own C headers rather than typed from a manual page, and the calls over descriptors, paths and `struct stat` written on top of them. `Errno` is a value that compares against a constant and prints the platform's own message, and every call raises with the number kept on the record under `errno`, so a caller decides what to do next by comparing a number rather than by reading a sentence.

Nothing here is typed by hand because this is the layer where being wrong does not look like being wrong. `struct stat` is 144 bytes on macOS and on Linux x86-64 and 128 on Linux arm64, and the two Linux architectures disagree with each other on eleven recorded facts, including the order of the fields. `mode_t` is two bytes on macOS and four on Linux. `EAGAIN` is 35 on macOS and 11 on Linux, and 35 on Linux is `EDEADLK`, so a literal in the wrong place does not fail to match, it matches something else. A C program under `tools/baseline` asks the host's headers for every one of those numbers, `pixi run baseline` checks the recording against the host on all three platforms on every run, and `tools/gen/syscall.py` turns the three recordings into one generated `abi.mojo`.

Directory reading is `opendir`, `readdir` and `closedir` rather than Go's `Getdents`. Go avoids libc entirely and so needs one of those per platform with a buffer walker for each layout, and this library is already linking libc. `Dirent` copies the fields out while the C library's own pointer is still good, since that memory is reused by the next call. `kind` is one of the `DT_` constants and is often `DT_UNKNOWN`, which is a real answer from a working call on a file system that does not carry the type, so there are deliberately no `is_dir`-style helpers on it: falling back to `lstat` is `core.os`'s decision, as it is in Go.

Both of the platform's clocks are readable through `clock_gettime`, which is one call for the two of them on all three platforms. `CLOCK_REALTIME` counts from the epoch and can be set backwards; `CLOCK_MONOTONIC` counts from a start the platform does not describe and cannot be set, so it is the one an elapsed time is measured with. Their numbers are the reason they are recorded rather than typed: monotonic is 6 on macOS and 1 on Linux, and 6 on Linux is a CPU time clock, so the wrong constant reads a clock that answers and means something else. A reading is the pair of seconds and nanoseconds the kernel wrote, unconverted, because what those add up to is `core.time`'s decision rather than this layer's.

Two facts about calling C from Mojo were found by building this and both are now design sections with a probe pinning them.

A variadic C function cannot be called portably. `external_call` emits a call of fixed arity, and on Apple silicon an anonymous argument goes on the stack rather than in a register, so `open(path, O_CREAT | O_WRONLY, 0644)` written the obvious way creates a file with mode zero on macOS and mode 0644 on both Linux machines, silently. `open` and `fcntl` therefore go through two wrappers with real prototypes in `core/syscall/shim/varargs.c`, which is the second and last C file in this library and has a README saying why it is not part of the first. `open` takes a mode on all three platforms, and a test asserts that the mode which lands on disk is the one that was asked for. `ioctl` is variadic too and is not wrapped, because nothing calls it yet.

A Mojo string is not a C string. It carries its length and no terminator, so the pointer under `as_bytes()` is not a `char *`. That is not a crash, it is worse: a path built by concatenation lands in an allocation that held a longer path a moment ago, so the call gets the right name with the tail of an older one stuck to it and fails with a plausible errno for a path nobody wrote. Every path here is copied into a zero terminated buffer first, which is what Go's `syscall.BytePtrFromString` does and for the same reason.

`core.path`, all nine symbols, and the first package of this milestone that touches nothing. `clean`, `join`, `split`, `base`, `dir`, `ext` and `is_abs` take a slash separated path apart and put it back together, `is_match` answers shell patterns, and `ErrBadPattern` is what it raises when the pattern is malformed. Everything is lexical, which is the property worth knowing before using any of it: `clean("a/../b")` is `"b"` whether or not `a` exists, and if `a` is a link to somewhere else then that answer names a different file than the input did. Go says the same about the same function, and the version that asks the file system is `filepath.eval_symlinks`, which is not here yet.

`Match` is `is_match` because `match` is a Mojo keyword, and the file it lives in is `pattern.mojo` because a module of that name cannot be imported either. That is the package's only rename and it is recorded in `tools/parity/renames.toml` beside `errors.Is` becoming `matches`, which is there for the same reason.

`tools/testgen` learned three things so that Go's own tables for all eight functions could be harvested rather than typed. A table whose strings are all printable text is now written as text instead of as hex, so a row reads `MatchTest("abc", "abc", True, "")` and can be checked against Go's source by eye; the hex form stays for the tables that are marshalled bytes, where a Mojo string literal would re-encode anything above 0x7F and quietly change the golden. A field that is an error is written as the message it carries, which is how the seventeen malformed pattern rows arrive with the text Go raises, so the test pins this library's message to Go's. And a field that is a list of values is written as a `List`, which `jointests` needs. A generated file for a package with no float in any of its tables no longer carries the paragraph about float bits or the two helpers nothing in it calls.

`core.time`, the first part of it. `Time`, `Duration`, the Gregorian calendar between them and the arithmetic over all three, which is enough to measure how long something took, to say what day a date falls on and to move about the calendar. The layout language, `Location` with the zone database, and the timers are each their own piece of work and none of them is here yet, so every method reads UTC and the package says so where a reader will see it.

The whole package is division and Mojo's division is not Go's. Mojo rounds towards negative infinity and Go rounds towards zero, and this is a library full of negative numbers: an instant before 1970, a duration counted backwards, a date named with a negative day. `core/time/divide.mojo` spells Go's two operators out as functions and every division in the package says which one it means. The calendar avoids the question a different way, by counting days from March 1 of the year -292277022400 in unsigned words, which is Go's trick over Cassio Neri and Lorenz Schneider's arithmetic.

Verified against Go rather than against a reading of Go. Two differential runs put 6106 rows through the pinned Go toolchain and through this on the same inputs and compared the text that came out: dates, clocks, weekdays, ISO weeks, year days, `Time.String`, `Duration.String`, every duration conversion, `date` with out of range arguments in every field, `add_date`, truncation and rounding of 305 durations by 12 moduli, the three Unix scales, saturating subtraction and comparison. The last three differences to go were the out of range month marker, where Go converts the value with `uint64` before printing it, so `%!Month(-3)` is really `%!Month(18446744073709551613)` and now is here too.

Fourteen of Go's own tables are harvested by `tools/testgen` and four are skipped with the reason for each written down, because a table whose rows hold a `Time` or a `*Location` cannot be written as a literal for the extractor to walk. Those tables are transcribed by hand instead: `utctests`, `nanoutctests`, the normalisation half of `dateTests`, `subTests` and `truncateRoundTests`.

Two deliberate differences from Go, both in `docs/deviations.md`. Go packs the wall clock, the monotonic reading and a flag into two words and drops the monotonic reading for any instant more than 292 years from 1885, and this holds four separate fields so nothing is dropped. And `==` here is Go's `Equal`, which compares the instant, rather than Go's `==`, which compares the fields and which Go's own documentation tells you not to use.

## v0.5.0 - 2026-09-04

M4 is complete. There is no reflection in Mojo and there is not going to be any, so this milestone built the thing that stands in for it and then the first package that leans on it. That is a reader for the JSON `mojo doc` emits, a generator that turns that JSON into encoders and decoders, and `core.fmt`, which asks while the program is being built the questions Go's `fmt` asks while it runs. Four pull requests, four issues, and the parity count moves from 13.6 percent to 13.7 percent, which is the wrong number to read this milestone by. Half of it produced tools rather than symbols, and four of the milestones after this one are built on those tools.

The lesson of the milestone was about reporting rather than computing. Everything here decides things at compile time, and Mojo 1.0 has no way to turn a compile time fact into an error or a warning. What it has is an interpreter that folds `comptime` bindings by running our own code, so a `print` from that code comes out while the program is built. Every compile time check in this library is now that print, with a marker on it, and the build of the test suite is what turns a marker into a failure. The plan had been for the linter to do it, and the linter could not: only code reachable from `main` is elaborated, so compiling a package folds nothing at all and the check had been passing without ever having run. That is worth knowing before `database/sql`, the templates and the codecs use the same pattern.

`tools/docjson`, the reader every generator here shares. It runs `mojo doc` over a package, models the structs, resolves the type names, and answers questions about fields, tags, conformances and parameters. A Go struct tag written in backticks goes in a field docstring, because there is nowhere else in Mojo to put one, and it comes back out of the compiler byte for byte.

Two things about that JSON shaped the reader and are worth knowing if you write a generator against it. A field type arrives as rendered text under the name it was declared with rather than the name the importing module wrote, so a field written `BigInt` prints as `Int`. And private fields are not in the JSON at all, so a struct with one looks exactly like a struct without one. Both are answered by reading the module's source alongside the JSON. Where the source cannot be read, a name that could be two things is reported as ambiguous and a struct that might be hiding a field is reported as incomplete, and a generator refuses rather than guesses in both cases.

`tools/codec`, the first generator over it. It writes one `json_codec.mojo` beside the structs, holding an encoder and a decoder for every struct whose docstring says `codec:"json"`, and it runs on any package anywhere rather than only on this library's. It refuses rather than guesses, which is most of the difference between it and Go's `encoding/json`: a misspelled tag, an option only Go has, two fields that would collide under one JSON name, a generic struct, a struct with a private field, and a field in another package all stop the run with a message naming the field, and nothing is written when anything is refused.

One deliberate difference from Go. Go leaves a field the document does not carry at its zero value and Mojo has no zero value, so only `Optional`, `List` and `Dict` may be absent here and anything else missing is an error. That makes `omitempty` on anything but those three a refusal too, because a field left out that cannot be read back is a round trip that quietly loses data. The scanner each generated file needs is copied into it rather than imported, so a codec works for somebody who has this library and nothing else of ours, and when `core.encoding.json` lands in M6 the emitter can import instead.

`core.fmt`, the compile time half. The format string is a `comptime` parameter, so it is parsed while the program is built, the verbs are checked against the types of the arguments beside them, and what is left in the program is the concatenation with no format string in it. `sprintf`, `printf`, `fprintf` and `appendf` are here, with every verb, flag, width and precision Go has, explicit argument indexes and `*` widths and precisions read from arguments.

The part that is not what anybody expects is how a mistake is reported. Mojo will not turn a compile time fact into a compile error and it will not turn one into a warning either. `where` clauses are proof carrying and their solver refuses to call our parser at all, and `@deprecated` warns wherever the name is written, including in a branch that is never taken and in a function that is never instantiated, so it warns on correct code. What does work is the compile time interpreter itself: a `comptime` binding whose value is read is folded by an interpreter that runs our own code, and a `print` in that code prints while the program is built. So a wrong format string now puts a line on the compiler's output naming the format, the verb and the argument, only for the call that is wrong, and then the program prints Go's exact marker when it runs. Two limits come with that and are written down: the line has no source location, so it names the format string instead, and a build served from the compiler's cache does not re-run the interpreter, so the line appears on the build that first compiles the call.

Inside this repository the build of the test suite turns any such line into a failure, which is what keeps a wrong format string out of `core`. That duty used to belong to the linter and did not work there: compiling a package elaborates nothing, so the check had been passing without ever having run.

326 of the 811 rows of Go's own `fmtTests` are harvested into one call per row by `tools/testgen/fmtcases` and pass byte for byte. The rest cannot be ported yet and the generated file states the count and the reason for each. The fourteen rows that expect an error marker are moved rather than dropped: they are format strings this library complains about, so they live in `tests/warnings` where a complaint is expected, and eleven of them assert the complaint text and Go's marker side by side. Two rows of Go's table are the reason that file is worth having, an eighteen digit width that overflows every integer there is and a verb that is a rune rather than a byte.

Two differences from Go were found by those rows and fixed. A format ending in a bare `.` does not start a precision in Go, so `%.` of an `Int` is `%!.(int=3)` and not a `NOVERB`. And `%x` of a string honours the zero flag when it pads, so `%08x` of `xyz` is `0078797a` rather than three spaces and six digits.

`core.fmt`, the runtime half. A format string assembled from a translation table is not known while the program is built, and the compile time path cannot take one, so there is a second entry point that can: `vsprintf`, `vprintf`, `vfprintf` and `vappendf`, taking a `String` and a list of `Arg`. It has no checking, it costs a box for every argument, and it is the honest answer for the caller who needs it and the wrong answer for everybody else. What the two paths share is the point of the design. The format string goes through one parser and every verb is turned into a call by one set of functions, so the only thing written twice is how a value is taken apart, which is a question about types and cannot be shared. All 326 harvested rows of Go's table now run down both paths and the two are compared to each other before either is compared to Go.

One thing does not survive the boxing and it is said out loud rather than papered over. A struct that prints field by field is walked with the verb it was asked for, and at the moment it goes into the list nobody knows what that verb will be, so it is walked at that moment under `%v` unless the caller names a different spec. If the format later asks for something else, the result is a marker saying the value was not boxed for that verb, rather than the answer to a different question handed over as if it were the right one.

`%v` of a type this package has never heard of is where the absence of reflection is felt, and it has three answers where Go has one. A type that implements `Writable`, which is Go's `Stringer`, prints through that. A type that implements the new `Fields` trait prints its fields, with the verb, the flags, the width and the precision handed down to each one exactly as Go hands them down, so `%d` of a struct holding an `Int` and a `String` is Go's `{1 %!d(string=hello)}` and `%#v` is Go's syntax with the type name in front. A type that implements neither is named on the compiler's output at the call, with both ways out spelled in the message, and prints Go's `%!v(value)` marker when it runs. `Fields` is one method and is meant to be generated from the same `mojo doc` JSON the codecs are generated from, which is why the trait is the shape it is.

The `Print` and `Sprint` families are here too, with Go's spacing rule, which is that `Print` puts a space between two arguments only when neither of them is a string. That rule looks arbitrary until you write `print("x = ", x)`, which is the call it exists for. Whether an argument is a string is known while the program is built here, so the spaces are decided then, where Go decides them at run time with a type switch. The names are Go's, so importing `print` from this package shadows the builtin in that file, and the way to avoid that is to import the package and write `fmt.print`.

## v0.4.0 - 2026-09-04

M3 is complete. Text and numbers, which is the two conversions between them, the elementary functions, the bit level primitives underneath everything numeric, complex numbers, random numbers, and arbitrary precision integers, rationals and floats. Nine pull requests, four issues, and the parity count goes from 7.8 percent to 13.6 percent, which is 1,208 of Go's symbols across eighteen packages.

The thread that runs through all of it is that accuracy is a contract rather than a preference, and that the contract is what decided wrap against port every time the question came up. `core.strconv` prints the shortest decimal that reads back as the same float and reads back the nearest float to what was written. `core.math` holds every function to the tolerance Go's own test tables hold it to. Every operation in `core.math.big`'s `Float` is correctly rounded, which means the true answer rounded once rather than approached through a sequence of roundings. Measured against those contracts, `std.bit` is exact and the thirty counting and reversing functions are one call each, while `std.math.erf` is off by a hundred and seventy million parts in the last place over Go's own inputs and is written out instead. The library calls Mojo's where Mojo's is right and ports Go's where it is not, and a measurement is what says which, not a preference for one or the other.

The other thread is that a port is worth what it is checked against, and that checking it against itself is worth nothing. Go's own test tables are now harvested out of the Go tree by `tools/testgen` rather than typed, and the tool fails rather than skipping when a table it was told to take is not there, since a table quietly disappearing after a Go upgrade would take its coverage with it and say nothing. Above that are the differential runs against a real Go process, which now include writing out and reading back all 4,294,967,296 float32 there are. And inside the suite are the independent oracles: the `Float` arithmetic is checked against a number held as a list of exponents, where adding is concatenating two lists, and the square root is checked by squaring the answer and measuring the distance back.

`core.math.big`, 166 of Go's 166 symbols with six waived. Arbitrary precision integers, rationals and floating point numbers, and the unsigned limb layer that all three are built on.

An `Int` is a sign and a list of sixty four bit limbs, a `Rat` is two `Int` values kept in lowest terms with the sign on the numerator, and a `Float` is a sign, a mantissa of as many bits as you ask for, and an exponent, with six rounding modes and an accuracy reported after every operation saying which way the answer was rounded. Every arithmetic result is correctly rounded, meaning it is the true answer rounded once rather than approached through a sequence of roundings.

The limb layer is Go's `nat`, split the way Go splits it. Multiplication is schoolbook below forty digits and Karatsuba above it with a squaring path of its own. Division is Knuth's algorithm D, with the divisor scaled so the two digit guess is never more than one too large and a reciprocal cached across the digits. Base conversion is a digit at a time for short numbers and a table of divisor powers for long ones. Exponentiation is a sliding window, with Montgomery multiplication for an odd modulus and Montgomery plus the Chinese remainder split for an even one. The greatest common divisor is Lehmer's, which does most of its work in single digit arithmetic on the leading digits. `probably_prime` is Baillie-PSW: the Miller-Rabin rounds the caller asked for, plus a base two round and an extra strong Lucas test that no known composite survives.

Two of Go's algorithms are not here, `divRecursive` and `karatsubaSqr`. Both are written entirely as overlapping subsections of one vector being read and written by the same call, which this port cannot express. Neither changes an answer, so a very large division and a very large squaring are slower here and correct.

There is no destination argument anywhere in the package, and that is the difference a caller meets first. `z.Add(x, y)` is `x.add(y)` returning a new value, because Mojo will not let one value arrive as both the mutable receiver and a borrowed argument, and `z.Add(z, y)` is exactly that. `quo_rem`, `div_mod` and `gcd_ext` have a second answer and write it through a `mut` argument, because a tuple would need `Int` to be implicitly copyable and a type holding a list cannot be. For a `Float` the same rule decides where the precision and the rounding mode come from: `x.add(y)` works at the wider of the two precisions and rounds by `x`'s mode, which is what Go's `new(Float).Add(x, y)` does, and `x.add(y, p)` names the precision. `copy` keeps the source's precision and mode where `set` rounds to the receiver's, which is Go's own distinction between `Copy` and `Set`.

`And`, `Or` and `Not` are Mojo keywords, so they are `__and__`, `__or__` and `__invert__`. `Xor` follows them to `__xor__` and `AndNot` stays `and_not`. The type is named `Int`, so a file that imports it by name loses Mojo's own `Int`, and every test file and the package docstring say `import core.math.big as big` and spell it `big.Int`, which is what a Go caller writes anyway.

Every panic is a raise and so is every nil. That is division by zero, a negative bit index, a bit that is not zero or one, the square root of a negative number, a base outside two to `MaxBase`, an even second argument to `jacobi`, a negative round count to `probably_prime`, a `fill_bytes` buffer too small to hold the number, a zero denominator, the inverse of zero, a NaN or an infinity handed to `Rat.set_float64`, and the three places Go returns a nil `Int` for no inverse, no modular square root and a negative power of a number with no inverse. Go panics with an `ErrNaN` value in the six places reachable through a `Float`, which are two infinities of opposite signs added, two of the same sign subtracted, a zero times an infinity, a zero over a zero or an infinity over an infinity, the square root of a negative number, and a NaN handed to `set_float64` or `new_float`, and all six raise with the `ErrNaN` code instead. Go's own documentation calls that panic a value carrying an error, which is a raise written the long way round.

A `Rat`'s denominator is a one from the moment the value exists. Go leaves the zero value's empty and reads an empty one as a one, which costs it `mulDenom`, `scaleDenom` and half of `norm`. None of the three has a counterpart here and no number behaves differently, because Go normalises at the first assignment. The only visible trace is the gob encoding of a `Rat` nobody has assigned to, which Go writes with an empty denominator and this writes with a one. Both sides read both forms, so a value still crosses in either direction, and there is a test for reading Go's form.

Four more rows are in `docs/deviations.md` beside those. `bits` and `set_bits` copy, where Go documents them as raw access to the number's own array, and `Rat.num` and `Rat.denom` copy for the same reason, since a view of storage a value owns is the thing this library does not hand out anywhere. `Rat.float64` and `Rat.float32` report a number below the smallest subnormal as inexact, where Go reports `1/(1<<2000)` as an exact zero, because a zero does not represent that number and the flag exists to say whether the float is the rational. `Float.int` and `Float.rat` raise for an infinity where Go returns a nil, since an infinity is not an integer and not a rational number and there is nothing to hand back. And `Int.rand` takes anything implementing `core.math.rand.Source` rather than a pointer to a `Rand`, so its digits differ from Go's for the same seed, because Go builds each sixty four bit digit from two thirty two bit draws left over from its v1 generator and `core.math.rand` is v2, whose sources are already sixty four bits wide.

`core.math.rand`, all 59 of Go's symbols, no waivers. PCG and ChaCha8 as the two generators, `Rand` over either of them for everything derived from a uniform draw, `Zipf` for the fourth distribution, and the nineteen top level functions that need no generator at all.

This is `math/rand/v2`, named without the version because there is no version one here to tell it apart from. Go's original `math/rand` shares one locked generator between its top level functions, pays for a division to correct the bias in `Int31n`, and lets `Seed` make the whole program's randomness a global. None of that was worth carrying, and Go excluded it from this library on the same reasoning.

The top level functions are the reason the package declares `unsafe`, and only `globals.mojo` is. They need a generator that outlives the call, is not shared between threads, and is seeded by the operating system, and Mojo has nowhere to put one. So the C shim in `core/errors/shim/slot.c` grew a second slot beside the error record, the generator is allocated with `malloc` because a pthread key destructor is what frees it, and the seed comes from a raw `getentropy`. That is the whole of it, it is three functions long, and nothing a caller of `Rand`, `PCG`, `ChaCha8` or `Zipf` touches goes near any of it. The dependency it adds is on `core.errors`, which every package in the library already has.

Six things differ from Go and each has a row in `docs/deviations.md`. A `Rand` owns its `Source` and a `Zipf` owns its `Rand`, where Go holds pointers and lets the caller go on drawing from the same generator alongside, which is the mistake neither language can check for. `shuffle` takes its swap as a compile time parameter, so the exchange is inlined rather than called through a pointer, the choice `core.sort` already made. Every panic is a raise, which is a bound that is not positive, a zero to `uint64_n`, a negative count to `shuffle` or `perm`, and a `new_zipf` with parameters that describe no distribution, where Go hands back a nil pointer for the caller to find by dereferencing it. `n` raises on a `DType` that is not integral, because Go constrains its type parameter and section 10 of `docs/design.md` is why that check cannot be a compile error here; it is a `comptime if` and folds away for every integer type. `ChaCha8.read` has `io.Reader`'s signature exactly and declares nothing, because declaring the conformance would put `core.io` underneath this package and Go's own does not import `io` either.

The sixth is worth more than a line. `ChaCha8.UnmarshalBinary` in Go reads the `readbuf:` length byte and the block position straight out of the encoding and uses both without looking at them, so three shapes of untrusted input panic there with a slice bounds failure and a fourth restores a generator that silently skips forward in the stream. All four are refused here with `ErrInvalidEncoding`, and a refusal leaves the receiver alone. A marshalled generator is exactly the sort of thing that arrives from somewhere else, so the decoder is the wrong place to trust a length.

52 tests, ported from `pcg_test.go`, `chacha8_test.go`, `rand_test.go`, `regress_test.go`, `auto_test.go` and `race_test.go`. `TestRegress` is the most valuable of them and is three hundred and forty golden values, twenty from each of seventeen methods of a `Rand` on `new_pcg(1, 2)`, with a fresh generator per method. There is no reflection here, so the seventeen calls are written out in the order reflect walks them, which is alphabetical by Go's name, and each one reads the harvested list its return type went into at the offset its group starts at.

Go checks the `ChaCha8.Read` transcript by taking a sha256 of 2976 bytes and comparing it against a constant. There is no sha256 in this library yet and there did not need to be one for this: 2976 is 372 times 8, and the transcript is exactly the little endian expansion of `chacha8output`, which was confirmed against Go before it was relied on. So the read tests compare against the expansion, which pins the same bytes and also says which one is wrong when one is. The hash is harvested and waiting for `core.crypto.sha256`.

Harvesting those tables changed `tools/testgen`. Go's marshalled forms are byte strings rather than text, and a Mojo string literal is UTF-8, so a byte like `\xb6` in a Go table would arrive as the two bytes 194 and 182 and a sixteen byte golden would come out eighteen bytes long. Byte strings are now emitted as hex through a generated `_hex` helper with the Go spelling above them as a comment. The two harvests that already existed, `math` and `cmplx`, came back byte identical afterwards, so the change reaches only tables that contain bytes.

`Zipf` has no test in Go, in either version of the package, and has had none since it landed in 2011. Its goldens here were generated from go1.26.7 instead: three parameter sets of twenty values each, all from `new_pcg(3, 4)` so that the same uniform draws feed all three and a difference between them is the parameters and nothing else. On top of those is a shape test, a hundred thousand draws asked whether the first three values come out in the ratio one to a quarter to a ninth, because a golden list taken from the implementation's own ancestor cannot notice a plausible looking wrong distribution.

The concurrency test found something about the sanitiser rather than about the package, and it is written down in `tools/mojotest/run.py` where the next person writing a threaded test will read it. The Mojo runtime serves every `List` out of its own allocator, the thread sanitiser does not intercept that allocator, so it never learns that a block one thread freed is the same block another thread was later handed, and a file containing nothing but a `List` built inside a thread reports a data race. The threaded test therefore leaves out `perm`, which is the one top level function that allocates, and `perm` draws through the same per thread generator as everything else. Everything else in the package runs from eight threads at once with the sanitiser clean.

`core.math.cmplx`, all 27 of Go's symbols, no waivers. The elementary functions on complex numbers, on `std.complex.ComplexFloat64`, which is Mojo's own type, so a value from this package is a value the rest of the language already works with.

The manifest said this would be a wrap over `std.complex` and it is a port of all twenty seven. The type and the functions turned out to be different questions. `ComplexFloat64` is a good number type and carries the four operators, a conjugate and a norm, and none of the twenty seven, so there was nothing to wrap. Two of the three it does carry are not the ones Go uses either: `norm()` squares both parts and adds them, so it overflows at `(1e308, 1e308)` where the answer is 1.4e308 and underflows to zero at `(1e-320, 1e-320)` where the answer is 1.4e-320, and `abs` here is a hypotenuse and is right at both. Division is the naive formula and overflows the same way, which never comes up only because Go's `math/cmplx` never divides one complex number by another. The arithmetic is the type's, the functions are Go's.

The bodies are Cephes by way of Go and are short. The C99 Annex G special case switches in front of them are most of the source and all of the difficulty, because the answers there turn on the sign of a zero, on an infinity beside a not a number counting as an infinity rather than as a not a number, and on which side of a branch cut an argument arrived from. Go has one unreachable panic, in `Pow`, and it is reachable: `IsNaN` is false for a not a number sitting beside an infinity, so an exponent of `(nan, inf)` arrives with none of the three comparisons true. A not a number is the answer everywhere else a not a number exponent turns up and it is the answer there. `polar` returns Go's two values as a tuple that unpacks, the way `frexp` does.

The package depends on `core.math` and on `core.math.bits`, which puts it in tier 2. The dependency on `bits` is `tan` at a huge argument: reducing modulo pi in float64 has no correct digits left around 1e10, so the reduction runs in three hundred and twenty bits of an integer pi through `mul64`, `add64` and `leading_zeros64`, and Go's `tanHuge` table holds it to three parts in the last place afterwards.

Building this changed `core.math.hypot` from a wrap into a port, and the reason is one worth keeping. It was the system routine on the grounds that `sqrt(p*p + q*q)` has one right answer and nothing to disagree about, and the system routine is not required to give it. On macOS `hypot(-16.688001947990161, -24.14182405800559)` comes back as 29.348203997243527 where the correctly rounded answer is 29.348203997243523, and Go's two lines give the correctly rounded one. A part in the last place would not matter if `hypot` were only ever the length of something, but `sqrt` here divides by it and then subtracts two nearly equal numbers, and at `asinh(-5.010603618271075 + 9.636293707198417i)` that one bit arrives fifty bits wide, which is thirty times the tolerance Go holds the function to. Go's version is reproducible and the system's is whatever the platform ships, so this package now gives the same answer everywhere.

`core.math`, all 97 of Go's symbols, no waivers. Thirty constants and sixty seven functions, every one of them on float64, as Go's are.

The manifest said this would be a wrap over `std.math` and about half of it is a port. The reason is that Mojo's is a throughput first library and Go's tests are an accuracy contract. Measured against libm over Go's own inputs, `std.math.erf` is off by a hundred and seventy million parts in the last place, `pow` by ten million and `log` by two million, while the tolerances Go holds its `math` to are forty five parts and two. So `exp`, `exp2`, `log`, `log1p`, `pow`, `erf`, `erfc`, `cosh` and `gamma` are transcriptions of Go's, and Go's own test tables are what says they are close enough now. The functions that were already accurate enough are still one call each, because what is inside libm is FDLIBM and what Go wrote down is a transcription of the same code, so a third copy would add a place for a bug to live and take nothing away from either of the other two.

Accuracy was the easy half. The harder half is that a system library and Go disagree at the special values, and the special values are exactly what a caller reaches for `math` rather than for an arithmetic operator to get right. `std.math.sinh` is a not a number at negative infinity and `std.math.tanh` is one at a not a number, so both are ported whole. `std.math.j1` hands back a negative zero at negative infinity, correctly for an odd function and not what Go returns, so `j0`, `j1`, `y0` and `y1` keep the system library for the arithmetic and answer Go's special cases in front of it. `lgamma` in the system library is positive infinity at both infinities where Go's is the argument. And `gamma` had to be ported outright rather than patched at the edges, because `std.math.gamma(-170.5)` is out by four parts in fourteen digits, four times the tolerance Go allows that function and about two hundred places in the last bit, and -170.5 is not a special value at all, just an ordinary argument in the range where the reflection formula runs.

Nine more are here because there was nothing to call: `erfinv` and `erfcinv`, which are a rational approximation out of a statistics paper, `jn` and `yn`, which are Bessel recurrences, `ilogb`, `pow10`, `round`, `round_to_even` and the sign half of `lgamma`, which in C is a global variable that the call sets as a side effect and which Go turned into a second return value.

Two of the constants are written as bit patterns rather than as the decimals Go writes, because a float literal is flushed to zero on its way into a `Float32` or a `Float64` when it is subnormal, and the smallest nonzero float of a width is subnormal by definition. `MAX_FLOAT64` and `MAX_FLOAT32` are written out too, and not taken from `Float64.MAX`, which in Mojo is positive infinity rather than the largest finite value. The fifteen integer limits have the type their name says instead of being untyped as Go's are. All four of those have a row in `docs/deviations.md`.

The eleven irrational constants needed none of that, and finding out why corrected something this project had written down wrongly. A `comptime` expression in Mojo is evaluated at arbitrary precision and rounded once, exactly as a Go untyped constant is, so `LOG2E` could have been written as `1 / LN2` here just as Go writes it. Between two float64s the same division rounds twice, and for `LOG10E` that costs a bit in the last place. `tests/math/test_const.mojo` asserts both spellings so the fact stays pinned. It matters beyond the constants: Go's large angle trig tests add `100000 * Pi` to every input, and writing that as a product of two float64 values lands an ulp low, which is 6e-11 there and enough to move the fourth digit of the sine.

`core.math.bits`, all 50 of Go's symbols, no waivers. Bit counting and the wide arithmetic that a multiple precision integer is built out of.

This is the shortest package in the library and the reason is worth writing down. Go implements every one of these by hand, out of generated byte tables, de Bruijn constants and Knuth's algorithm D, and it does that because the Go compiler recognises some of these functions on some architectures and the written version is what the rest fall back to. Mojo has `std.bit` for the counting and the reversing and `UInt128` for the arithmetic, so the twenty counting functions and the ten reversing functions are one call each, and the wide sum, difference, product and quotient are the ordinary operation done one width up and split in half. That is not a shortcut past Go's work, it is Go's work already done by the compiler. The tests take Go's own tables to say the answers are the same, including the byte table Go builds by shifting one bit at a time, which is exactly the independent implementation you want on the other side of a comparison.

The five rotations are the exception and are written out, because `std.bit.rotate_bits_left` wants the distance at compile time and Go's takes it at run time. Both shifts are masked, not just the first, since a shift by the full width is undefined below Mojo and a rotation by zero would otherwise land on it.

The six functions that can fail raise rather than panic. Go's zero divisor and its too wide quotient both come out as the runtime's own `integer divide by zero` and `integer overflow`, which read as though the hardware trapped when in fact the package checked. Here they are `ErrDivideByZero` and `ErrOverflow`, two new codes. A package in tier 1 is not the one that gets to end the process.

`core.strconv`, all 43 of Go's symbols, no waivers. Numbers to text and back, and Go's quoted string syntax. The two places Go panics, a bad bit size in `FormatFloat` and in `FormatComplex`, raise here.

`core.strings`, 82 of Go's 82 symbols with one waived. The waiver is `Title`, the same one `core.bytes` took, deprecated in Go itself because the word boundary rule turns "they're" into "They'Re". `to_title` is here and is the rune wise mapping, which was never the broken part.

The whole package is built on one decision: nothing here reimplements a search. Every function that looks for something calls `core.bytes` over the string's own bytes and turns the byte offset it gets back into a slice. Go has two packages with the same twenty functions in them because `[]byte(s)` copies the string, so calling one from the other would cost an allocation per call. A Mojo `String` already holds UTF-8 and `as_bytes()` lends those bytes without copying, so the reason for the second copy of the code is gone. `index`, `split`, `trim`, `fields` and the rest are thin, and the Rabin-Karp and the cutset bitmap that they run on live in one place and are tested in one place.

Turning a byte offset back into a string is where the safety comes from. `s[byte=a:b]` aborts if either bound is not a code point boundary, so every slice this package hands out is one that a search found, and a bug in an offset is a stopped program rather than a `String` holding half a rune. That is a language guarantee this library did not have to build.

There is no `len`. `count_bytes`, `count_runes` and `count_graphemes` are three names for the three answers, and which one a caller wants is a question that has a different answer for every one of them: "a👩‍👩‍👧‍👦é" is 28 bytes, 9 runes and 3 graphemes. Mojo makes `len(s)` a compile error and it is right to.

Every signature binds its origin as `ImmOrigin` rather than as a plain `Origin`. That is not a detail. Two spans over the same mutable origin cannot be passed as two arguments of one call, so with the plain bound `trim(s, s)` and `has_prefix(s, s)` would not compile, and a caller would meet the exclusivity checker while doing something obviously harmless. Declaring the bound immutable removes the restriction, and nothing in the package writes through a span anyway.

`Builder` is not copyable, so the mistake Go catches with a runtime panic does not compile here. `string()` raises when what was written is not valid UTF-8 and `bytes()` is the accessor that never refuses, the same split `bufio.Scanner` uses. `reset()` keeps the allocation, unlike Go's, which drops it, because the builder is not copyable and hands out nothing that views its storage, so there is no way to read the old bytes and no reason to give them back. What it costs is that `string()` copies: Go's reinterprets the accumulated bytes in place through `unsafe`, and here the `String` has to own what it holds.

`Replacer` is one trie rather than Go's four implementations. Go picks between a single byte table, a byte to string table, a single string search and a generic trie by inspecting the pairs, which is four bodies of code to keep in agreement about a subtle rule: replacements happen in the order they appear in the target, matches do not overlap, and at the same position the pair that came first in the argument list wins, which is priority and not longest match. One trie answers all of that once. The nodes are `Int` indices into a list rather than pointers, since a recursive struct cannot be written. Two visible differences from Go: the constructor takes a list of pairs, so the odd argument count Go panics on cannot be written down, and the trie is built by the constructor rather than on first use behind a `sync.Once`, because `replace` takes `self` by borrow and there is no interior mutability to build through. `write_string` builds the whole result and writes it once instead of streaming each piece, so a writer that fails sees one call rather than a half written result.

`Reader` carries its origin in the type, so `reset` takes a slice from the same string the reader was built over, exactly as `bytes.Reader` and `bufio.Reader` do. All eleven of Go's methods are there.

78 tests, ported from `strings_test.go`, `builder_test.go`, `replace_test.go` and `reader_test.go`. The tables that Go writes with invisible characters in them are built with `chr(0x85)`, `chr(0xA0)`, `chr(0x3000)` and `chr(0x200B)` instead of pasted literals, which keeps a source file that no editor and no tool can silently rewrite. `test_trimming_the_same_string_twice` exists only to prove the `ImmOrigin` bound does what the paragraph above says.

Adding `core.bytes` to this package's dependencies moved it from tier 2 to tier 3, and the lint computes a package's tier from the graph rather than trusting what it records, so 49 other manifests move up by one behind it. None of them changed in any other way.

## v0.3.0 - 2026-09-03

M2 is complete. Reading and writing, buffering, ordering, and the two packages that everything textual is built on. Eight pull requests, seven issues, and the parity count goes from 6.7 percent to 7.8 percent, which is 691 of Go's symbols across eleven packages.

The thread that runs through all of it is that Go's interfaces are checked at run time and these are not. `io.copy` in Go type asserts its argument to `io.WriterTo` and then to `io.ReaderFrom`, and a caller cannot find out ahead of time which path it will take. Here every reader and writer answers `capabilities()` with a set of bits, the fast paths are selected from those bits, and a caller can ask the same question the library asks. The erased forms exist for when the type genuinely is not known until run time, and they carry the same bits, so nothing has to be discovered by trying.

The other thread is that a `for` loop in Mojo swallows an error raised out of `__next__`, which was found with a probe before anything depended on it. That one language fact is why `core.iter.Cursor` exists and why fallible iteration in this library is written as an explicit `has_next` and `next` pair rather than as a loop. The lint enforces it.

`core.bytes`, 97 of Go's 99 symbols with two waived and one renamed. That closes M2. The waivers are `Title`, which Go's own documentation deprecates because its word boundary rule turns "they're" into "They'Re", and `Buffer.AvailableBuffer`, which hands out the buffer's spare capacity to be appended into and has nowhere to land here. The rename is `MinRead` to `MIN_READ`, on the constants rule the rest of the library already follows.

The rule the package is built around is one sentence: **a method never hands out a view into the buffer's own storage.** Go documents `Buffer.Bytes`, `Next` and `Peek` as valid only until the next write, and a Go program that breaks that rule reads stale bytes out of a live allocation. Here the next write can reallocate, so the same mistake reads freed memory, and `probes/span_outlives_its_owner.mojo` pins that the compiler does not stop it. So all three return owned bytes and there is no view returning accessor beside them under any name. The copy is real and `Buffer` is a hot type, so there are four ways not to pay for it, and the docstring leads with them: `len()`, `write_to`, `read` into a span the caller already owns, and `string()`, which builds the `String` directly rather than through a `List[Byte]` first. The functions that carve a slice up, `trim` and `cut` and `split` and `fields`, do return spans, exactly as Go returns subslices: those borrow the caller's bytes rather than the package's own.

Everything Go panics about raises instead. There are four: `Repeat` on a negative count or an overflowing length, `Join` on an overflowing length, `Buffer.Grow` on a negative one, and `Buffer.Truncate` past what is buffered. Each is a check the caller could have made. Running out of memory raises `ErrTooLarge` rather than panicking with it, because a buffer that cannot grow is a condition only the caller can report on, since they are the one who knows whether the input that caused it was theirs.

Two more places answer differently and both follow the rule the rest of this library uses: bytes now, the reason next call. `peek` short of what was asked returns what there is and does not raise, and only raises `EOF` when the buffer is empty and the count is positive; `read_bytes` and `read_string` with no delimiter left return everything remaining and let the end arrive on the following call. Go returns the bytes and `io.EOF` together in both cases, which puts the answer in the value and the reason in the error at the same time and is the shape that produces callers who check the error first and drop the data. `deviations.md` has the row.

`Reader` carries its origin in the type, and that costs one thing: `reset` takes a span from the same place the reader was built over, because `Reader[o]` cannot be re-pointed at a different `o` without becoming a different type. Pointing a reader at another part of the same buffer works, which is what `Reset` is mostly for; pointing it at a different buffer means `new_reader`, which is two words and no allocation. Same shape as `bufio.Reader.Reset`, and the row is next to it.

`search.mojo` is the answer to the second half of issue #15. All fourteen functions are written against `Span[Byte, o]` and none of them allocates, so `core.strings` will call these rather than having its own copy: a Mojo `String` already holds UTF-8 and lends its bytes through `as_bytes()` without copying. Go has two of everything precisely because `[]byte(s)` copies. `index` is Rabin-Karp over a rolling hash, which is Go's fallback rather than its amd64 assembly, neither of which is available here, with the naive loop below the crossover Go puts it at and the same FNV prime as Go so that a divergence in behaviour cannot be a divergence in the hash.

121 tests, ported from `bytes_test.go`, `buffer_test.go` and `reader_test.go`. The thing that made them portable is four functions in `tests/bytes/_fixtures.mojo`. Go's tables are full of byte string literals like `"a\xffb"` that a Mojo `String` cannot hold, so `enc` reads that notation into bytes, `quote` prints bytes back into it, `joined` joins pieces with a bar, and `expect` runs a table's `want` column through both so the two sides meet. Converting the expectation rather than the result is the direction that keeps the tables readable, because printable ASCII and the bar survive the round trip unchanged, so a row about characters still reads as characters and a row about bytes still reads as `\xNN`. A failure prints `a\xffb` instead of a column of numbers.

Two of those tests are worth naming. `test_the_dead_prefix_is_reclaimed` is Go's issue 5154: a buffer read from and written to forever must reuse the space in front of the read cursor rather than growing without bound, and nothing else in the file would catch it. And `test_fields_splits_on_the_space_table_and_not_the_ascii_six` is where a wrong assumption of mine got caught by the library rather than the other way round: `unicode.IsSpace` includes U+0085 NEL and U+00A0 NBSP, which most people would not guess, and does not include U+200B ZERO WIDTH SPACE, which most people would.

`core.unicode`, all 309 symbols, no waivers: 247 range tables, six maps, the case and fold arithmetic, the thirteen predicates and the Turkish and Azerbaijani special cases. It is scheduled for M3 and lands early for the same reason `utf8` did — `core.bytes` and `core.strings` are next and both want case mapping — and the manifest says `Adapt` because the tables cannot be a Go `map` here and one of Go's types cannot be constructed at all.

Everything is generated by `tools/gen/unicode.py` from five files of the Unicode character database, vendored under `tests/data/ucd` at edition 15.0.0 and pinned by sha256 with `Unicode-3.0` recorded against each. The generated source is checked in, so a build never reaches the network, and `pixi run generated-check` reruns the generator and fails on a diff. The generator emits code the formatter would not change, which took two rounds to get right: `mojo format` wraps at 80 columns and leaves docstrings alone, so an 82 character map entry and a missing blank line between two functions were enough to make `format` and `generated-check` disagree about the same file, each of them correct.

`data.mojo` is nine thousand lines and five arrays, and the shape of it is the reason the package is fast. A range is packed into one 64-bit word as `lo | hi << 21 | stride << 42`, because a code point needs 21 bits and three of them fit in a word with room over, and every table is laid out end to end in one array rather than one array each. What that buys is that a `RangeTable` is four integers naming a slice — no pointer, no origin, no lifetime — so it can be a `comptime` constant, `unicode.Greek` costs nothing to pass, and reading a range is `materialize[_RANGES]()[i]`, a load from read only memory rather than a copy of the array. `docs/design.md` section 6 has the measurement that makes that true, and if it stops being true this package gets slow rather than wrong.

The price is the first deviation and it is a real loss: a caller cannot build a `RangeTable`, because there is nowhere to put the ranges. Go's `rangetable.New` has no equivalent here. `is_one_of` over a `List[RangeTable]` of the tables that do exist covers most of what people build one for, and the rest is a predicate the caller writes. The second deviation is that Go's six maps — `Categories`, `Scripts`, `Properties`, `FoldCategory`, `FoldScript`, `CategoryAliases` — are functions returning a fresh `Dict`, since a `Dict` cannot be a compile time value, and so are `GraphicRanges`, `PrintRanges` and `CaseRanges` for the same reason about `List`. Calling `Categories()` in a loop builds a 38 entry dictionary every time round; reaching for `unicode.Lu` instead is free, and that is the advice the module docstring leads with. `docs/deviations.md` has all four rows, the fourth being `CaseRange.Delta`, which is a four lane `SIMD[DType.int32, 4]` because Mojo's fixed size array is not implicitly copyable and its vector type only comes in powers of two. The fourth lane is always zero and nothing reads it.

`Is` is `is_in` and `In` is `in_any`, because both of Go's names are Mojo keywords. Those two are the questions the package exists to answer, so they had to keep reading as questions rather than becoming `is_` and `in_`. The ten constants are capitals — `MAX_RUNE`, `UPPER_CASE`, `REPLACEMENT_CHAR` — on the same rule that gave `io` its seek constants, and `tools/parity/renames.toml` carries all twelve renames with the reasoning.

The check that the tables are Go's is exhaustive rather than sampled, which is what #19 asked for. Two new differ areas do it. `unicode-tables` dumps all 245 tables the five maps name, range by range, the 328 case ranges and the 42 category aliases, and the 7,571 lines are byte identical to the same dump out of Go. `unicode-runes` prints one line per code point holding a thirteen bit predicate mask and five mappings, and all 1,114,112 of them are byte identical too. Together that is 1,121,683 compared inputs in about eighteen seconds. Both drivers accept `--seed` and ignore it: there is nothing random about a character database, and always starting at zero is what makes the differ's case index the code point that diverged, so a failure names itself. The nightly passes the run number as a seed, and without that rule it would have started the sweep at an arbitrary code point and skipped everything below it.

`tools/differ` grew the harness to go with them. Areas are declared in `tools/differ/cases.toml` with the command for each side, what it needs on `PATH`, and how many cases it wants, and `differential.yml` now derives its matrix from that file rather than from a list in the workflow. The list that was there named eight areas that do not exist and passed flags the tool does not have, so the first nightly after this would have failed on all eight; an area now reaches the nightly by being declared, and the areas `docs/testing.md` describes and nobody has written are simply absent, which is the difference between a plan and a job that fails every night. Eighty tests, ported from Go's `letter_test.go`, `graphic_test.go`, `digit_test.go` and `script_test.go` with the fixtures transcribed from Go's sources rather than from memory — those code points were chosen by somebody reading the Unicode files, one per interesting block and one either side of every boundary, so a table derived from this implementation would agree with it by construction and prove nothing. Go's category and property tests carry one line that is easy to miss and worth more than the rest of the file: after every fixture row has been checked, every category the fixture did not mention is a failure. That assertion is here too, so a table cannot arrive untested. The other two that earn their place are `TestLetterOptimizations`, which asks the 256 byte Latin-1 table and the range tables the same questions and is the only thing that would catch one bit set wrong in the byte table, and `TestNegativeRune`, which exists because those shortcuts narrow a rune to a byte and a negative rune narrowed to a byte looks like a perfectly ordinary letter.

Go's quirks are reproduced rather than fixed, and the tests say so by name. `FoldCategory` has no `LC` key even though `LC` is a category with fold exceptions, because Go's generator only walks the categories that appear in the file it reads; `test_fold_category_has_no_cased_letter` asserts the absence so that nobody quietly corrects it. `to(-1, r)` answers `REPLACEMENT_CHAR` rather than failing, which is one of the few places in either library where a programming mistake produces a code point. And the case mappings are simple mappings only: ß upper cases to ß and not to `SS`, the Turkish tables are four code points rather than a language, and full case mapping is a string operation that belongs to `core.strings`.

`simple_fold` is the function in here worth reading the docstring of. It is not a fold — it walks the cycle of code points equal to its argument under case folding, so calling it repeatedly enumerates an equivalence class. `K`, `k` and U+212A KELVIN SIGN are one such class and `S`, `s` and U+017F LONG S are another, and the case mappings only go one way through each: U+212A lower cases to `k` and nothing upper cases to U+212A, while U+017F upper cases to `S` and nothing lower cases to U+017F. A program comparing case insensitively by mapping both sides has to map towards lower case to get Kelvin right and towards upper case to get long s right, and no single direction gets both. That is the whole reason the function exists, and there is a test that says it in five lines.

`core.maps`, all ten symbols, no waivers. The manifest says `Adapt`, because two of Go's five shapes do not survive the crossing and the docstrings argue for both rather than presenting them as translations.

The three producers return a `List` where Go returns an `iter.Seq`. A `Dict` already has `keys()`, `values()` and `items()`, they borrow rather than copy, and a `keys` here that handed one back would be a second name for something that exists. What does not exist is the thing a Go programmer writes `slices.Collect(maps.Keys(m))` for, so that is what these three are, each with an `_into` sibling that appends to a list the caller already owns. That is thirteen functions for ten symbols and it is the cheaper half of the deviation.

The order is the `Dict`'s and nothing here promises what that is, with one exception that is worth having and costs nothing: with no mutation in between, `keys`, `values` and `all` walk the dict the same way, so `keys(d)[i]` and `values(d)[i]` are one entry. Go promises the opposite on purpose — each of its iterators randomises separately — and the effect there is that anyone wanting parallel lists has to go through `All` and unpack. `test_keys_and_values_line_up` is the test that makes it a guarantee rather than an accident.

The two consumers take a `Span[Tuple[K, V], o]` rather than the `core.iter.Cursor` that `slices.collect` takes, and that one is forced. A cursor's element type is an associated `comptime Element`, and there is no way to say "and that element is a `Tuple[K, V]`" that the compiler will take apart again: `where C.Element == Tuple[K, V]` parses, is checked at the call site, and leaves `C.Element` opaque in the body, so `pair[0]` on it is still an error. `probes/pair_cursor.mojo` pins that and `design.md` records it next to the weaker form `slices.sorted` ran into. A fallible source is therefore drained with `slices.collect` first and the list handed over, which costs a line and a copy of the pairs; two tests do exactly that against a fixture cursor that fails partway, because a documented workaround nobody compiled is a guess.

`delete_func` gathers the keys to delete before deleting any of them, so the predicate sees every entry exactly once. Go deletes as it iterates, which its map specification allows and which nothing here promises about a `Dict`; the cost is one list of keys and the gain is that the rule is about this function rather than about the implementation underneath it. `equal` compares values with `==` and so says a dict holding a NaN is not equal to itself, which is `core.cmp.compare`'s total order deliberately not applying outside sorting, and there is a test named after it.

Every bound is spelled `K: KeyElement & Copyable & Deinitable`. `KeyElement` is `Movable & Hashable & Equatable` and implies neither of the other two, so the first version of this package compiled until it tried to copy a key and then said it lacked evidence to prove the copy correct. Forty-three tests, sorting both sides of every comparison through one shared helper rather than repeating the sort, because a test that sorts one side and forgets the other passes for the wrong reason.

Four packages now have a `tests/<pkg>/_fixtures.mojo` and two of them imported it as a bare `from _fixtures import`. The suite is one generated main built with `-I` at the root, so the fourth one made the name ambiguous and the build failed inside `tests/slices`, which had not changed. All of them are now spelled `from tests.<pkg>._fixtures import`, which is what the other two already did.

`core.cmp`, `core.sort` and `core.slices`, eighty-four symbols across the three, no waivers anywhere in them. They landed together because they are one stack: `cmp` is the ordering, `sort` is the algorithm over it, `slices` is the collection of loops people actually call. Splitting the work would have meant writing `slices.sort` twice.

`core.cmp` is four symbols and one of them is a decision. `Ordered` is a `comptime` alias for `Comparable` rather than a new trait, because Go writes `cmp.Ordered` as a type set only for want of a way to say "supports `<`", and Mojo has one. Inventing a trait here would have produced a worse `Comparable` that `Int` did not conform to. The name survives so that a bound written `T: Ordered` reads the same in both languages.

The NaN rules in `compare` are Go's and they are deliberately not IEEE's: a NaN sorts before every number and two NaNs are equal. IEEE makes `a < b`, `a > b` and `a == b` all false for the same pair, and a partition loop given that answer three times has no invariant left and walks off the end of the array. That is not a hypothetical — it is the same failure the next paragraph is about. The cost is that `compare` and `==` disagree about NaN on purpose, so `slices.equal` and `slices.compare` give different answers on the same two spans, and there is a test named after the disagreement rather than a comment apologising for it.

`core.sort` is a port of Go's pdqsort and SymMerge rather than a wrapper around `std.builtin.sort`, and the manifest says `Port` where it used to say `Wrap`. The reason is memory safety, not fidelity. Handed an inconsistent comparator, the standard library's sort passes that comparator elements from outside the span it was given: McIlroy's antiquicksort adversary extracts 645 such comparisons from a 1,000 element range, and an index outside the data is a dead process. Go's sort does not do this at any size, stable or unstable. A caller who gets the ordering wrong deserves a wrong order, and that guarantee is most of the reason to want Go's sort in the first place. `tests/sort/test_adversary.mojo` runs the adversary at 1,000 and at 10,000, and the stable sort is run through it too, because "that one has nothing to attack" is a claim and not a fact.

A comparator here is a compile time parameter, and `tools/probe/probes/comparator_capture_list.mojo` pins the one subtlety that makes the whole approach work. The parameter has to be declared `capturing [_]`. Spelled `capturing thin`, which is how `std.builtin.sort` prints its own signature, it compiles, drops the capture silently, and sorts by whatever the closure would have read had it been able to read anything — and with a capture owning heap memory the same shape aborts instead. No error and no warning at that spelling. The probe is the working half, forwarded through one wrapper and through two, which is exactly what `core.slices` calling `core.sort` is. The broken half is not written down, because a dropped capture is undefined behaviour and a probe should not be.

`Reverse` holds a pointer at the data rather than a value, because a `Reverse` holding a `T` would sort a copy and hand the caller back an unchanged slice with nothing to report. `StringSlice.swap` goes through a temporary and two copies, because borrowing both elements of one span mutably is refused; sorting an index list with `slice` is the way out when the strings are long enough for that to matter. Sixty-two tests, including Bentley and McIlroy's grid of distributions and both adversaries.

`core.slices` is forty symbols over four files, and the split is by what the function does to the length rather than by Go's file layout. `find.mojo` and `order.mojo` take a span and leave it the length it was. `edit.mojo` is everything that changes the length, and every function in it takes `mut s: List[T]` and returns nothing. Go returns the new slice because a slice header is a value and returning one is how a length change gets published; here the length lives in the list the caller already owns, and handing back a second `List` over the same buffer is the thing ownership exists to prevent. `insert` rotates the appended block into place with three reversals rather than shifting, `clip` gives the spare allocation back rather than capping a capacity that a span does not have, and `concat` is variadic over `List[T]` rather than over spans because a Mojo variadic binds one origin parameter for every argument and cannot take spans into two different lists.

`seq.mojo` is where Go's symmetry breaks. Go's producers return an `iter.Seq` and its consumers take one, so the two halves meet in the middle. Here the four producers return ordinary Mojo iterators and a `for` loop over one is correct, while the five consumers take a `core.iter.Cursor` and are written as a `while`. Walking a span cannot fail, and `core/iter/cursor.mojo` says outright that a list iterator is not a `Cursor` and should not be made into one. But csv records, sql rows and directory walks can all fail, and a `collect` that only accepted infallible iterators would be a `collect` with nothing to collect from. The producer tests are written as `for` loops on purpose: if one of them stops compiling, the producers have quietly become fallible and the rule needs looking at again.

`append_seq` takes the cursor first and the destination second, which is backwards from Go and from every other length-changing function in the package. That is not taste. `C` is inferred from the cursor and the destination is a `List[C.Element]`, so with the destination first the compiler reaches it before `C` is resolved and refuses the call. The three `sorted` functions have a related scar: `where conforms_to(C.Element, Ordered)` does narrow the associated type where the type stands alone, and does not let `T` be inferred through a `Span[C.Element, o]`, so they go through two private helpers whose `T` is explicit. `probes/refined_associated_type.mojo` has the reduced case and design.md records it, so when the compiler learns to infer through the refinement the probe starts compiling and the helpers go away.

`min_func` and `max_func` both return the first of a tie. That is Go's documented rule for both, it was implemented here as first and last before anyone checked, and the obvious wrong `max_func` — `>=` where it should be `>` — passes every test that does not have three records comparing equal on the key and differing in the payload. There is now such a test. One hundred and twenty tests over the package, with a `Tracked` element type that counts live objects rather than destructor calls, because counting destructors made the assertions depend on how many copies `compact` happened to make.

The linter's iteration rule is narrower by one case. It rejected any `__next__` that raises, which is design.md section 7 made mechanical, and Mojo 1.0's `Iterator` trait requires the signature `def __next__(mut self) raises StopIteration`. That raise is not an error being swallowed — it is how the language spells end of input and the loop catching it is the loop working — so `StopIteration` alone is now exempt, and the check reads what follows `raises` rather than stopping at the word. A bare `raises` is still rejected and so is `raises Error` or any other named type, which is the shape a lazier exemption would have waved through: a check that stopped at the word `raises` and accepted anything typed after it would let a read failure arrive by the route the loop uses to learn that the data ended. `tests/lint/typed_fallible_next.mojo` is the third fixture and it keeps that half of the rule provably alive.

`core.unicode.utf8`, all nineteen symbols, no waivers. It is scheduled for M3 with the rest of Unicode and it landed in M2 instead, because `core.bufio` needed a decoder and `core.bytes` and `core.strings` need one next, and the milestone order had them all depending on something that did not exist. Splitting it was cheap: the nineteen symbols are arithmetic, and the tables, the character classes and the case mapping that make `unicode` a week of generated code are still in #19. Issue #115 has the reasoning and #19 lost these from its scope.

The package works on `Span[UInt8]` rather than on `String`, and that is the point rather than an implementation detail. A `String` here is already valid UTF-8, so a decoder over one has nothing to decide; the input worth having a decoder for is bytes off a socket. The four `...InString` functions are kept anyway, one line each, because Go has them for a reason that does not apply — `[]byte(s)` copies and `String.as_bytes` borrows — and a Go programmer should still find the name they went looking for.

Invalid input decodes to `RUNE_ERROR` with a size of exactly one, never zero and never the width of the malformed sequence. That is Go's rule and it is not the obvious one: a decoder meeting a byte it dislikes could reasonably skip the whole sequence and resynchronise. Advancing one byte is what makes a decode loop terminate, what makes `rune_count` agree with the loop a caller writes, and what leaves resynchronisation to the caller, who is the only one who knows whether the right answer is to show the damage or reject the message.

The corollary is the trap in the package. `RUNE_ERROR` is an ordinary code point that valid input may contain, so `valid` is written against the size rather than the value — `EF BF BD` is three bytes of perfectly good text, and a check on the value would have this library calling its own error output malformed. `rune_len` is the other one: it answers -1 for a value that is not a code point where `encode_rune` substitutes and writes three bytes, so sizing a buffer from it is a bug that only shows up on input somebody else chose. `bufio`'s private predecessor made those two agree by returning 3, which was the wrong fix — it made the question unanswerable. There is a test named after the disagreement.

`AppendRune` is the one signature that changed. Go returns the grown slice because that is what `append` does; `append_rune` takes `mut dst` and returns the byte count, since two names for the same list is what ownership forbids. `deviations.md` has the row.

Forty tests. The tables are Go's `utf8map`, `surrogateMap` and the invalid sequence list, transcribed by hand as byte lists rather than string literals — half of those sequences cannot be held in a Mojo `String` at all, which is itself the reason the package takes spans. Two of them are exhaustive rather than sampled: every code point from zero to `MAX_RUNE` round trips through `encode_rune` and `decode_rune` with `rune_len` checked in the same loop, and all 256 single bytes are decoded against the stated rule with `full_rune` checked alongside so the two answers cannot drift.

Forty two mutations, one per claim, forty one caught on the first pass. The survivor was the landing check in `decode_last_rune`, and the reason it survived is worth more than the fix. Every truncated input in the table answers `(RUNE_ERROR, 1)` because the forward decode from the recovered start byte fails on its own; the check that the decode landed exactly on the end never decides anything for them. It decides for `41 C2 80 80` — an `A`, a complete two byte rune, and one loose continuation byte — where the backwards scan finds the `C2`, decodes a real rune from it, and is still wrong. That input is now a test, and the table test's docstring says which half of the work it is doing.

`core/bufio/_rune.mojo` is deleted. Its first line promised that it would go when `core.unicode.utf8` arrived and that the replacement would be an import change and a deletion, and that is what it was: three imports repointed, `_rune_len` dropped because nothing ever called it, and 124 `bufio` tests passing unchanged. `core.bufio` gains the dependency and the `PACKAGE.toml` comment explaining the absence is gone.

`core.bufio`, all of it: the buffered reader, the buffered writer, the scanner, the four split functions and the pair of halves Go calls `ReadWriter`. `pixi run parity core.bufio` reports nothing missing, with six waivers each carrying a reason about Go rather than about effort. It landed at tier 2 rather than the tier 3 the graph had planned for it, because it turned out to need `core.bytes` for nothing that a loop over a span does not do, and `core.unicode.utf8` is tier 0, so neither dependency costs a tier. Four packages downstream moved with it.

The decision that shaped every file is that nothing here returns a view into a buffer. Go's `Peek`, `ReadSlice`, `ReadLine` and `Scanner.Bytes` all hand back a slice of the reader's own memory and document that the next call invalidates it, and design.md used to claim that origins turn that documented hazard into a compile error here. That claim was wrong and it had no probe, which is why every claim in that file has one now. A `Span` built over a `List` stays usable across a mutation of that list, including one that reallocates and leaves it pointing at freed memory, and nothing in the compiler notices; `probes/span_outlives_its_owner.mojo` pins it. So all four return owned bytes, the copy is on `deviations.md` as a cost rather than a win, and that page's better column is one row shorter than it was.

`Scanner` is a `core.iter.Cursor`, which is what `Cursor` was written for: it names `bufio.Scanner` as the thing it exists to prevent. `for s.Scan() {}` ends early and silently on a read failure and the check that would have caught it is `s.Err()`, somewhere after the loop, easy to forget and impossible for a reader of the code to notice is missing. Here a clean end of input is `False` out of `has_next` and everything else is a raise, so there is no `Err` and nothing to forget. The deviations page has the row and the module docstring has the loop written out, deliberately as a `while` rather than a `for`.

The split function is a trait rather than a function pointer, and it is the first use of a shape the rest of the library will lean on, so design.md section 3 gained a paragraph about it. Go's `SplitFunc` takes a `[]byte`, and a function type here has to name concrete types in every position, origins included, so the argument has no spelling that does not launder an origin through `core.runtime.box` — in a package that otherwise needs nothing unsafe. A trait method may be parametric over the origin exactly as `io.Reader.read` is, so the hole does not exist, and the receiver is where a closure's captures go. `mut self` makes a stateful splitter ordinary rather than clever. The consequence is that the splitter is a type parameter fixed when the scanner is built, so Go's `Split` setter and the panic it carries for being called after the first `Scan` are both gone rather than reimplemented.

A token is a start and a stop into the data the splitter was given rather than a subslice, for the same reason `peek` returns a copy. That moves a bounds check from the compiler to us and buys a check Go cannot make: a split function whose range is outside the window is caught rather than handing out neighbouring bytes. `Split` also carries `final` where Go has `ErrFinalToken`, which is Go's one place where an error is not a failure; the error channel here only ever carries failures.

`read_string` and `Scanner.text` raise on input that is not valid UTF-8, and that is the one place this package is deliberately stricter than Go rather than merely different. A Go string is bytes that are usually text, so `ReadString` hands back whatever it read; a Mojo `String` says it is UTF-8. The alternatives were to substitute U+FFFD, which loses bytes silently, or to assert the encoding without checking, which is the `unsafe_` constructor and would have made this package unsafe on behalf of a caller who never asked. `read_bytes` and `Scanner.bytes` are the versions that never refuse, and a protocol carrying both text and binary wants them anyway.

`ReadWriter` is two named fields and twenty forwarders rather than Go's two embedded pointers, and it comes out ahead. Go's version has two `Buffered` methods, two `Size` methods and two `Reset` methods, and promotion resolves none of them: `rw.Buffered` does not compile and a Go caller writes `rw.Reader.Buffered()` anyway, one mistake later. The three ambiguous names are simply not forwarded here and the fields are public, so that spelling is what everybody writes from the start. Everything with one honest meaning is forwarded.

Two things about Go's scanner had to be checked against Go's own loop rather than assumed, and both were assumed wrong first. Once the input has ended, a decision carrying no token ends the scan even if bytes are left — a stateful splitter that skips on alternate calls loses its last token, and that is Go's rule, not a bug in the scanner. And the token ceiling counts the delimiter: a sixteen byte line needs a seventeen byte buffer, because the delimiter is held before the splitter drops it. Both are now named tests rather than quiet fixes.

The tests are four files over six shared fixtures, and the fixtures are where the value is. A buffered reader is a loop around a source that does not cooperate, so `Half`, `OneByte` and a reader that fails after handing over its bytes are what the whole suite is run through, alongside a sink that accepts half of every write and one that fails after a fixed number of bytes. Nine hand written splitters go with them, five misbehaving on purpose: one that goes backwards, one that goes past the end, one whose token range is outside the data it was given, one that never advances, one that raises.

Twenty seven mutations, one per claim. Twenty three were caught on the first pass and four were not, which is the reason for doing it rather than a footnote to it. Refusing a `peek` larger than the buffer can ever hold was checked for the error but not for the fact that it is refused before the source is touched. The straight-through read path was tested with a span more than twice the buffer, so a version that took it half as often passed. A cut line ending in a carriage return was tested only where the newline did arrive, where dropping the return and putting it back are indistinguishable. And both `ScanWords` inputs ended in whitespace, so the branch that produces the last word because the input ended was never reached. Four tests later all twenty seven are caught.

`_rune.mojo` was a private decoder written because `core.unicode.utf8` was scheduled for M3 and `read_rune`, `write_rune` and `ScanRunes` cannot be written without one. It is gone, deleted by #115 above, which is what its first line promised. `ScanRunes` deviated while it was here and keeps deviating after, for a reason that has nothing to do with the decoder: Go substitutes the encoding of U+FFFD for a byte that is not valid UTF-8, and a token that is a range of the input has nowhere for bytes that are not in the input to come from, so the offending byte is the token. One per byte, same advance, so the token stream still lines up with Go's.

The rest of `core.io`. Nineteen more traits, seven functions and five types, which is Go's `io` complete apart from the pipe, and `pixi run parity core.io` now reports every symbol present or waived with a reason.

The small traits are one required method each and none of them needed a decision, with one exception. `ReaderFrom` and `WriterTo` already existed as methods on `Writer` and `Reader` with capability bits behind them, so declaring them again as traits looked like two mechanisms for one thing. It is not, and the reason is that a single method satisfies both: a struct that lists `Writer, ReaderFrom` and writes `read_from` once conforms to both, which was checked before any of this was written. Which name to use is a question about what a function needs rather than about what a type is. A function that only makes sense over a writer with a fast path takes `[W: ReaderFrom]` and gets a compile error otherwise; `copy` cannot, because it takes any writer and finds out at run time, and that is what the bit is for. The bit stays the only thing `copy` reads.

`read_full` and `read_at_least` are the two functions that justify the two new sentinels. A truncated stream raises `ErrUnexpectedEOF` and an empty one raises `EOF`, and the distinction is the entire reason those are separate numbers: a decoder reading records in a loop wants to stop cleanly at a record boundary and complain loudly anywhere else, and only this layer can tell it which happened. `ErrShortBuffer` is raised before anything is read, because a buffer smaller than the minimum asked for is a caller mistake that no amount of input would fix.

Both loop, and a version of either written as one `read` passes every test over a reader that fills the span it is given. So they are tested through a half reader as well, which is Go's `iotest.HalfReader` and the type most of the value in Go's `io` suite is carried by. The same reader is what proves `read_all` keeps its offsets right across the three list growths a 1,500 byte stream needs.

`copy_n` and `copy_buffer` are the two copies with something invisible to get wrong. `copy_n` has to clip its last read to the count, because a version that read a whole buffer and wrote only part of it produces exactly the right output and silently eats the rest of a stream somebody else was going to read. `copy_buffer` has to use the buffer it was handed and still take a fast path over it, which surprises people and is Go's behaviour. Neither claim is visible in the bytes, so both are checked with counters.

`copy_n` differs from Go and says so. Go reaches the destination's `read_from` by wrapping the source in a `LimitReader` and calling `Copy`; the wrapper here would have to hold a borrowed reader in a field, which `erased.mojo` forbids because a view does not keep its target alive. A caller that owns its source gets Go's behaviour exactly by writing `copy(dst, limit_reader(src^, n))`, and the docstring says that rather than leaving the difference to be discovered.

`LimitedReader`, `SectionReader` and `OffsetWriter` are generic over what they wrap instead of holding an erased value. Go has to hold an interface, so every read through `io.LimitReader` is an indirect call; here `LimitedReader[Fixed]` calls `Fixed.read` directly and can inline into it. The cost is that they own their argument, because a parameter has to be a type and the alternative is a view in a field.

`SectionReader.outer` is the one place a Go signature would not translate. Go hands back the underlying `ReaderAt` along with the offset and the size, and a method here cannot return a borrow of a field alongside two values, so the source is the public field `r` and `outer` returns the pair. Two section readers over one source still read at the same time without disturbing each other, which is the property `ReaderAt` exists to promise and there is a test for it.

`WriterAt` takes `mut self` where `ReaderAt` takes `self`, and the asymmetry is deliberate. Go documents parallel non overlapping `WriteAt` calls as safe, which is a property of the destination rather than of the value, and Go can express it because its implementations write through a pointer. A sink that keeps its bytes in a field cannot change them through an immutable borrow without interior mutability, which this library does not have, so the promise survives as a comment and the borrow checker serialises the calls. Nothing was lost that could have been said.

`multi_reader`, `multi_writer`, `tee_reader`, `nop_closer` and `Discard` are the combinators, and three of them behave differently from Go on purpose. A multi reader whose middle source is empty keeps going rather than handing back a zero length read, because a zero without an error is the thing `ErrNoProgress` exists to catch and producing one deliberately is worse than the extra loop. A tee reader raises when its sink fails, because by then the bytes are out of the source and a swallowed failure loses them with nobody told. And it does not flatten a nested multi reader the way Go does, because the erased value's type is gone by the time it is seen and there is nothing to recognise.

`Discard` is a type rather than a variable, since there are no package level variables and there was nothing to construct anyway, so it is `Discard()` at the use site. It sets `READER_FROM` and implements `read_from`, which is what makes draining a reader into it allocate one 8 kB buffer instead of thirty two.

`write_string` does not type assert. Go's `io.WriteString` looks for an `io.StringWriter` and the only thing that buys is skipping the copy `[]byte(s)` makes; `String.as_bytes` is a borrow, so there is no copy and the assertion would have nothing to gain. The trait is still declared, because a writer that wants the string rather than its bytes is a real thing and a function can ask for one by name.

`io.Pipe` is waived to M4 with the milestone and the issue named on the waiver line. Every one of its methods blocks until the other side arrives, which needs `core.sync`, and a pipe written against nothing would deadlock on first use. `ErrClosedPipe` is numbered now regardless, so the sentinel sits with the rest of the `io` ones and does not move when the pipe lands.

Twenty mutations, one per claim, each reverted after the suite caught it. Deleting the short buffer check, reporting `EOF` where a truncation should report `ErrUnexpectedEOF`, running `read_at_least` once instead of looping, dropping `LimitedReader`'s clip, reading a section's `read_at` offset as absolute, letting `copy_n` read past its count, having `copy_buffer` allocate its own buffer or skip the fast path, swallowing a tee's write failure, clearing `Discard`'s bit. All twenty were caught.

One more Mojo fact, with a probe. A struct's own parameter has to be written `Self.R` in a field declaration; the bare name is refused with "unqualified access to struct parameter" while being perfectly legal in a method signature three lines below and in the return type of a free function next to it. Every wrapper type in this package hit it.

The parity tool was under-reporting again, and this time the bug had the shape worth recording: it read re-exports with a regular expression that only matched a single line `from ... import`, so a package measured worse the more it exported, because `mojo format` rewrites a long import into the parenthesised multi-line form the moment the names stop fitting. It matches both spellings now. The seek constants are in `renames.toml`, because the rule turns `SeekStart` into `seek_start` and this library spells a constant in capitals.

`core.iter.Cursor`, which is the shape every fallible iterator in this library has to be written in. A Mojo `for` loop drops an error raised out of `__next__`, so a csv reader that hits a malformed row returns the rows before it and the program carries on believing it read the whole file. The replacement is an explicit `has_next` and `next` pair with a trait to hang it on, and the loop written out three lines longer, which is the entire point: the failure comes out of the `while` or out of the `next` and lands on the caller, because there is nowhere for it to go quietly.

It is deliberately not called `Iterator`. The hazard being defended against is somebody assuming `for x in it` works, and a trait with that name invites the assumption at every use site. Infallible iteration keeps Mojo's own `__iter__` and `__next__`, which are safe for exactly the reason this is not.

The element type is an associated `comptime Element` rather than a parameter, because `trait Cursor[T]` does not compile: trait declarations do not take parameters. Its bound is `Deinitable & Movable`, the least a caller needs to own what it is handed and let it go again, so a cursor may yield a buffer or a file handle. Requiring `Copyable` would have ruled out most of the interesting ones. Both methods may raise and the implementation chooses which side does the work, because a reader cannot know whether there is another record without parsing one, and a reader sitting on a buffer answers `has_next` cheaply and fails in `next`.

The swallowing turns out to be specific to `__next__`, which nobody had checked. A raising `__has_next__` makes the `for` statement itself a raising call, so the loop cannot be written in a function that is not `raises` and the error comes out normally. There is a second probe for that half, because the two behaviours being different is what makes the linter rule correct as narrowly as it is written, and a release that made them consistent could go either way.

The linter rule had a hole of the same kind the unsafety check had. Its pattern required the parenthesis straight after the name, so `def __next__[o: Origin](mut self) raises` went through unmatched, and that is not an exotic spelling: it is what an iterator borrowing its input looks like. The pattern now skips an optional parameter list, and a second fixture goes with it, because the first one names `__next__` the old way and would still be rejected with the new half deleted.

Go's four symbols in `iter` are waived. `Seq` is `func(yield func(V) bool)`, so the sequence is a closure and iterating it means storing another one, which design.md section 3 says is not available; `Pull` gets to a next and stop pair, which is the shape used here, but it gets there by taking a `Seq`. There is no `Cursor2`, because Go needs `Seq2` only to give a range over func a second yield argument and a `Cursor` whose `Element` is a tuple covers it.

`core.io` has its first three symbols: `Reader`, `Writer` and `copy`. It is the package the rest of the library is shaped around, so the interesting part is not the code but which of Go's `io` decisions survived contact with Mojo.

Go's `io.Copy` opens with two type assertions, `src.(WriterTo)` and `dst.(ReaderFrom)`, and neither is available here. A trait is a compile time constraint rather than a value, so there is nothing to assert on, and a generic function also cannot ask whether its `R` happens to implement something, so both halves of Go's mechanism are missing rather than one. They are replaced by one thing: `capabilities`, an `Int` of bits declared on the trait with a default body returning zero, alongside the optional methods declared with default bodies that raise. A type that implements `write_to` overrides two methods, the one that does the work and the one that admits to it. What makes this worth the redundancy is that it reads identically on both paths. A static reader answers from a constant the compiler sees through; an erased one answers from a field it copied off its target at construction. Go needs an interface table lookup for the erased case and cannot do the static case at all.

A type can therefore lie, and setting a bit without writing the method gets the inherited raising stub, which is a clear failure at the first call rather than a wrong answer. There is a test for that, and for the path choice itself: the four combinations of a static and an erased side, with the bit set and with it cleared, proven by a counter on the test types rather than by reading the code. A suite that only compared the output bytes would pass with the whole dispatch deleted.

`Read` is stricter than Go's. A read that moved bytes returns them and does not raise, so `EOF` always arrives with a count of zero. Go allows both at once and then asks every caller to handle the `n` before the `err`, which is a rule a caller can forget and a familiar source of silently truncated data. Go's own `bufio` already behaves the way this does.

Two erased types rather than one, and the split is the safety story. `AnyReader` owns what it wraps and is what a function returning "some reader" returns. `ReaderView` borrows: it is an address and a table and it keeps nothing alive, and it exists because `read_from` is handed a `mut src` it has no right to take and must still call it through a function pointer, which is the one thing a trait bound cannot do. A view is an argument and never a field, nothing checks that, and it is confined to two constructions inside the package that both hand it straight to a call.

Two Mojo findings came out of building it. A pair of structs whose function pointer fields name each other compile on their own and stop compiling once the slots are filled by parametric thunks, reported as `struct has recursive reference to itself` against whichever came second, which is not where the problem is; the slots carry the other view's address as an `Int` instead, so only the thunk bodies name it. That one is recorded next to the code and not in design.md, because every claim there comes with a probe and no small program reproduces it. The second one does: a value is destroyed after its last use rather than at the end of its scope, so taking a view's address and never mentioning it again means the view is already gone when the callee reads it. `_ = view^` after the call is the fix, `tools/probe/probes/last_use_destroys.mojo` pins that it is still needed, and design.md now says so.

The parity tool was measuring this package at zero and then at half. It ran `mojo doc` without an include path, so the first package in the tree with a dependency failed to parse and reported no symbols at all while looking like a package nobody had started; it now passes the root and prints the compiler's own message when a package fails, rather than leaving the reader to reproduce it. It also counted only declarations, so a name a package republishes for its users was invisible, which is `EOF` and its two siblings here: they are declared in `core.errors.codes` because they come out of one generated table, and they are importable exactly as Go's `io.EOF` is. It now reads the `from ... import` lines of each package's `__init__.mojo`, and only that file, because an import anywhere else is a private dependency rather than a promise.

A correction to design.md section 5, and a probe so it stays corrected. The section said a struct field cannot carry an unbound origin, and left the reader to conclude that the erased box stores an integer because nothing else was available. That conclusion is wrong: `AnyOrigin` in a field is rejected, but `Pointer[T, UntrackedOrigin[mut=True]]` in a field is accepted and erases just as thoroughly. There are now two probes, one on each side of that line. The integer is a choice, and the reason is that the box has forgotten its pointee type as well as its origin, so a pointer field would have to name a placeholder `T` and reinterpret at every use.

The bottom of the erasure design: `core.runtime.box`, a refcounted heap box holding a value whose type has been forgotten. `io.Reader`, `io.Writer`, `net.Conn`, the nine `database/sql` driver interfaces and every value in a JSON document sit on this, because Mojo has no trait objects and each of those has to be built by hand out of a box and a table of function pointers.

It is its own package rather than forty lines inside `core.io`, which is the decision worth explaining. All four of the consumers already depend on `core.io`, so that would have cost nothing in dependency edges. It was rejected because `core.io` would have to declare `unsafe = true`, and that permission then covers every line of the reader, the writer and `copy` rather than the forty that need it, and because erasure is not an IO idea: anything that ever wants a heterogeneous collection would have to depend on `core.io` to get one. That makes 138 packages and 17 unsafe, with `core.io` still safe, which was the point.

The count and the value share one allocation, because erasure sits on the read path of every buffered reader in this library and two allocations per box is a cost that shows up. That means the block is aligned by `posix_memalign` rather than `malloc`, since `malloc` promises sixteen bytes and a SIMD type wants sixty four, and there is a test that boxes one.

The destructor is the part that was not obvious. A parametric `_release[T]` can be materialized into a `def (Int) thin -> None` and stored in a struct field, which is what lets a box that has forgotten its type still run that type's destructor. That is design.md section 2 used for something other than a vtable.

Copying is an atomic increment and it is spelled out at the call site, because Go's interface copy is free and this one is not. `errors.ErrorValue` made the same call for the same reason.

`pixi run race` builds the whole suite under the thread sanitiser. Refcounts and locks are the two things in this library whose bugs do not arrive as a failing assertion, so a green `pixi run test` is not evidence about either of them. The sanitiser reports and then leaves the exit code alone, which would have meant a suite with a data race passing with the report sitting in the log, so the runner reads its output and promotes the report. Making the box's count non atomic produces four race reports and a failing count, and both halves are printed rather than the first of the two.

One trap found on the way and worth knowing about: two packages in the same binary declaring the same foreign symbol with different argument types is a build that fails, and nothing says so until both packages land in one link. `core.errors` frees a pointer, this box was freeing an integer, and the test suite is the first build that contains both.

The linter's unsafety check had a hole big enough to drive the box through, and now does not. It was a list of eight names, all of them types or free functions, and it never looked at the unsafe operations that hang off a safe type as methods. `span.unsafe_ptr().as_unsafe_any_origin()` is a raw pointer with its origin erased, it is the entire trick `core.runtime.box` exists to contain, and the word `Pointer` does not appear in it. The check now matches the whole `unsafe_` prefix as a family, which covers the fifty odd names that exist today and the ones that arrive with the next release. A second fixture goes with it: the old one names the raw types outright, so it would still be rejected with the family match deleted and therefore cannot prove the family match is alive.

## v0.2.0 - 2026-09-03

M1 is complete. `core.errors` is the first package in this library with code in it, and the first at full parity. It is the mechanism every fallible function written here from now on is written against, which is why it comes before anything that could use it.

The problem it solves is that Mojo's `Error` carries a string and nothing else, while half of Go's standard library returns a struct with a path, a syscall number or a byte count in it. The answer is a record in thread local storage, matched to the error by the message it was raised with, and `capture` for when the error has to outlive the raise. All three of the ways that can fail silently now have a test that was watched failing.

Two language probes and the design facts they pin, ahead of `core.errors` in M1.

Mojo has no global mutable state. A module level `var` is refused outright and the message tells you to move it into a function or make it a `comptime` constant, so there is nowhere in the language to put a package level counter, cache, registry or default. Go's standard library has one in a dozen places. [docs/design.md](docs/design.md) now records that, and that every one of those becomes a value the caller owns and passes.

The one exception is the thread local error record in section 4, which has to outlive the call that wrote it and cannot be passed. It gets its slot from a small C object that `core.errors` links, described below. The cost is stated in the design rather than discovered later, and the alternative it was weighed against was threading an explicit context through every fallible call in the library, which puts the error mechanism in the signature of every function in it.

`tools/probe/probes/thread_local.mojo` pins that pthread's per thread storage really is per thread. Four threads each claim a slot, hand its address to `pthread_setspecific`, wait at a barrier until all four have written, then read the pointer back and write through it, while the main thread holds a different value in the same key across all of it. Without the barrier a shared slot would still look correct, because each thread would set and read before the next arrived. The failure this rules out is one thread reading another thread's error fields, which is a wrong answer rather than a crash.

Both probes were checked against the two ways they can fail: compiling when they should not, and still being refused for a different reason than the one recorded.

The first library code in the tree: the thread local error record, which is the mechanism every fallible function in this library will be written against.

`Report(message).with_field("path", name).error()` writes a record into this thread's slot and hands back the `Error` to raise. `field(e, "path")`, `code(e)` and `partial(e)` read it back at the catch site, so the fields Go would have put in a struct survive a raise that carries only a string, and so does the `n` from Go's `(n, err)` that a raise would otherwise drop.

A record is matched to an error by the message it was raised with and by nothing else. That is what makes the two silent failures safe. An error raised by `std`, or by anything that has never heard of this mechanism, finds a record whose message is not its own and is correctly reported as carrying nothing. An error held past the next raise on the same thread finds the newer record, sees a different message, and reports nothing rather than the newer error's fields. Both of those would otherwise run, print something plausible and be wrong, so both have a test, and both tests were watched failing with the identity check removed. Nothing is appended to the message to make this work: a message with a token in it is a message that cannot be printed, and matching on text that somebody also reads would make every wording change a breaking change to a lookup.

The slot is C, in `core/errors/shim/slot.c`, and that directory's README says why at length. It is a pthread key rather than a `_Thread_local` pointer because a key has a destructor, so a thread that exits still holding a record frees it. The destructor is a Mojo function handed to the shim rather than exported for it to find, because a function only C calls is a function a dead code pass removes, and the exported version linked on Linux and not on macOS. `core.errors` therefore declares `unsafe = true`, taking the linter's count from fifteen packages to sixteen, and running the tests now needs a C compiler on the host.

`core.errors` is tier zero, so every binary built on this library links that object. The cost is stated in [docs/design.md](docs/design.md) section 4 rather than left to be found in a link line, and the alternative it was weighed against, threading an explicit context through every fallible call, is recorded there too.

Two more language facts, each with a probe. A struct valued field cannot be moved out of an owned `self`, which is why `errors.Report` is both the builder and the record rather than the two structs that would read better. And the pthread key destructor really does call back into Mojo on a worker thread's exit, which was proved before the record depended on it.

`tools/lib/native.py` is now the one place that goes looking for a C compiler, shared by `pixi run baseline` and the test runner, and it explains why neither takes one from the lockfile.

The rest of Go's `errors` package: `wrap`, `matches`, `join`, `unwrap`, `causes` and `new`. `core.errors` is the first package in this library at full parity, five symbols present and two waived.

The record is a tree now, because wrapping and joining both make one. It is an arena of links with integer indices, which is the technique the design already committed to for every recursive type here, used for the first time. A chain survives any number of levels with each level keeping its own fields, and `wrap` copies the cause out of the thread's slot before the new record replaces it, which is the only order that works when there is one slot per thread. `field` and `code` answer about the error you hand them and not about what it wraps, because two links in a chain can each carry a `path` and the wrong one is worse than nothing. `matches` is the one that walks, and it walks every cause of a joined error rather than the first, which is the part of Go's contract that is easy to get wrong and which now fails a test when it is.

A sentinel is a code, and nobody picks the number. Go's `errors.Is(err, io.EOF)` works because `io.EOF` is a value you can hold, and there is none here, so a sentinel is an integer on the record. Integers chosen by hand collide, and a collision makes `matches(e, io.EOF)` quietly true for an `os` error, so `core/errors/codes.toml` lists every sentinel in the library and `tools/gen/codes.py` numbers them. That makes a collision impossible rather than unlikely, at the cost that the numbers move when a line is inserted, so a code is meaningless outside the process that produced it and the type says so. `Code` is a struct rather than an `Int`, which is what stops `with_code(300)` compiling where `with_count(300)` was meant.

`errors.As` and `errors.AsType` are waived. Both are reflection over a type hierarchy and this library has neither, so there is no honest partial version; the replacement is the field lookup, the sentinel comparison, and a per package helper such as `os.PathError.of(e)`. `errors.Is` is renamed to `matches`, because `is` is a Mojo keyword.

`join` is weaker than Go's and the deviations page says so rather than leaving it to be found. Go holds error values and every field with them. At most one of the errors passed here still owns the thread's record, so the others contribute their message and their place in the tree and nothing more. `capture` is what will close it.

Sixteen new tests, and the suite was checked against three ways of getting this wrong: a `matches` that does not walk the chain, a `join` that reports only its first cause, and a wrap that refers to the record instead of copying it. Each one fails the tests that name it and nothing else.

`errors.capture(e)` and `ErrorValue`, which is what makes an error a value again. It copies the error's whole subtree out of the thread and owns every message, field and cause it can reach, so a failure can go in a list, sit in a struct field, or be read by a thread that never saw it raised. `ErrorValue.error()` is the way back: it installs the record on whatever thread calls it, so a task's error can be re-raised by the thread that collected it and every function in this package then works on it as though it had just happened.

The cross thread case is the one that decides whether any of this is real, and it now has a test. The reading thread first raises an error of its own, so its slot holds something else entirely, and then reads the captured value. Routing `ErrorValue.field` through the thread's slot instead of the value makes that test fail with `left: /the wrong one`, which is the exact wrong answer it exists to rule out.

`join` over captured errors keeps every field of every cause. Over live errors it cannot, because a record is written at raise time and the next raise replaces it, so all but one arrive as a message. Both halves have a test, so the code and the deviations page cannot drift apart.

With that, the three ways design.md section 4 can fail silently are all covered: a foreign error mistaken for ours, an error held past the next raise, and a capture read on a thread whose own storage holds something else.

The platform key is the operating system and the architecture and nothing else, spelled the way the CI matrix spells them. Branch protection on `main` now requires a pull request with the `ci ok` check passing and the branch up to date, on top of the force push and deletion rules that were already there.
