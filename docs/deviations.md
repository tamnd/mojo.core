# Deviations

Every deliberate departure from Go, in one place, so that you can read the whole cost of the translation without assembling it from the package documentation.

This is the honest answer to the claim that nothing is missing. Every symbol in the implemented column of [packages.md](packages.md) is present. Not every one behaves identically, and the ones that do not are here. A deviation that is not on this page is a bug, so please report it.

Five categories, and the split matters. Forced is what Mojo would not let us do. Better is where Mojo let us do more than Go. Added is what Go lacks. Omitted is what we chose not to carry. Residue is the small set of aborts that survive.

## Forced by the language

Each row names the property of Mojo behind it. The numbers refer to sections of [design.md](design.md).

| --- | --- | --- |

| `sort.Slice(x, less)`, where `less` is a closure value passed at run time | `slice[less](span)`, where `less` is a compile time parameter spelled `capturing [_]`. | `bytes.Buffer.AvailableBuffer`, an empty slice over the buffer's spare capacity to be appended to and written back | Nothing, for the two reasons above at once: a `Span` has no capacity to append into, and handing out the buffer's own memory is what this package does not do | 5 |

Pointing a reader at a different part of the same buffer works; pointing it at a different buffer means making a different reader, which is two words and no allocation. The same shape as `bufio.Reader.Reset` above. | 5 |
| `bytes.FieldsFuncSeq(s, f)` returning an `iter.Seq[[]byte]`, the same type whatever `f` is | `fields_func_seq` returns a struct that a `for` loop walks but that declares neither `Iterator` nor `IterableOwned`. | `strings.Reader.Reset(s string)` with any other string | `reset` takes a slice with the same origin, because the origin is part of `Reader[o]`. Pointing a reader at another part of the same string works; pointing it at a different string means making a different reader. The same shape as `bytes.Reader.Reset` above. | 5 |
| `strings.Builder.String` costing nothing, because it reinterprets the bytes it accumulated as a string without copying them and promises never to write them again | `string()` copies. A `String` owns its bytes and the builder still owns its list, so the two cannot be the same memory. `bytes()` copies for the same reason, and `len()` is the question that does not need either. | no shared ownership |
| `strings.NewReplacer` building its trie on first use behind a `sync.Once`, so a replacer that is never used costs nothing | The constructor builds it. `replace` takes `self` by borrow and there is no interior mutability to build through, so the work has to happen while the value is still owned. | 5 |
| `strconv.ParseFloat`, `ParseInt`, `ParseUint` and `ParseComplex` returning the clamped value alongside `ErrRange`, so a caller who ignores the error still gets an infinity or the nearest limit | The failure is a raise and a raise carries no value, so there is nothing beside it. `errors.matches(e, strconv.ErrRange)` says which limit was hit and the sign is in the input, which is all the clamped value ever told you. `NumError.of(e)` recovers the call, the input and the code. | 4, one string error type |
| `strconv.ParseComplex` and `FormatComplex` working on `complex128` | Both work on `std.complex.ComplexFloat64`, because Go's complex is a language type and Mojo's is a library one. It is the standard library's rather than `core.math.cmplx`'s: that package sits above this one and could not be depended on from here. | no complex in the language |
| `strconv.AppendInt`, `AppendFloat`, `AppendQuote` and the rest returning the grown slice | Every append form takes `mut dst: List[UInt8]` and returns the byte count, the same rule as `utf8.AppendRune` below | no shared ownership |
| `utf8.AppendRune(p, r)` returning the grown slice, because that is what `append` does | `append_rune(mut dst, r)` grows the list in place and returns the byte count instead, since two names for the same list is exactly what ownership forbids | no shared ownership |

| `unicode.CaseRanges`, `GraphicRanges`, `PrintRanges`, `TurkishCase` and `AzeriCase`, package level slices | The same five names as functions, each returning a fresh `List`, for the same reason as the maps above | no global mutable state |
| `unicode.CaseRange.Delta`, a three element array of runes indexed by `UpperCase`, `LowerCase` and `TitleCase` | A four lane `SIMD[DType.int32, 4]` with the fourth lane unused. A fixed size `Array` is not implicitly copyable, so a struct holding one cannot be either, and a vector's length has to be a power of two. The three indices are unchanged. | a fixed array is not implicitly copyable |
| `slices.Insert`, `Delete`, `Replace`, `Compact`, `Grow` and `Clip` returning the new slice, so that `s = slices.Delete(s, 1, 2)` is the idiom | The same six take `mut s: List[T]` and return nothing. A Go slice header is a value, so returning one is how a length change is published; here the length lives in the list and the caller already has it. Returning a second `List` would mean two owners of one buffer. | no shared ownership |
| `slices.Concat(a, b)` and `Insert(s, i, v...)` taking slices of the same element type from anywhere | `concat` is variadic over `List[T]` rather than over spans, and `insert` takes one span. A Mojo variadic binds a single origin parameter for every argument, so `*parts: Span[T, o]` cannot accept spans into two different lists. | 5, one origin per variadic |
| `slices.AppendSeq(s, seq)`, destination first, as every append shaped function in Go is | `append_seq(mut c, mut into)`, cursor first. `C` is inferred from the cursor and the destination's type is `List[C.Element]`, so with the destination first the compiler reaches it before `C` is resolved and refuses the call. | argument order fixes inference order |
| `slices.Clip(s)` returning `s[:len(s):len(s)]`, which caps the capacity so a later append cannot reach into the tail, and frees nothing | `clip(mut s)` moves the elements into an exact capacity list and gives the old allocation back. | `slices.All`, `Values`, `Backward` and `Chunk` returning an `iter.Seq`, and `Collect`, `Sorted` and `AppendSeq` taking one, so producers and consumers meet in the middle | Producers return ordinary Mojo iterators and a `for` loop over one is correct. Walking a span cannot fail; the sequences people actually collect from — csv records, sql rows, directory walks — can, and a `collect` that only took infallible iterators would be a `collect` nobody could use. | 7, `for` drops the error |
| `math.SmallestNonzeroFloat32` and `SmallestNonzeroFloat64`, each a decimal literal like every other constant in the file | Both are built from their bit pattern, one bit set in the lowest place of the fraction. The value is Go's exactly, and it has to be written this way because a float literal is flushed to zero on its way into a `Float32` or a `Float64` when it is subnormal, and the smallest nonzero float of a width is subnormal by definition, so the decimal spelling would have given zero twice. | a subnormal float literal is zero |
| `math`'s fifteen integer limits as untyped constants, so `math.MaxInt64` is usable wherever a number is wanted and `math.MaxUint64` does not overflow anything until it is assigned to something | Each has the type its name says. `MAX_INT64` is an `Int64` and `MAX_UINT64` is a `UInt64`, which are the limits of Mojo's own types and are what a caller comparing against a value of that type wants anyway. | `rand.New(src)` holding a `Source` interface value, so the caller keeps the source and can go on drawing from it alongside the `Rand` | `Rand[S]` owns its source and `Zipf[S]` owns its `Rand`, where Go holds a `*Rand`. | `rand.Shuffle(n, swap)`, where `swap` is a `func(i, j int)` passed at run time | `shuffle[swap](count)`, where `swap` is a compile time parameter spelled `capturing [_]`, so the exchange is inlined rather than called through a pointer. | `rand.N[T]` constrained to the integer types by `~int \| ~int8 \| ...`, so `rand.N(1.5)` does not compile | `n[dt](limit)` raises `ErrInvalidArgument` when `dt` is not integral. The test is a `comptime if` and folds away for every integer type, so an integer call pays nothing for it, and there is no way to make the float call a compile error instead. | 10, a compile time fact cannot be turned into a compile error |

That is why `core.math.rand` declares `unsafe`, and it is confined to `globals.mojo`; nothing a caller of `Rand`, `PCG`, `ChaCha8` or `Zipf` touches goes near it. | no global mutable state |
| `big.Int`'s methods taking the destination as the receiver, so `z.Add(x, y)` can be called with `z` as one of the operands and a loop around a single allocation is the idiom | `x.add(y)` returns a new `Int`. The three operations with a second answer, `quo_rem`, `div_mod` and `gcd_ext`, write the extra ones through `mut` arguments the caller already holds. A destination that is also an operand is one value borrowed for writing and for reading at the same time, which is the one thing the checker is there to refuse. | 5, no two borrows of one value when one of them writes |
| `big.Int`, a name that sits beside the builtin `int` without colliding with it | The struct is `Int`, so `from core.math.big import Int` takes Mojo's `Int` away for the rest of the file. Every caller writes `import core.math.big as big` and spells it `big.Int`, and the package's own files say `_MojoInt` where they mean a machine integer. | a package name is not part of a type name |
| `big.Int.Bits` and `SetBits`, documented as the number's own backing array so the limbs can be read and written in place | Both copy | 5, a span does not keep its owner still |
| `big.Int.Rand(rnd *rand.Rand, n)`, holding a pointer to a generator the caller keeps | `rand` takes anything implementing `core.math.rand.Source` as a parameter, which a `Rand` is and so are `PCG` and `ChaCha8` on their own. The digits differ from Go's for the same seed: Go builds each sixty four bit digit from two thirty two bit draws, which is what its v1 generator was wide, and `core.math.rand` is v2, whose sources are already sixty four. | 1, no trait objects |
| `big.Rat.Num` and `Denom`, documented as pointers into the value, so a program can write through them and change the fraction, and so the two stop being valid when the `Rat` is assigned to | Both copy. Same reason as `Int.Bits` above: the owner can move. A caller who wants to build a new value out of the two halves calls `set_frac`, which is what writing through the pointers was for. | 5, a span does not keep its owner still |
| `big.Rat`'s zero value carrying an empty denominator, which its own methods read as a one and which `mulDenom`, `scaleDenom` and half of `norm` exist to remember | The denominator is a one from the moment the value exists, so those three have no counterpart. The only visible difference is the gob encoding of a `Rat` nobody has assigned to, which Go writes with an empty denominator and this writes with a one. Both sides read both forms, so a value still crosses in either direction. | a method on a value cannot assume it was reached through a pointer |
| `syscall.Stat_t`, a struct declared per platform and laid out by the compiler | `Stat`, a byte buffer the kernel writes and accessors that read a field at the offset the platform's own headers reported, recorded in `core/syscall/baseline/*.json` and generated into `abi.mojo`. There is no way to declare a C structure layout in Mojo and be sure it matches, and `struct stat` disagrees with itself across all three of our platforms, down to the field order. | a C layout cannot be declared |
| `syscall.Errno`, an integer that satisfies `error`, so it is both compared and returned | `Errno` is a value with the same two jobs, but a call reports failure by raising, with the number on the record under `errno`. `errors.field(e, "errno")` gets it back, and there is no `(n, err)` pair to return it beside. | 4, one string error type |
| `time.UTC` and `time.Local`, package level `*Location` variables, so `t.In(time.UTC)` names one without calling anything | `utc()` and `local()`, functions. | `time.Parse` returning a `*ParseError`, which a caller reaches with `errors.As` and then reads five fields off | The failure is a raise with `ErrParseTime` on the record and the same five fields beside it, and `ParseError.of(e)` puts them back together as a value. | `time.Time.AppendFormat(b, layout)` returning the grown slice | `append_format(mut dst, layout)` grows the list in place and returns the byte count, the same rule as `strconv.AppendInt` and `utf8.AppendRune` above | no shared ownership |

| `init()` | Compile time initialisers and explicit registration | no `init` |
| Struct embedding with method promotion | Composition with explicit forwarding | no promotion |
| The `embed` directive | A tool that generates a Mojo source file from a directory | a directive is not a library |

Two of these cost far more than the rest. The compile time warning means every static check in this library is a warning that our linter promotes to an error inside this repository and that you see as a warning. The fixed stack means a task is not a goroutine even if the green thread work in M9.4 succeeds.

## Where this library is stricter or better

These are deviations too, because code written against Go's semantics may not port, and they are improvements.

| Go | This library |
| --- | --- |
| `Read` may return bytes and an error together, and every caller is told to handle the count before the error | A read that moved bytes returns them and does not raise, so `EOF` always arrives with a count of zero |
| A string builder copied after use panics through a runtime check | Not copyable, so the mistake does not compile |
| A mutex copied by value is caught by a separate analysis tool | Not copyable, so it does not compile |
| `io.MultiReader` returns a zero length read when a source in the middle is empty | The loop moves to the next source instead, so a caller never sees a zero without an error |
| `io.TeeReader` reads and writes, and a caller that ignored the error loses the bytes it already took | A write failure comes out of the read, because the bytes are already gone from the source by then |
| `io.WriteString` type asserts to `io.StringWriter` to avoid the copy that `[]byte(s)` makes | `String.as_bytes` is a borrow, so there is no copy to avoid and no assertion to make |
| `time.Time` packs the wall clock, the monotonic reading and a flag into two words, and drops the monotonic reading for any instant more than 292 years from 1885 | Four separate fields, so nothing is dropped and a far future instant keeps its monotonic reading. A program can only tell the two apart by subtracting two times that are both centuries away and both came from `now`, which needs the machine clock to have been set there. |
| `==` on a `time.Time` compares the fields, so two values naming the same instant compare unequal when one carries a monotonic reading or a different location, and Go's own documentation says not to use it | `==` is Go's `Equal`, which compares the instant. Go's `Time.Equal` and this library's `__eq__` are the same function, and the comparison Go's `==` does has no spelling here. |
| A removed list element is a dangling pointer the documentation asks you not to use | An index and a generation counter, so a stale handle raises |
| `rows.Scan(&a, &b)` checks the column count at run time | `rows.scan[Int, String]()` checks it at compile time |
| `context.WithValue` stores `any` and reading it back is an unchecked assertion | `ctx.value[RequestID]()` returns an optional, and a mismatch does not compile |
| An unclosed row set or transaction leaks a connection until a finalizer runs | Not copyable, returns the connection in the destructor, and the transaction is a `with` block |
| `sync.Pool` is emptied by the garbage collector and documented as a cache | Deterministic. It holds what it is given, with an optional cap. |
| Interned values are freed when the collector proves them unreachable | Reference counted, so they are freed when the last handle goes |
| A file is closed by a finalizer if you forget | Closed by the destructor, a close error is reported rather than lost, and the linter warns on a written file dropped without an explicit close |
| Struct tags are unchecked strings that fail silently when misspelled | Validated against a grammar by the generator, and a bad one fails the build |
| The regexp engines are trusted to agree | Every pattern in the corpus runs through all applicable engines and the results have to be identical |
| `for s.Scan() {}` ends early and silently on a read failure, and `s.Err()` after the loop is what you were supposed to remember | A failure comes out of `has_next` as a raise. There is no `Err`, so there is nothing to forget. |
| `bufio.ReadSlice` on a full buffer returns the buffered bytes alongside `ErrBufferFull`, and a caller that handled the error first has dropped them | The bytes stay buffered. `read_bytes` on the same reader still returns the whole thing, so the recovery is one call rather than a merge. |
| `Scanner.Text` and `ReadString` on bytes that are not valid UTF-8 hand back a string containing them, because a Go string is bytes | Both raise. `Scanner.bytes` and `read_bytes` are the versions that never refuse, and they are what a caller reading unknown encodings wants anyway. |
| `bytes.Buffer.Peek` short of `n`, and `ReadBytes`/`ReadString` with no delimiter in what is left, each return the bytes alongside `io.EOF`, so the answer is in the value and the reason is in the error at the same time | The bytes come back with nothing raised, and the end arrives on the next call, which has nothing to hand over. Same rule as `Read` above and as `bufio`: a call that moved bytes succeeded. `peek` raises `EOF` only when the buffer is empty and `n` is positive. |
| A split function returning a token that is not inside the data it was given cannot be checked, because the token is a slice and is inside by construction | The token is a pair of indices the split function chose, so the range is bounds checked and an off by one raises rather than handing out neighbouring bytes |
| `ErrFinalToken`, an error value that is not a failure and means stop after this token | `Split.last` and `Split.stop_here`, which are data. The error channel only ever carries failures. |
| `bufio` panics in three places: `Split` after scanning, `Buffer` after scanning, and a split function returning tokens without advancing | All three raise. The last one is `ErrNoProgress` after the same hundred empty tokens Go counts. |
| `bytes` panics in four places: `Repeat` on a negative count or an overflowing length, `Join` on an overflowing length, `Buffer.Grow` on a negative one, and `Buffer.Truncate` past what is buffered | All four raise, and the out of memory case raises `ErrTooLarge` rather than panicking with it. Every one of them is a check the caller could have made, and a buffer that has run out of memory is a condition the caller is the only one able to report on, because they know whether the input that caused it was theirs. |
| Each of Go's map iterators randomises separately, so a caller wanting parallel key and value lists has to go through `All` and unpack the pairs | `keys` and `values` walk the dict the same way when nothing has changed in between, so `keys(d)[i]` and `values(d)[i]` are one entry. Which order it is stays unpromised, as in Go. |
| `slices.Chunk` clips the capacity of every chunk it yields, so that appending to one cannot overwrite the start of the next | A chunk is a `Span`, which has no capacity and cannot be appended to, so the hazard the clip exists to prevent has nowhere to happen |
| `strings.Builder.String` hands back whatever bytes were written, valid UTF-8 or not, because a Go string is bytes | `string()` raises and `bytes()` is the accessor that never refuses, the same rule as `Scanner.Text` above |
| `strings.Builder.Reset` drops the allocation, so a builder reused around a loop allocates again every round | `reset()` keeps the capacity and only sets the length back to zero. The builder is not copyable and hands out nothing that views its storage, so there is no way to read the old bytes and no reason to give them back. |
| `strings` panics in one place, `Builder.Grow` on a negative count | It raises, like the four in `bytes` above |
| `strings.NewReplacer` panics when given an odd number of arguments, because its pairs are a flat variadic list | The constructor takes a list of pairs, so a replacement with nothing to replace it with does not compile |
| `Replacer.WriteString` writes each unchanged run and each replacement as it finds them, so a writer that fails halfway has already been handed part of the result and the caller has to read the count to learn how much | The result is built first and written once, so a failure means the writer saw one call and the count is the whole answer or nothing. The cost is holding the result in memory, which the walk it shares with `replace` was doing anyway. |
| `strconv` panics in two places, `FormatFloat` and `FormatComplex` on a bit size that is neither of the two allowed | Both raise. A bit size is written by the program rather than read from its input, so the mistake is the caller's either way, and raising lets a generic wrapper that passes one through report it instead of taking the process down. |
| `strconv.ParseInt` reports an impossible base and malformed digits through the same message with no sentinel behind it, so a caller cannot tell them apart | `ErrBase` and `ErrBitSize` are separate codes. The base and the bit size came from the program and the digits came from its input, which are two different bugs to go and fix. |
| `math/bits` panics in six places, `Div`, `Div32`, `Div64`, `Rem`, `Rem32` and `Rem64` on a zero divisor, and the three `Div` on a quotient too wide to return | All six raise, `ErrDivideByZero` and `ErrOverflow`. The panic Go raises there is the runtime's own `integer divide by zero`, which reads as though the hardware trapped when in fact the package checked, and a package this far down the tier list is not the one that gets to end the process. The three `Rem` cannot overflow, which is why Go has them beside `Div` at all. |
| `math/big` panics in eight places reachable through `Int`: division by zero, a negative bit index, setting a bit to something that is not zero or one, the square root of a negative number, a base outside two to `MaxBase`, an even second argument to `Jacobi`, a negative round count to `ProbablyPrime`, and a `FillBytes` buffer too small to hold the number | All eight raise, `ErrDivideByZero` for the first, `ErrBase` for the base and `ErrInvalidArgument` for the rest. Every one is a fact about arguments the caller wrote, and an arbitrary precision number is the kind of thing a program computes with for a long time before it prints anything, so ending the process is the least useful thing to do with the news. |
| `big.Int.ModInverse`, `ModSqrt` and `Exp` returning a nil `*Int` when there is no inverse, no square root, or a negative exponent whose base has no inverse, which a caller finds out about by dereferencing it | All three raise. A nil `*Int` is not a number and there is no equivalent here to hand back, and the raise says which of the three it was rather than leaving the caller to work it out from what they passed. |
| `math/big` panics in three more places reachable through `Rat`: a zero denominator to `NewRat`, `SetFrac` and `SetFrac64`, the inverse of zero, and a division by zero | All three raise `ErrDivideByZero`, for the same reason the eight above do. |
| `big.Rat.SetFloat64` returning a nil `*Rat` for a NaN or an infinity, and `SetString` returning a false for text that is not a number, both of which leave the receiver holding something undefined | Both raise, `ErrInvalidArgument` for the float and `ErrSyntax` for the text, and both leave the receiver exactly as it was. A caller that catches the raise is holding the number it started with rather than a value it never wrote. |
| `big.Rat.Float64` and `Float32` reporting a number below the smallest subnormal as an exact zero, because the rounding step that loses bits only covers the subnormal range and the check afterwards is for an infinity alone, so `1/(1<<2000)` comes back as `0, true` | Both report `0, false`. A zero does not represent that number, and the flag exists to say whether the float is the rational. The top of the range was already right in Go and is unchanged here. |
| `math/big` panics with an `ErrNaN` in six places reachable through `Float`: adding two infinities of opposite signs, subtracting two of the same sign, multiplying a zero by an infinity, dividing a zero by a zero or an infinity by an infinity, the square root of a negative number, and `SetFloat64` or `NewFloat` of a NaN | All six raise with the `ErrNaN` code. Go's own documentation calls that panic a value carrying an error, which is a raise written the long way round, and every one of the six is a pair of operands a program computed rather than typed. |
| `big.Float.Int` and `Rat` returning a nil alongside their accuracy when the number is an infinity, which a caller finds by dereferencing it | Both raise `ErrInvalidArgument` and report no accuracy. An infinity is not an integer and not a rational number, so there is nothing to hand back, and the accuracy Go returns in that case says nothing a caller can use. |
| `big.Float`'s precision and rounding mode live on the destination, so `new(Float).SetPrec(p).SetMode(m).Add(x, y)` is how either is chosen and the same expression also says where the answer goes | There is no destination, so `x.add(y)` works at the wider of the two operands' precisions and rounds by the left operand's mode, which is what Go's `new(Float).Add(x, y)` does, and `x.add(y, p)` names the precision. Choosing a mode is `x.copy()` then `set_mode`. `copy` keeps the source's precision and mode where `set` rounds to the receiver's, exactly as in Go. |
| `math/rand/v2` panics in four places: a bound that is not positive to any of the `N` functions, a zero to `Uint64N`, a negative count to `Shuffle`, and a `Perm` of a negative length | All four raise `ErrInvalidArgument`. Every one is a bound the caller computed, and a package whose whole job is to hand back a number is not the one that gets to end the process over an argument. |
| `rand.NewZipf` returning a nil `*Zipf` when `s <= 1` or `v < 1`, which is a nil the caller finds by dereferencing it | `new_zipf` raises `ErrInvalidArgument`. Those parameters describe no distribution, so there is nothing to hand back either way, and a raise says which of the two was wrong. |
| `ChaCha8.UnmarshalBinary` indexing its `readbuf:` section by a length byte it never checks, and slicing the state by a position it never checks, so three shapes of untrusted encoding panic with a slice bounds failure and a fourth restores a generator that silently skips forward in the stream | All four raise `ErrInvalidEncoding`. A marshalled generator is exactly the kind of thing that arrives from somewhere else, so the decoder checks the length byte, checks the position against the block it indexes, and leaves the receiver untouched when it refuses. `tests/math/rand/test_chacha8.mojo` pins all four. |
| `utf8.ValidString` is the check you run before trusting a `string`, since a Go `string` is arbitrary bytes | A `String` is validated when it is built, so this answers `True` unless somebody went through the `unsafe_` constructor. The function stays precisely so that assertion has somewhere to be audited. |

Five of those are the same observation. Go documents a hazard and Mojo's type system removes it.

One row belongs here that is not a deviation from Go at all, because the alternative it rejects is the one a reader will assume was taken. `core.sort` is a port of Go's pdqsort and SymMerge rather than a wrapper around `std.builtin.sort`, and the reason is that the standard library's sort hands the comparator elements from outside the span it was given when the comparator is inconsistent. McIlroy's antiquicksort adversary gets 645 such comparisons out of a 1,000 element range, and an index outside the data is a dead process rather than a wrong answer. Go's sort does not do this at any size, stable or not, and a caller who gets the ordering wrong should get a wrong order. Issue #16 has the reproducer and `tests/sort/test_adversary.mojo` runs the adversary at that size and at ten times it.

`core.math` is the second row of that kind, for a similar reason found the same way. It was recorded as a wrap over `std.math` and about half of it is a port, because `std.math` is a throughput first library and Go's tests are an accuracy contract. Measured against libm over Go's own inputs, `std.math.erf` is off by a hundred and seventy million parts in the last place, `pow` by ten million and `log` by two million, where the tolerances Go's tests hold its `math` to are forty five parts and two. `std.math.sinh` is a not a number at negative infinity, `std.math.tanh` is one at a not a number, `std.math.j1` hands back a negative zero at negative infinity where Go's answer is a positive zero, and `std.math.gamma` at -170.5 is out by four parts in fourteen digits, which fails even the loosest tolerance Go uses. So nine functions are ported for accuracy, two more whole for the special values, four keep the system library behind Go's special case switch, and nine are ported because there was nothing to call at all. The rest are the system library's, which is FDLIBM either way, so copying it a third time would only add a place for a bug to live. One more trap is worth naming because a reader will assume the opposite: `Float64.MAX` and `Float32.MAX` in Mojo are positive infinity rather than the largest finite value, so `MAX_FLOAT64` and `MAX_FLOAT32` are written out as Go writes them and `tests/math/test_ieee.mojo` pins the difference.

`hypot` joined that list late and from a different direction. It was the system routine, on the grounds that `sqrt(p*p + q*q)` has one right answer and nothing to disagree about, and the system routine is not required to give it. On macOS `hypot(-16.688001947990161, -24.14182405800559)` comes back as 29.348203997243527 where the correctly rounded answer is 29.348203997243523, and Go's two lines give the correctly rounded one. A part in the last place would not matter if `hypot` were only ever the length of something, but `core.math.cmplx.sqrt` divides by it and then subtracts two nearly equal numbers, and at `asinh(-5.010603618271075 + 9.636293707198417i)` that one bit arrives fifty bits wide, which is thirty times Go's tolerance for the function. So `hypot` is Go's, and `core.math.cmplx` gives the same answer on every platform rather than the platform's answer.

`core.math.cmplx` is the third row of that kind. It was recorded as a wrap over `std.complex` and is a port of all twenty seven functions, because the type and the functions turned out to be different questions: `std.complex.ComplexFloat64` is a fine number type and carries the four operators, a conjugate and a norm, and none of the twenty seven. Two of the three it does carry are not the ones Go uses either. `norm()` squares both parts and adds them, so it overflows at `(1e308, 1e308)` where the answer is 1.4e308 and underflows to zero at `(1e-320, 1e-320)` where the answer is 1.4e-320, and `abs` is a hypotenuse and is right at both. Division is the naive formula and overflows the same way, which does not come up only because Go's `math/cmplx` never divides one complex number by another. So the type is Mojo's, a value from this package is a value the rest of the language already works with, and everything done to it is Go's.

## Additions Go does not have

Nothing here is present because it seemed nice. Each one is either forced by an absence in Mojo or a response to a failure that keeps happening in Go's ecosystem.

| Addition | Why |
| --- | --- |
| `core.unicode.norm`, the four normalisation forms | In Go's extended text repository rather than its standard library. A library that cannot tell you two spellings of the same string are equal is unfinished. |
| `core.sync.chan` as a package | Go spells channels in the language. Mojo has no channel, select or go keyword. |
| `core.runtime.sched` as a package | Go's scheduler is its runtime. Ours is a library. |
| `core.runtime.box` as a package | Go's interface value is a type pointer and a data pointer allocated by its runtime. Mojo has no interface value at all, so the box is a library type and the vtable is written by hand. |
| `errors.capture` and `ErrorValue` | Go's errors are values with the lifetime of whoever holds them. Ours need an explicit capture to outlive the raise, to be stored, or to cross a thread. |
| `errors.partial` | Recovers the count from Go's count and error pair, which a raise would otherwise drop. |
| `errors.wrap` | Go spells wrapping as a `%w` verb inside `fmt.Errorf`, which needs a runtime format string. This is the operation on its own. |
| `errors.causes` | Go exposes the multiple cause case only as an `Unwrap() []error` method on a type it does not export, so a joined error's causes cannot be reached from outside. |
| `big.Int.must_set_string` | Go has no `MustSetString` because `x, _ := new(big.Int).SetString(s, 0)` works at package level. A constant here is built inside a function and `set_string` raises, so without this every file holding a written down modulus or curve order would have to be a raising one. |
| `big.Int.gcd_ext` | Go's `GCD` is one method that also computes the Bézout coefficients, if the caller passes destinations for them, and skips that work if the caller passes nil instead. There are no destinations to leave out here, so the plain divisor and the extended answer are two methods and each one says what it costs. |
| `fmt.vprintf` and a runtime argument list | Go's `Printf` takes a runtime format string without noticing. Ours needs a second, slower entry point for that. |
| `fmt.Fields`, a trait a type implements to be printed field by field | Go prints a struct under `%v` by reflecting on it. There is no reflection here, so a type that wants that says how, in one method that gets the verb and hands it to each field the way Go does. A type that implements neither this nor `Writable` is named while the program is built and prints Go's `%!v(value)` marker when it runs. |
| Archive extraction helpers that reject traversal by default | Go ships the dangerous primitive without a safe convenience, which is why the same path traversal bug has been found in hundreds of programs. |
| Pixel count limits on every image decoder | A decompression bomb is a 200 byte PNG. Go has a config call and no limit. |
| Scanning a row directly into a struct | Third party Go libraries exist to provide this over reflection. The generator already exists here. |
| A reference SQL driver, shipped rather than test only | We ship no real driver, so without this the package is untestable, and a driver author needs an example to write against. |
| A marker trait for values that may cross a thread boundary, enforced by the linter | Mojo has no send or sync marker. Go has neither and ships a race detector. We ship both. |
| Full memory ordering parameters on atomics | Go offers only sequential consistency. The library itself needs acquire and release. Sequential consistency stays the default. |
| A context on every blocking network operation | Go takes one only when dialling. |
| Separate sender and receiver handles for a channel | Dropping the last sender closes the channel, which removes the most common channel bug in Go. |
| Header, part count and body size limits on by default | Go added most of these after they turned out to be denial of service vectors. Starting with them is free. |

## Omissions

Things a Go programmer will look for and not find. This is separate from the 41 packages left out entirely, which are listed with a reason each in [packages.md](packages.md).

| Missing | Instead |
| --- | --- |
| `syscall.Getdents` on Linux and `syscall.Getdirentries` on macOS, each reading raw directory entries out of a descriptor | `opendir`, `readdir` and `closedir`, which are the same three functions with the same behaviour on all three of our platforms. Go avoids libc entirely and so has to have one of these per platform and a buffer walker for each layout; this library is already linking libc, and the C library is also what deals with a directory whose entries take more than one buffer to arrive. The handle comes back as a plain integer, because Mojo's pointers cannot be null and cannot carry an origin that means somebody else owns the memory. |
| `strings.Title` and `bytes.Title` | Deprecated in Go itself: the word boundary rule does not handle Unicode punctuation, so it turns `they're` into `They'Re`. | A single `len` for a string | `count_bytes`, `count_runes` and `count_graphemes`. Mojo makes `len(s)` a compile error and it is right to. |
| `maps.Keys`, `Values` and `All` returning an iterator | `keys()`, `values()` and `all()` returning a list, each with an `_into(out)` sibling. Go's iterators are closures, and a `Dict` already has iterators of its own, so a function handing one back would be a second name for something that exists. |

| Go's iterator function types generally | Traits for iterable and fallible iterable. |
| `ChaCha8` declaring `io.Reader`, so one can be handed to anything that reads | `ChaCha8.read` has that signature exactly, so wrapping one as a reader is a wrapper and nothing more. Declaring the conformance would put `core.io` underneath `core.math.rand` in the tier list, and Go's `math/rand/v2` does not import `io` either. |
| `fmt`'s `%T` verb | Nothing. It prints the type of the argument and there is no way to ask for one, so a type outside the table `core.fmt` knows is called `value` inside a marker rather than named. Every type it does know is named exactly as Go names it, so `%!d(string=hi)` is Go's own text. |
| `fmt`'s `%p` verb | Nothing. It prints an address, and an address printed in a test is a number that changes between runs, which is why Go's own tests write it as `0xPTR` and rewrite it before comparing. |
| `big.Int.Format` and `big.Int.Scan` | `text` for a number in a base, `write_to` for printing one, and `set_string` for reading one back. | Go's `divRecursive` and `karatsubaSqr` | Long division and the squaring loop, at every size. | Backreferences and lookaround in regexp | Linear time matching, as in Go. Not a deviation from Go, listed because it is the first thing people ask. |
| Encrypted zip entries | Not supported, matching Go. The old scheme is broken and the new one is not interoperably standardised. |
| Zstandard, Brotli and LZ4 | Not in Go's standard library. Candidates for a separate repository. |
| WebP, AVIF, TIFF and BMP | Same reason. |
| Arithmetic coded JPEG | Not supported, matching Go. |
| TLS 1.0 and 1.1 | Cannot be enabled. Go removed them and there is no reason to reintroduce them in a library written now. |
| Custom elliptic curve arithmetic | Deprecated in Go, and the route to invalid curve attacks. |
| Leap seconds | Matching Go and POSIX. A positive leap second repeats a second. |
| Anything Windows specific | Windows is not a Mojo target, so Go packages whose reason to exist is Windows portability lose it. |
| Placeholder rewriting between SQL dialects | Matching Go. A question mark stays a question mark. |
| Compile time compiled regular expressions | Deferred past 1.0 behind a benchmark gate. The API is shaped so it can be added later without changing anything else. |
| `io.Pipe`, `io.PipeReader` and `io.PipeWriter` | Deferred to M4. Every method blocks until the other side arrives, which needs `core.sync`. `io.ErrClosedPipe` is already numbered so the sentinel does not move when the pipe lands. |

| `bufio.Scanner.Err` | Nothing to call, and nothing to remember. The failure came out of `has_next` at the moment it happened. |
| `io.CopyN` taking the destination's `read_from` fast path | It does not. Go gets there by wrapping the source in a `LimitReader`, which here would mean holding a borrowed reader in a field. Write `copy(dst, limit_reader(src^, n))` when you own the source. |

## The abort residue

The rule is that nothing in this library aborts for a condition the caller could have checked. Go aborts on an out of range index, on a write to a nil map, and on compiling a bad pattern with `MustCompile`. Here indexing raises, nil maps do not exist, and the rest raises.

Eleven functions keep the abort. All eleven are `must_` prefixed, where aborting is precisely what the caller asked for by choosing that name over the fallible sibling:

`regexp.must_compile`, `regexp.must_compile_posix`, `template.must`, `html.template.must`, `netip.must_parse_addr`, `netip.must_parse_addr_port`, `netip.must_parse_prefix`, `time.must_load_location`, `big.Int.must_set_string`, `url.must_parse` and `sql.must_register`.

Plus `core.panic(message)` itself, which writes a message and a stack trace and then aborts.

This matters more here than it does in Go, because a Mojo program cannot catch an abort. Each one of these is a program somebody cannot make robust. So every one has a fallible sibling with the same behaviour and a raise, the documentation page for each names it, and the linter warns on a `must_` call whose argument is not a literal. A `must_` on a literal is a constant the programmer has asserted. A `must_` on a variable is a crash waiting for the right input.

## How this page stays true

A deviations list maintained by good intentions is a deviations list that is wrong within a month, so there are three mechanisms.

The waivers file is the machine readable form of the omissions section, one line per symbol with a reason, and it is diffed in review. A growing waivers file is the signal that the contract is being negotiated away rather than met.

Every package's documentation page has a mandatory section on how it differs from Go's package of the same name, and the documentation tool fails a page that omits it. The entries there and here come from the same source, so they cannot disagree.

And the language probes pin the facts behind the first table. When a Mojo release changes one, a probe fails and names the row. Two of those rows could plausibly disappear within the life of this project, which is why the deviations are written as consequences of numbered properties rather than as decisions somebody made.
