# Deviations

Every deliberate departure from Go, in one place, so that you can read the whole cost of the translation without assembling it from the package documentation.

This is the honest answer to the claim that nothing is missing. Every symbol in the implemented column of [packages.md](packages.md) is present. Not every one behaves identically, and the ones that do not are here. A deviation that is not on this page is a bug, so please report it.

Five categories, and the split matters. Forced is what Mojo would not let us do. Better is where Mojo let us do more than Go. Added is what Go lacks. Omitted is what we chose not to carry. Residue is the small set of aborts that survive.

## Forced by the language

Each row names the property of Mojo behind it. The numbers refer to sections of [design.md](design.md).

Two of these cost far more than the rest. The compile time warning means every static check in this library is a warning that our linter promotes to an error inside this repository and that you see as a warning. The fixed stack means a task is not a goroutine even if the green thread work in M9.4 succeeds.

## Where this library is stricter or better

These are deviations too, because code written against Go's semantics may not port, and they are improvements.

| Go | This library |
| --- | --- |
| `Read` may return bytes and an error together, and every caller is told to handle the count before the error | A read that moved bytes returns them and does not raise, so `EOF` always arrives with a count of zero |
| A string builder copied after use panics through a runtime check | Not copyable, so the mistake does not compile |
| `os.DirFS("")` builds a file system whose every call fails with `os: DirFS with empty root` | `dir_fs("")` raises there and then, so a value that exists is one that can be used. The failure is the same either way and this one names the line that made the mistake |
| `subFS.fixErr` shortening the path in a failure by editing the `Path` field of the `*PathError` in place | The record is built again with the short path on it and the code, the operation and the errno kept, since nothing here is edited in place. It works for a refusal with no errno on it as well, which Go's assertion to `*PathError` covers but its edit does not have to |
| A mutex copied by value is caught by a separate analysis tool | Not copyable, so it does not compile |
| A walk hands its callback a nil `fs.DirEntry` in the one case where nothing was learned about the name, a root that could not be stat'ed, so a callback that forgets to check the error ends the process | The entry is always there. In that case it carries the base name of the root and no type, so the same mistake reads a name that is true |
| `filepath.EvalSymlinks` reports a component that is not a directory as a bare errno with no path on it, and too many links as a plain message with no code at all, so neither can be told apart from anything else | Both are a `PathError` carrying the operation, the path and the number, so `errors.matches`, `errors.field` and `PathError.of` answer for them as they do for every other failure in the package |
| `io.MultiReader` returns a zero length read when a source in the middle is empty | The loop moves to the next source instead, so a caller never sees a zero without an error |
| `os.Getenv` and `os.Environ` read a copy of the environment that Go takes at start up, so `os.Setenv` and a `setenv` from linked C disagree from the moment either of them runs | Every read goes through to libc, so the two halves of a process agree. It costs a call and a copy per lookup, and nothing is locked, so a read racing a write is a data race here exactly as it is in C |
| `io.TeeReader` reads and writes, and a caller that ignored the error loses the bytes it already took | A write failure comes out of the read, because the bytes are already gone from the source by then |

| `time.Time.UnmarshalText`, `UnmarshalJSON` and `UnmarshalBinary` assign the receiver before they look at the failure, so a value one of them refused is a value it cleared to the zero time | Nothing is written unless the whole input is accepted, so a value handed to a failing call is the value it was. | `csv.Reader.FieldPos` panicking on an index that is not a field of the last record | Raises, saying the index and how many fields there were. Five of those are the same observation. Go documents a hazard and Mojo's type system removes it.

One row belongs here that is not a deviation from Go at all, because the alternative it rejects is the one a reader will assume was taken. `core.sort` is a port of Go's pdqsort and SymMerge rather than a wrapper around `std.builtin.sort`, and the reason is that the standard library's sort hands the comparator elements from outside the span it was given when the comparator is inconsistent. McIlroy's antiquicksort adversary gets 645 such comparisons out of a 1,000 element range, and an index outside the data is a dead process rather than a wrong answer. Go's sort does not do this at any size, stable or not, and a caller who gets the ordering wrong should get a wrong order. Issue #16 has the reproducer and `tests/sort/test_adversary.mojo` runs the adversary at that size and at ten times it.

`core.math` is the second row of that kind, for a similar reason found the same way. It was recorded as a wrap over `std.math` and about half of it is a port, because `std.math` is a throughput first library and Go's tests are an accuracy contract. Measured against libm over Go's own inputs, `std.math.erf` is off by a hundred and seventy million parts in the last place, `pow` by ten million and `log` by two million, where the tolerances Go's tests hold its `math` to are forty five parts and two. `std.math.sinh` is a not a number at negative infinity, `std.math.tanh` is one at a not a number, `std.math.j1` hands back a negative zero at negative infinity where Go's answer is a positive zero, and `std.math.gamma` at -170.5 is out by four parts in fourteen digits, which fails even the loosest tolerance Go uses. So nine functions are ported for accuracy, two more whole for the special values, four keep the system library behind Go's special case switch, and nine are ported because there was nothing to call at all. The rest are the system library's, which is FDLIBM either way, so copying it a third time would only add a place for a bug to live. One more trap is worth naming because a reader will assume the opposite: `Float64.MAX` and `Float32.MAX` in Mojo are positive infinity rather than the largest finite value, so `MAX_FLOAT64` and `MAX_FLOAT32` are written out as Go writes them and `tests/math/test_ieee.mojo` pins the difference.

`hypot` joined that list late and from a different direction. It was the system routine, on the grounds that `sqrt(p*p + q*q)` has one right answer and nothing to disagree about, and the system routine is not required to give it. On macOS `hypot(-16.688001947990161, -24.14182405800559)` comes back as 29.348203997243527 where the correctly rounded answer is 29.348203997243523, and Go's two lines give the correctly rounded one. A part in the last place would not matter if `hypot` were only ever the length of something, but `core.math.cmplx.sqrt` divides by it and then subtracts two nearly equal numbers, and at `asinh(-5.010603618271075 + 9.636293707198417i)` that one bit arrives fifty bits wide, which is thirty times Go's tolerance for the function. So `hypot` is Go's, and `core.math.cmplx` gives the same answer on every platform rather than the platform's answer.

`core.math.cmplx` is the third row of that kind. It was recorded as a wrap over `std.complex` and is a port of all twenty seven functions, because the type and the functions turned out to be different questions: `std.complex.ComplexFloat64` is a fine number type and carries the four operators, a conjugate and a norm, and none of the twenty seven. Two of the three it does carry are not the ones Go uses either. `norm()` squares both parts and adds them, so it overflows at `(1e308, 1e308)` where the answer is 1.4e308 and underflows to zero at `(1e-320, 1e-320)` where the answer is 1.4e-320, and `abs` is a hypotenuse and is right at both. Division is the naive formula and overflows the same way, which does not come up only because Go's `math/cmplx` never divides one complex number by another. So the type is Mojo's, a value from this package is a value the rest of the language already works with, and everything done to it is Go's.

## Additions Go does not have

Nothing here is present because it seemed nice. Each one is either forced by an absence in Mojo or a response to a failure that keeps happening in Go's ecosystem.

| Addition | Why |
| --- | --- |
| `core.unicode.norm`, the four normalisation forms | In Go's extended text repository rather than its standard library. A library that cannot tell you two spellings of the same string are equal is unfinished. |
| `core.sync.chan` as a package | Go spells channels in the language. Mojo has no channel, select or go keyword. |
| `core.runtime.sched` as a package | Go's scheduler is its runtime. Ours is a library. |
| `core.runtime.box` as a package | Go's interface value is a type pointer and a data pointer allocated by its runtime. Mojo has no interface value at all, so the box is a library type and the vtable is written by hand. |
| `errors.capture` and `ErrorValue` | Go's errors are values with the lifetime of whoever holds them. Ours need an explicit capture to outlive the raise, to be stored, or to cross a thread. |
| `errors.partial` | Recovers the count from Go's count and error pair, which a raise would otherwise drop. |
| `csv.Reader.last_record` | Go's `Read` hands the record back alongside `ErrFieldCount`, and a raise carries one value, so the record waits on the reader for the caller who wants to see what failed the count. |
| `csv.Reader.records`, a `Cursor` over the records left | Go's loop is a `Read` and a comparison against `io.EOF`, and the whole of its correctness is in the comparison. Leave it out and the loop ends on the first malformed row and reports nothing. This is the first user of the `Cursor` trait and the example its own documentation is written around. |
| `xml.Decoder.max_depth`, a cap on how deeply elements may nest | Go caps nesting at ten thousand inside its reflection half only, so a document read a token at a time can nest as deeply as it likes and the token stack grows with it. The cap is on the token half here, starts at Go's own number, can be raised or turned off, and `raw_token` ignores it because a raw token does not match elements and so pushes nothing. |
| `xml.Decoder.tokens`, a `Cursor` over the tokens left in a decoder | The reason `csv.Reader.records` exists, one directory over. Go's loop is a `Token` and a comparison against `io.EOF`, and leaving the comparison out ends the loop on the first malformed document while reporting nothing. |
| `json.valid_or_raise` | Go's `Valid` answers yes or no and drops the reason, and the scanner behind it had already worked out both the message and the offset, so the only way to reach them in Go is to `Unmarshal` the document into something and read the `*SyntaxError` off the failure. This raises what the scanner already knew, over the same single pass `valid` makes. |
| `json.Decoder.max_depth`, a cap on how deeply brackets may nest | The same hole as `xml.Decoder.max_depth`, one directory over. Go applies its ten thousand level cap inside the scanner, which `Valid` and `Unmarshal` run through and which the token path does not, so a file of nothing but `[` read one token at a time grows a stack the size of the file. The cap is on the token path here, starts at Go's own number and can be raised, and the refusal is the scanner's message word for word so that a document refused for depth reads the same whichever way it was read. |
| `json.Decoder.tokens`, a `Cursor` over the tokens left in a decoder | The reason `csv.Reader.records` and `xml.Decoder.tokens` exist, a third time. Go's loop is a `Token` and a comparison against `io.EOF`, and a loop that leaves the comparison out ends on the first malformed document while reporting nothing. |
| `json.Document.reset`, which empties a document and keeps its memory | Go's tree is garbage and the next `Unmarshal` allocates a new one, so a program reading a million small messages allocates for the total. An arena can be refilled, so this is one call and the three lists keep their capacity. It is also the reason a handle carries a generation: reusing the memory is exactly what makes a handle from before it wrong. |
| `json.Value.write_to`, so a document written back out is a `String(value)` | Go's way back out is `Marshal` on the `any` the document was read into, which is the reflection half of the package doing a job that needs no reflection at all. A node already knows what it is, so writing it is a walk of the arena, and it is an explicit stack rather than recursion so that a document nested at the cap costs a list rather than ten thousand frames. |
| `json.MAX_NESTING_DEPTH`, written down rather than unexported | Go's `maxNestingDepth` is a limit on input a program may be handed from anywhere, and the only ways to learn the number in Go are to read the source or to feed in ten thousand brackets and see. It is a constant here for the same reason Go's is one, that nothing raises it and nothing lowers it, and it has a name so that a program generating deep documents can check itself against it. |
| `errors.wrap` | Go spells wrapping as a `%w` verb inside `fmt.Errorf`, which needs a runtime format string. This is the operation on its own. |
| `errors.causes` | Go exposes the multiple cause case only as an `Unwrap() []error` method on a type it does not export, so a joined error's causes cannot be reached from outside. |
| `big.Int.must_set_string` | Go has no `MustSetString` because `x, _ := new(big.Int).SetString(s, 0)` works at package level. A constant here is built inside a function and `set_string` raises, so without this every file holding a written down modulus or curve order would have to be a raising one. |
| `big.Int.gcd_ext` | Go's `GCD` is one method that also computes the Bézout coefficients, if the caller passes destinations for them, and skips that work if the caller passes nil instead. There are no destinations to leave out here, so the plain divisor and the extended answer are two methods and each one says what it costs. |
| `fs.skip_dir` and `fs.skip_all` | Go's `SkipDir` and `SkipAll` are errors a callback returns, and a callback here raises instead. The two codes are still there and still what a walk matches on, and these two build the raise so that no callback has to invent a message for a thing that is not a failure. |
| `fs.Subtree`, exported, where Go's `subFS` is unexported | Go can keep it private because `Sub` returns an `fs.FS` and the type never appears in a signature. Here it is the return type of `sub`, so it has a name, documentation and a place on this page. |
| `fs.FS.capabilities` and the six bits beside it | The replacement for a type assertion, described in the forced table above. It is an addition because a file system implementing this trait has to set them, which Go's does not. |
| `fmt.vprintf` and a runtime argument list | Go's `Printf` takes a runtime format string without noticing. Ours needs a second, slower entry point for that. |
| `fmt.Fields`, a trait a type implements to be printed field by field | Go prints a struct under `%v` by reflecting on it. There is no reflection here, so a type that wants that says how, in one method that gets the verb and hands it to each field the way Go does. A type that implements neither this nor `Writable` is named while the program is built and prints Go's `%!v(value)` marker when it runs. |
| Archive extraction helpers that reject traversal by default | Go ships the dangerous primitive without a safe convenience, which is why the same path traversal bug has been found in hundreds of programs. |
| Pixel count limits on every image decoder | A decompression bomb is a 200 byte PNG. Go has a config call and no limit. |
| Scanning a row directly into a struct | Third party Go libraries exist to provide this over reflection. The generator already exists here. |
| A reference SQL driver, shipped rather than test only | We ship no real driver, so without this the package is untestable, and a driver author needs an example to write against. |
| A marker trait for values that may cross a thread boundary, enforced by the linter | Mojo has no send or sync marker. Go has neither and ships a race detector. We ship both. |
| Full memory ordering parameters on atomics | Go offers only sequential consistency. The library itself needs acquire and release. Sequential consistency stays the default. |
| `asn1.Parser`, a public cursor that reads one DER value at a time | Go's entry points are `Unmarshal` and `Marshal`, which walk the type they are handed while the program runs. There is no such walk here, so the layer underneath Go's reflection has to be a public one: generated code drives it, and so does the hand written code in `core.crypto.x509` that already knows the shape it is reading. `TagAndLength` is public for the same reason and is unexported in Go. |
| `asn1.Builder`, the writer that answers that cursor, which puts down a value at a time and closes a constructed one when the caller says so | Go's encoder builds a tree of nodes, measures it and then walks it again to write it, because it cannot know a length until it has walked the value's type. This writes forward into one buffer and leaves a single byte where each open value's length goes, then widens that byte and shifts the contents along if the length outgrew it. Nothing recurses, so it matches `Parser` in having no depth to cap, and the two together are the layer generated code sits on. |
| `Builder.add_t61_string` and `add_bmp_string`, writers for the two string types Go can read and cannot write | Go picks a tag from a Go type, and both of these are a Go `string`, so its writer has no way to be told which of them was meant. Here the caller names the call, so the tag is not something to infer. Both matter to certificates issued before UTF8String was in common use, which is to say to anything that has to re-encode an old chain. |
| A context on every blocking network operation | Go takes one only when dialling. |
| Separate sender and receiver handles for a channel | Dropping the last sender closes the channel, which removes the most common channel bug in Go. |
| Header, part count and body size limits on by default | Go added most of these after they turned out to be denial of service vectors. Starting with them is free. |

| `maps.Insert(m, seq)` and `Collect(seq)` taking an `iter.Seq2[K, V]` | Both take a `Span[Tuple[K, V]]`. The natural translation is a `Cursor` of pairs, and it cannot be written: `where C.Element == Tuple[K, V]` is checked at the call site and leaves the type opaque in the body, so a dict cannot get the key and the value out separately. Drain a fallible source with `slices.collect` first. |
| Go's iterator function types generally | Traits for iterable and fallible iterable. |
| `ChaCha8` declaring `io.Reader`, so one can be handed to anything that reads | `ChaCha8.read` has that signature exactly, so wrapping one as a reader is a wrapper and nothing more. Declaring the conformance would put `core.io` underneath `core.math.rand` in the tier list, and Go's `math/rand/v2` does not import `io` either. |
| `fmt`'s `%T` verb | Nothing. It prints the type of the argument and there is no way to ask for one, so a type outside the table `core.fmt` knows is called `value` inside a marker rather than named. Every type it does know is named exactly as Go names it, so `%!d(string=hi)` is Go's own text. |
| `fmt`'s `%p` verb | Nothing. It prints an address, and an address printed in a test is a number that changes between runs, which is why Go's own tests write it as `0xPTR` and rewrite it before comparing. |
| `big.Int.Format` and `big.Int.Scan` | `text` for a number in a base, `write_to` for printing one, and `set_string` for reading one back. Go's two are its run time formatting interfaces, `fmt.Formatter` and `fmt.Scanner`, and `core.fmt` takes the format string as a `comptime` parameter and typechecks the verbs when the program is compiled, so there is no `State` to hand them and no verb to look at. |
| Go's `divRecursive` and `karatsubaSqr` | Long division and the squaring loop, at every size. Both of Go's are written as overlapping subsections of one vector being read and written by the same call, which is the shape this port cannot express, and neither changes an answer: `divRecursive` helps on divisors of several thousand digits and `karatsubaSqr` on squaring numbers about as large. |
| Backreferences and lookaround in regexp | Linear time matching, as in Go. Not a deviation from Go, listed because it is the first thing people ask. |
| Encrypted zip entries | Not supported, matching Go. The old scheme is broken and the new one is not interoperably standardised. |
| Zstandard, Brotli and LZ4 | Not in Go's standard library. Candidates for a separate repository. |
| WebP, AVIF, TIFF and BMP | Same reason. |
| Arithmetic coded JPEG | Not supported, matching Go. |
| TLS 1.0 and 1.1 | Cannot be enabled. Go removed them and there is no reason to reintroduce them in a library written now. |
| Custom elliptic curve arithmetic | Deprecated in Go, and the route to invalid curve attacks. |
| Leap seconds | Matching Go and POSIX. A positive leap second repeats a second. |
| Anything Windows specific | Windows is not a Mojo target, so Go packages whose reason to exist is Windows portability lose it. |
| Placeholder rewriting between SQL dialects | Matching Go. A question mark stays a question mark. |
| Compile time compiled regular expressions | Deferred past 1.0 behind a benchmark gate. The API is shaped so it can be added later without changing anything else. |
| `io.Pipe`, `io.PipeReader` and `io.PipeWriter` | Deferred to M4. Every method blocks until the other side arrives, which needs `core.sync`. `io.ErrClosedPipe` is already numbered so the sentinel does not move when the pipe lands. |
| `io.ReadAll` returning the bytes it did read alongside a failure | The failure alone. Copy into a buffer you own if the partial result matters; `errors.partial` still says how far it got. |
| `bufio.Scanner.Err` | Nothing to call, and nothing to remember. The failure came out of `has_next` at the moment it happened. |
| `io.CopyN` taking the destination's `read_from` fast path | It does not. Go gets there by wrapping the source in a `LimitReader`, which here would mean holding a borrowed reader in a field. Write `copy(dst, limit_reader(src^, n))` when you own the source. |
| `exec.CommandContext`, `Cmd.Cancel` and `Cmd.WaitDelay` | Nothing. All three are about stopping a command from another goroutine while this one sits inside `Wait`, and there is no other goroutine for them to be stopped from. A caller who wants to give up on a command calls `start`, does whatever waiting it wants to do, and calls `kill`. |
| `exec.Cmd.SysProcAttr`, a pointer to a struct declared per platform | `setsid` and `setpgid`, two booleans, which are the two fields of it anything in this library sets. A typed field would have to name a struct per platform, and `core.syscall` deliberately declares none. |
| `exec.LookPath` asking the kernel with `faccessat` and `X_OK` whether this process may run the file | The permission bits, which is Go's own fallback for a platform without that call. It is the weaker test: it says whether anybody may run the file rather than whether this process may. A file that passes here and then fails at the exec reports `EACCES` from `start`, which is the honest place for the answer, since permission can change between the question and the exec anyway. |
| `signal.Notify` with an empty signal list, which means every signal there is | Nothing. A caller who wants several signals calls `notify` several times. A loop over every number would take over `SIGSEGV` and `SIGBUS` as well, and a program that catches those and carries on is a program running on a corrupt stack. |
| `File.ReadFrom` and `File.WriteTo` reaching for `sendfile` or `copy_file_range` when both ends are files, so a copy between two files never leaves the kernel | A loop through a 32 KiB buffer. The bytes move and the count is right, so `core.io.copy` over two files is correct and is not yet fast. Neither call is bound in `core.syscall`, issue #188 is where they go, and the two method bodies are the only thing that changes when they land. |
| `File.SyscallConn`, a `syscall.RawConn` for reaching the descriptor without racing the runtime for it | `File.fd`. Go's runtime owns the descriptor and can move it in and out of the poller, which is what the dance exists for. Nothing owns a descriptor here except the `File` holding it, so the number is the whole answer. |
| `os.ProcAttr.Sys`, a pointer to a `syscall.SysProcAttr` declared per platform | `ProcAttr.setsid` and `ProcAttr.setpgid`, the same two booleans `exec.Cmd.SysProcAttr` gets above, for the same reason: a typed field would have to name a struct per platform and `core.syscall` deliberately declares none. |
| `time.Timer`, `time.Ticker`, `time.After`, `time.AfterFunc`, `time.Tick`, `time.NewTimer` and `time.NewTicker` | `time.sleep`, and nothing else yet. Every one of the seven delivers on a channel or runs a function on a goroutine, and both of those arrive with `core.sync.chan` in M9. A timer built before then would have to invent a way of delivering that nobody coming from Go would recognise, or block the calling thread, which is `sleep` under another name. |
| `signal.NotifyContext` | Deferred with `core.context`. It is `Notify` with a cancellation in place of the channel, and both halves of it need packages that are not here yet. |

## The abort residue

The rule is that nothing in this library aborts for a condition the caller could have checked. Go aborts on an out of range index, on a write to a nil map, and on compiling a bad pattern with `MustCompile`. Here indexing raises, nil maps do not exist, and the rest raises.

Eleven functions keep the abort. All eleven are `must_` prefixed, where aborting is precisely what the caller asked for by choosing that name over the fallible sibling:

`regexp.must_compile`, `regexp.must_compile_posix`, `template.must`, `html.template.must`, `netip.must_parse_addr`, `netip.must_parse_addr_port`, `netip.must_parse_prefix`, `time.must_load_location`, `big.Int.must_set_string`, `url.must_parse` and `sql.must_register`.

Plus `core.panic(message)` itself, which writes a message and a stack trace and then aborts.

This matters more here than it does in Go, because a Mojo program cannot catch an abort. Each one of these is a program somebody cannot make robust. So every one has a fallible sibling with the same behaviour and a raise, the documentation page for each names it, and the linter warns on a `must_` call whose argument is not a literal. A `must_` on a literal is a constant the programmer has asserted. A `must_` on a variable is a crash waiting for the right input.

## How this page stays true

A deviations list maintained by good intentions is a deviations list that is wrong within a month, so there are three mechanisms.

The waivers file is the machine readable form of the omissions section, one line per symbol with a reason, and it is diffed in review. A growing waivers file is the signal that the contract is being negotiated away rather than met.

Every package's documentation page has a mandatory section on how it differs from Go's package of the same name, and the documentation tool fails a page that omits it. The entries there and here come from the same source, so they cannot disagree.

And the language probes pin the facts behind the first table. When a Mojo release changes one, a probe fails and names the row. Two of those rows could plausibly disappear within the life of this project, which is why the deviations are written as consequences of numbered properties rather than as decisions somebody made.
